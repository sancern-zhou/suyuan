# 昨日污染回顾乡镇站区域响应与传输确定性计算方案

## 1. 设计结论

本方案完善许昌“昨日站点污染回顾”的区域对比和传输分析。

- `xuchang.station_deviation_alert_fetcher` 是唯一的污染抬升告警生产者。
- 昨日回顾只消费场景一的告警事件、episode 和证据包，不重新判定告警。
- 乡镇站不参与告警基线、告警阈值和 episode 起始条件，只参与告警后的区域响应分析。
- 前/中/后窗口、站点变化、先后关系和空间梯度由 Fetcher 确定性计算，Agent 只负责表达。
- 结果只能形成区域响应或传输线索，不能形成污染源、责任单位或贡献率结论。

## 2. 数据流与职责

场景一负责告警判定、事件发布、episode 合并、重复抑制、episode 关闭和证据包保存。昨日回顾负责读取 episode，加载周边站点数据，计算告警后的区域响应并生成日报证据包。

昨日回顾只接受 `xuchang.station_deviation.alert_created` 和 `xuchang.station_deviation.episode_closed`。没有对应场景一事件时记录 `alert_source_status=not_found`，不得根据日报数据补算告警。

昨日回顾不得再次执行 `_hourly_evidence()` 作为触发器，不得重新计算告警偏差，不得重新发布 `xuchang.station_daily_pollution.confirmed`，也不得把乡镇站加入告警基线。

## 3. Episode 合并与幂等

区域响应分析以 `episode_id` 为唯一过程主键，不以单个告警小时为主键。建议分析 ID 为 `xuchang-daily-review-{target_date}-{episode_id}`。

同一 episode 内多个告警小时只生成一份分析；显著恶化记录为过程内峰值更新，不创建新过程。跨自然日 episode 仍然只有一个 episode，不因日报日期变化而拆分。

证据包保存 `episode_id`、`parent_alert_event_ids`、`source_evidence_package_path`、`analysis_id`、`target_date` 和证据版本。相同 episode、相同证据版本重复投递返回 `duplicate`；证据版本变化时生成新版本并保留父版本关系。

## 4. 告警前/时/后窗口

告警时间统一归一化到小时。对于一个 episode，`episode_start` 是第一条告警时间，`episode_end` 是最后一条告警时间。

| 窗口 | 范围 | 目的 |
| --- | --- | --- |
| 告警前 | `episode_start-3h` 至 `episode_start-1h` | 背景、提前抬升和区域先行变化 |
| 告警时 | `episode_start` 至 `episode_end` | 周边站点是否同向抬升 |
| 告警后 | `episode_end+1h` 至 `episode_end+3h` | 滞后响应和扩散线索 |

每个窗口至少需要 2 个有效小时样本，否则标记 `insufficient_data`。查询范围按 episode 扩展到最早开始时间前 3 小时至最晚结束时间后 3 小时，以覆盖跨午夜过程。

## 5. 周边站点同向抬升

告警基线继续使用场景一的常规站点；告警后证据可以纳入常规站、乡镇站、省控站及已完成类型和区县映射的站点。

每个站点、每个窗口计算告警前均值、告警时均值、告警后均值，以及 `during_delta`、`after_delta`、`during_ratio` 和 `after_ratio`。抬升必须满足固定的污染物绝对阈值和相对阈值，阈值版本写入证据包。

每个站点输出有效小时数、均值、增量、增幅、`rise / flat / decline / insufficient_data`、首次抬升时间及相对目标站点的提前/同步/滞后小时数。

建议区域分类：

- `regional_co_rise`：有效周边站不少于 3 个，且至少 60% 在告警时抬升；
- `local_target_only`：目标站抬升，周边站多数未抬升；
- `delayed_regional_rise`：告警后抬升比例明显高于告警时；
- `regional_decline`：目标站告警时周边站整体下降；
- `insufficient_evidence`：有效站点或有效小时不足。

## 6. 时间先后与空间梯度

周边站首次达到抬升阈值的时间为 `first_rise_hour`，并计算 `lead_hours_to_target = first_rise_hour - episode_start`。小于 0 表示提前，等于 0 表示同步，大于 0 表示滞后；没有有效抬升时为 `no_detected_rise`。

空间梯度必须使用真实站点坐标。乡镇站无坐标时，可以做浓度变化和区县汇总，但不得计算距离、方位角和梯度，不得用区县中心点替代站点坐标，写入 `spatial_status=missing_coordinates`。

有坐标时计算距离、相对目标站方位、告警时增量、告警后增量和径向梯度：`(during_delta_neighbor - during_delta_target) / distance_km`。至少 3 个有坐标且不共线的有效站点时，可拟合二维变化平面并输出梯度方向、大小、样本数和拟合状态。空间梯度只描述空间结构，不能单独证明传输方向。

## 7. 传输一致性表达

允许的站点观测结论包括：区域同步抬升、周边提前抬升、告警后扩散和局地突出。每个结论必须附有效样本、窗口、阈值、缺测、站点类型和坐标状态。

禁止输出“确定由某方向传输造成”、具体源区、企业责任或污染贡献率。

## 8. 证据包字段

证据包至少包含 `alert_anchor`、`episode_id`、`parent_alert_event_ids`、`episode_start`、`episode_end`、`peak_time`、`window_policy`、`station_response_by_window`、`regional_co_rise`、`temporal_lead_lag`、`spatial_gradient` 和 `transport_consistency`。每项结果带数据源、窗口、阈值版本、有效样本数、缺测情况、站点类型、坐标可用性和计算状态。

## 9. 验收标准与实现顺序

- 昨日回顾不重新计算告警，乡镇站不影响场景一告警基线；
- 没有场景一事件时不生成新的告警事件；
- 同一 episode 多个告警小时只生成一份分析，重复投递不重复计算；
- 跨自然日 episode 不被拆分；
- 前/时/后三段窗口可追溯，样本不足时不输出方向性结论；
- 同向抬升比例、时间先后和空间梯度可复算；
- 无坐标时明确标记空间证据缺失；
- 报告结论不越过站点观测证据边界。

实现顺序：先接入场景一 episode 和证据版本读取，再改造昨日回顾为只读消费；随后接入乡镇站小时数据，完成窗口计算、同向抬升、先后关系和空间梯度；最后补齐乡镇站坐标、增加跨日/去重/缺测测试并更新报告 Agent 字段。
