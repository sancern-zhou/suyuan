# 企业微信推送部署指南

面向目标用户（局长/科长/区县/驻场/执法等业务角色）的个人微信点对点推送，
与微信群 RPA 广播互补。用户**用微信添加运营成员的企业微信为好友**即可，
无需安装企业微信、无需任何订阅授权。首期覆盖**月度特征分析**（每月 2 日）
与**企业核查线索周报**（每周一）两个此前仅有 APP 渠道的场景。

## 一、方案形态与关键限制

- 推送方式：企业微信「客户联系-企业群发」（`add_msg_template`，点对点
  chat_type=single），客户在**微信聊天列表**里收到，体验接近好友私信。
- **关键限制（平台设计）**：API 创建的是群发**任务**，创建后运营成员的
  企业微信客户端会收到提醒，**需手动点一次「发送」**客户才能收到。系统
  会在创建任务后自动调用「提醒成员群发」接口催办一次。
- 频控：每个客户每天最多收 1 条企业群发——月报+周报远低于上限。
- 运营节奏：每周一早（周报任务创建后）运营者点一次发送；每月 2 日
  （月报）再点一次。**无需用户做任何操作**。

## 二、前置条件

1. **认证的企业微信**：未认证企业无客户联系 API 权限。
2. **开通客户联系**：企微管理后台 → 客户联系 → 配置「可使用客户联系
   的成员」（把运营成员加进去），并在「API」页记录 **Secret**
   （对应 `WECOM_CONTACT_SECRET`）。
3. **回调与可信 IP**：
   - 管理后台 → 应用管理 → 客户联系 → 接收事件服务器：URL 填
     `https://<域名>/api/wecom/callback`，Token/EncodingAESKey 自定义
     （与后端 env 一致），首次保存会触发 URL 验证（后端已实现验签回显）。
   - 「企业可信 IP」配置服务器出口 IP（gettoken 要求）。
4. **公网回调可达**：nginx 把 `/api/wecom/callback` 反代到后端网关
   （参照现有 `/api/` 规则加一条精确 location）。
5. 记录企业 ID（CorpID，"我的企业"页）与运营成员的**成员 UserID**
   （通讯录里点开成员可见，用于 `WECOM_DEFAULT_MEMBER`）。

## 三、后端配置

`backend/.env` 追加（web 与 worker 成对使用同一份）：

```bash
# 企业微信客户联系推送渠道
WECOM_ENABLED=true
WECOM_CORPID=ww1234567890abcdef
WECOM_CONTACT_SECRET=<客户联系应用的 Secret>
WECOM_DEFAULT_MEMBER=<运营成员的企微 UserID，如 ZhangSan>
WECOM_TOKEN=<与回调配置一致的 Token>
WECOM_AES_KEY=<与回调配置一致的 43 位 EncodingAESKey>
WECOM_API_PREFIX=/api/wecom
WECOM_TIMEOUT_SECONDS=15
```

说明：`WECOM_TOKEN`/`WECOM_AES_KEY` 留空时回调路径在网关层整体关闭
（默认安全）；`WECOM_ENABLED=false` 或 corpid/secret/member 缺失时
推送渠道自动跳过。

## 四、用户绑定流程（微信扫码加好友即绑定）

身份沿用 APP 账号体系（`APP_ACCOUNTS_JSON`），external_userid 是账号的
附加绑定；受众仍由 `push_audiences.json` 的角色配置决定，零新增配置面。

1. 管理员为账号生成「联系我」二维码（网关管理员登录态调用）：

   ```bash
   curl -X POST https://<域名>/api/wecom/admin/bind-qrcode \
     -H "Authorization: Bearer <管理员token>" -H "syscode: <syscode>" \
     -H "Content-Type: application/json" \
     -d '{"account": "大气科1"}'
   # 返回 {"account":"大气科1","qr_code":"https://wework.qpic.cn/...","state":"bind:大气科1","members":["ZhangSan"]}
   ```

   把 `qr_code` 二维码图片发给目标用户（微信里发图即可）。
2. 用户**用微信扫码并添加企微成员为好友**（免验证，扫码即通过）→
   回调 `add_external_contact` 自动完成 账号↔external_userid 绑定并
   记录跟进成员（owner）。
3. 用户删好友 / 成员删跟进 → 回调自动标记 unbound，后续推送跳过。
4. 管理端查询/删除绑定：

   ```bash
   curl -H "Authorization: Bearer <管理员token>" https://<域名>/api/wecom/admin/bindings
   curl -X DELETE -H "Authorization: Bearer <管理员token>" https://<域名>/api/wecom/admin/bindings/大气科1
   curl -H "Authorization: Bearer <管理员token>" https://<域名>/api/wecom/admin/status
   ```

注意：同一微信号重复扫不同账号的码，绑定会自动"搬家"到新账号（防跨
账号泄漏）；多个运营成员各自的客户在投递时按成员分组创建任务。

## 五、推送链路

```
fetcher（cron 冻结证据包）
  └─ publish_event → workflow（monthly_review / enterprise_clue）
       ├─ APP：EventTaskDelivery → 广播收件箱 + GeTui（原链路不变）
       └─ 企业微信：push_wecom_report(kind, title, content, roles)
            ├─ 受众：roles → push_audiences.json 角色 → APP 账号（复用）
            ├─ 绑定：wecom_bindings.json 查 external_userid + owner
            │    跳过：未绑定 / 已删好友
            ├─ 内容：完整通报，UTF-8 字节安全截断到 2048 字节并加提示
            ├─ 任务：按 owner 分组 add_msg_template（chat_type=single）
            └─ 催办：remind_group_msg_send 提醒运营成员确认发送
                 → 运营成员在企微客户端点「发送」→ 用户微信收到
```

- 渠道整体 try/except 隔离，任一失败不影响微信群与 APP。
- 绑定文件：`<social目录>/wecom_bindings.json`（原子写，勿手工编辑运行
  中的文件）。

## 六、验证清单

1. [ ] 企微后台回调配置保存成功（URL 验证通过）
2. [ ] `curl /api/wecom/admin/status` 返回 `enabled: true`、
      `callback_configured: true`
3. [ ] 扫码加好友后 `/admin/bindings` 出现该账号（owner 为运营成员）
4. [ ] 手动执行企业线索周报任务（或等周一 07:20）→ 运营成员企微出现
      群发任务提醒 → 点「发送」→ 用户微信收到周报文本
