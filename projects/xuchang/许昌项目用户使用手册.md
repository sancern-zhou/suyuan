# 许昌市 AI 应用智能体用户使用手册

> 适用版本：许昌市 AI 应用智能体（`许昌市AI应用智能体`）｜数据核对基准日：**2026-09-29**
> 全文时间统一使用**北京时间（UTC+8）**，未特别说明城市时默认按**许昌市**处理。

---

## 1. 手册说明

本系统面向许昌市空气质量监测、污染过程分析、天气研判和业务报告编制，主要服务于：

- **监测监控岗**：掌握站点实时态势、及时发现污染抬升；
- **分析研判岗**：复盘昨日污染过程、研判成因、准备溯源材料；
- **领导与科室管理人员**：获取结论性研判和可直接使用的正式报告。

系统提供四条工作路径：用自然语言**查数据**、查**知识资料**、做**专家研判**、产出**正式报告**；另有后台**定时任务**自动产出日报和告警通报。

### 1.1 三条使用前必读的提示

1. **数据接入状态会直接影响可用时间范围。** 本项目配置了完整的数据采集任务清单，但项目级采集总开关 `fetchers_enabled` 当前为 `false`（自动采集调度暂停）。数据库中已有历史数据和持续更新的数据，因此日常查询与报告一般可用；但**能否查到"最新一小时/最新一天"取决于部署环境的实际采集状态**。
2. **缺测不等于无污染。** 当页面或报告提示"数据不可用""样本不足""证据不足"时，结论应按"待核实"处理，**不能读作"没有污染"**。
3. **线索不等于结论。** 上风向候选、后向轨迹、遥感高值、排放清单企业都只是**核查线索**，不构成污染来源认定、贡献率或企业责任。

> 如发现某天日报未按时产出、告警长时间不推送、数据明显不更新，请联系系统管理员核查采集与任务启用状态（见第 4.5 节）。

### 2.5 统计口径红线（会影响所有模式的结果，请务必了解）

1. **官方口径唯一。** 许昌空气质量数据以中大平台为**官方口径和唯一权威来源**。系统不会为"验证"再引入其他数据源交叉比对，也不会因外部数值不同而改写官方值。
2. **不得自行汇总月及以上指标。** 月度、季度、半年、年度的均值、极值、有效天数、达标率、重污染天数、排名、同比等，一律调用平台统计报表接口获取，**禁止用小时或日数据自行汇总**。
3. **新国标与规划期分段。** 2026 年起执行新国标（HJ 663-2026），中大平台按评价规划期分表管理：**2026-01-01 前查 145 规划期，之后查 155 规划期**，用错返回空结果。做同比时若跨过分界点，系统自动分段查询并回填对比值。
4. **缺测哨兵值。** 站点表缺测记为 `-99`，城市表记为 `-999`，系统统一识别并排除，**不会当作 0 参与统计**。
5. **PM₂.₅ 数值口径。** 报表与回答中的 PM₂.₅ 浓度统一使用平台"银行家算法"四舍五入（保留一位小数）的结果。
6. **AQI ≠ 浓度。** AQI、业务高值和法定日均限值是三个不同口径，不能相互替换或换算。
7. **数据源声明。** 每次查询结果都会说明实际使用的数据源、表名/接口、国标口径、时间范围和筛选条件；**缺少该说明视为查询未完成**。

### 2.6 数据质量提示

| 现象 | 含义 | 处理建议 |
| --- | --- | --- |
| 乡镇站 **0 时**无数据 | 数据源系统性缺测，非真实污染变化 | 系统自动跳过该小时，不影响过程判定结论 |
| 小时数据带**质控标记** | 该值为质量标记值，设备/运维状态存疑 | 先核查设备运行、采样管路、校准维护及质控记录，**不作为污染异常依据** |
| 有效样本不足 | 连续有效小时数不够，判定条件不成立 | 结论降级为"证据不足/待核实"，不写"没有异常" |
| PM₁₀ 缺失比例偏高 | 部分时段 PM₁₀ 上报缺失 | 涉及 PM₁₀ 的统计和判定请核对有效样本数 |
| 无质控记录 | 系统内许昌站点暂无质控历史数据 | **"无质控记录"不等于"无质控问题"**，仍需现场核实 |

### 2.7 时间口径总表

- **实时/近实时告警**：每 **5 分钟**检查一次已完成槽位；PM₂.₅ 使用最近完整小时，其余主要污染物使用 5 分钟数据。
- **昨日污染回顾**：**每日 02:05** 分析前一自然日；小时证据查询范围为"昨日向前 6 小时至昨日向后 3 小时"，最终报告只统计昨日及其关联过程。
- **站点高值后诊断**：以告警过程开始至关闭为主窗口，默认回看开始前 12 小时。
- **未来 7 天天气报告**：执行日 D 至 D+6；另附 D+7 至 D+14 共 8 天趋势展望。
- **历史查询**：按第 2.0 节实际覆盖范围返回。**系统不会用缺失数据补 0，也不会跨缺测区间插值制造连续过程。**

## 3. Agent 模式与适用场景

从首页进入"**智能体平台**"，在"**监测分析**"场景下选择智能体。**当前许昌项目提供 4 个智能体**（默认进入"问数生图"）：

| 智能体 | 一句话定位 | 什么时候用 |
| --- | --- | --- |
| **问数生图** | 自然语言查数据 + 自动出图 | 要数字、要对比、要趋势图 |
| **知识问答** | 查制度、流程、口径、模板 | 问"这个指标怎么算""这个流程怎么走" |
| **专家分析** | 多领域协同研判成因 | 问"为什么涨""是本地还是外来" |
| **报告生成** | 产出正式可交付报告包 | 要交材料、要 Word/HTML 存档 |

> 模式之间**不共享上下文**，切换模式是新建对话。制图能力已并入"问数生图"，不需要单独找图表入口。

### 3.1 问数生图（query）

**适合**：查某天/某时段污染物浓度、站点对比、城市排名、气象数据、趋势统计和图表。

**能做**：

- 用自然语言查询许昌（及您指定区域）的空气质量、站点、气象和预报数据；
- 完成均值、峰值、变化率、分组对比、同比环比、排名等统计；
- 基于**真实查询结果**生成折线图、柱状图、风玫瑰等图表，并保留数据来源和口径说明；
- 数据量大时提供可下载文件，并先给出一到三句话的可朗读核心结论。

**边界**：

- 查询覆盖不足时会**明确说明缺口**，不猜测、不补齐数值；证据不足时会直接说明，不用流畅文字掩盖；
- 统计 PM₂.₅、日达标、区域对比、气象和预报，并按正确口径给出结论；
- **许昌项目不启用 GIS 交互式地图问数**，不提供地图上的点选查询；
- 只要求查询或统计时**不必强行生成图表**；您已提供完整数据时不再重复取数；
- 不会用历史气象工具试查未来数据。

**示例**：
- "查询 2026 年 9 月 1—7 日许昌市 PM₂.₅ 日均值并绘制趋势图。"
- "对比上周和这周 6 个国控站的 PM₁₀ 日均浓度排名。"
- "查一下 9 月 20 日 14—20 时各站点风向风速。"

### 3.2 知识问答（knowledge）

**适合**：查询制度、业务流程、指标解释、报告模板、判定规则和项目资料。

**能做**：

- 从许昌知识库中检索资料，给出**可追溯**的业务解释和操作说明；
- 需要时读取指定文档段落、沿实体关系和因果链做深入解释；
- 资料未收录时明确说明，并建议补充材料。

**边界**：

- **不做数据库问数、污染研判、图表制作和报告生成**；遇到这类需求会提示您切换到对应智能体；
- 不编造页码、条款号、文件内容或下载链接；
- 您上传的材料会标注为"用户上传"，**与知识库结论严格区分**；冲突时以知识库为准并列出差异。

**示例**：
- "昨日污染回顾的小时过程是怎么判定的？"
- "站点快速污染抬升告警的通报要写哪几部分？"
- "O₃-8h 的评价限值是多少？"

### 3.3 专家分析（expert）

**适合**：污染过程成因研判、气象扩散条件分析、遥感线索解读、区域输送分析、本地候选企业核查。

**能做**：

- 综合空气质量、气象、周边站点、后向轨迹、卫星遥感、排放清单和许可证资料；
- 按"明确边界 → 拆解问题 → 取数 → 校验清洗 → 分析 → 提炼结论 → 成稿 → 质检 → 交付"组织工作，关键数字经实际计算并交叉验证；
- 输出**监测事实 / 分析线索 / 不确定性 / 数据缺口**四类内容分开陈述。

**边界**：

- **单一风向、单条轨迹、卫星图或企业清单都不能单独证明污染来源**；
- 不输出未经验证的贡献率、企业责任、执法结论或停产指令；
- 大范围、多步骤的报告编排应交给报告生成；专家分析只处理当前明确的专业问题；
- 排放清单是**年度静态值**，不代表告警时段的实际排放强度。

**示例**：
- "分析昨晚 PM₂.₅ 抬升是局地异常还是区域输送，并列出需要核查的证据。"
- "解读这次 O₃ 过程的气象条件和卫星 AOD 线索。"
- "帮我筛出上风向可能需要核查的候选企业，说明筛选依据。"

### 3.4 报告生成（report）

**适合**：正式生成 HTML、Word、独立 HTML 报告包，包括日报、天气形势报告和专项溯源报告。

**能做**：

- 按固定模板组织数据、图表、事实表、分析文字和口径说明；
- 自动编排子任务：数据事实交给问数、机制成因交给专家，报告本体统一成稿；
- 输出可预览、可下载、可分享的标准报告包。

**边界**：

- 报告模式**优先使用已冻结的证据包**，不在成稿阶段改写事实、重复抓数或用文字填补缺测；
- 数据不足时报告仍可生成，但**必须显示"证据不足/覆盖不足"**；
- 正文中不出现内部接口名、工具名、字段名、表结构、URL 或本地路径；
- 数据来源、统计时段与口径说明统一放在报告最后，不在各章节重复。

**示例**：
- "生成许昌市未来 7 天天气形势分析报告，导出 HTML 和 Word。"
- "把昨天 6 个国控站的小时过程整理成一份汇报材料。"

## 4. 定时任务及报告产出

系统共注册 **4 个许昌定时任务**。它们都是**事件触发**（不是按固定时间轮询）：由后台数据处理完成后发布事件，任务收到事件才开始执行。

| # | 任务名称 | 实际执行节奏 | 执行方式 | 产出形态 | 推送 |
| --- | --- | --- | --- | --- | --- |
| 1 | **许昌市昨日污染回顾分析** | **每日 02:05** | 智能体 + Skill | HTML/Word 报告包 | 是 |
| 2 | **站点快速污染抬升告警** | **每 5 分钟**（仅在命中时执行） | 固定流程（非智能体循环） | 告警通报 + 附图 | 是 |
| 3 | 许昌未来 7 天天气形势分析报告 | 每日 08:45 准备证据后 | 智能体 + Skill | HTML/Word 报告包 | 是 |
| 4 | 许昌市城市超标污染快速溯源 | 逐小时污染过程证据冻结后 | 智能体 + Skill | 证据包 + 报告包 | 否 |

> 全部任务均以**许昌市**为过滤条件，只处理本市数据。

### 4.1 许昌市昨日污染回顾分析

| 项目 | 说明 |
| --- | --- |
| **执行时间** | 每日 **02:05**（北京时间），分析**前一自然日** |
| **触发方式** | 昨日回顾证据计算完成后自动发布事件；**即使没有入选过程，也会出例行报告** |
| **分析范围** | 6 个国控站小时数据 + 76 个乡镇站小时数据 + 郑州/开封/平顶山/漯河/周口/商丘/驻马店 7 市对比 + 许昌气象实况与边界层高度 |
| **入选规则** | 同站点同污染物**连续 2 或 3 小时严格上升**，且**末值 ≥ 初值 × 1.5**，且**绝对增量**达到门槛；重叠窗口合并为一次过程 |
| **入选门槛** | PM₂.₅ ≥ 10、PM₁₀ ≥ 15、NO₂ ≥ 8、SO₂ ≥ 6 μg/m³；CO ≥ 0.3 mg/m³。**O₃ 和 NOX 不适用此规则** |
| **区域响应** | 风来向 ±67.5°、20 km 内最近 10 个乡镇站作为上风向候选；按"区域同步抬升/周边滞后/仅本站抬升"分类 |
| **报告结构** | 一、持续升高基本情况（每过程一行：站点/污染物/时段/浓度变化/升幅/绝对增量）→ 二、持续升高原因分析（按站点+污染物分节，含区域响应事实表）→ 四、结论 |
| **产出** | HTML 交互报告（含**每种入选污染物一张逐小时高德地图**，标注小时风向来向与风速）、Word、独立 HTML |
| **不产出** | Word 版**不含**逐小时站点浓度趋势图；无入选过程时写"昨日没有出现小时告警污染" |
| **注意** | 分钟级告警**只作同站同污染物的时间匹配线索，不能单独增加日报过程**；小时数据不可用时写"无法判定"，**不写"没有异常"**；跨日过程按结束小时归入日报 |

### 4.2 站点快速污染抬升告警

| 项目 | 说明 |
| --- | --- |
| **执行节奏** | **每 5 分钟**筛查一次，仅在命中判定时生成通报 |
| **前置门槛** | 参照站点数 ≥ 3，且当槽可用站点比例 ≥ 80%，否则本轮不判定 |
| **命中规则一：单站相对区域偏高** | 目标站浓度相对**周边站点均值**（剔除本站）相对偏差超阈值，**且**绝对差值同时超过污染物门槛 |
| **相对偏差阈值** | 按当日空气质量等级动态取值：优 30%、良 40%、轻度及以上污染 50% |
| **绝对差值门槛** | PM₂.₅ 10、PM₁₀ 10、NO₂ 10、SO₂ 5、O₃ 30、NOX 15 μg/m³；CO 0.2 mg/m³ |
| **命中规则二：单站持续快速上升** | 连续 **6 个 5 分钟**上升（覆盖 30 分钟）且总升幅同时超过相对和绝对门槛。**PM₂.₅ 与 O₃ 不适用此规则** |
| **气象调节** | 低风速静稳、静风或逆温条件下，判定阈值**放宽至 75%**（更容易命中）；高湿只作辅助说明，不直接触发 |
| **数据粒度** | PM₂.₅ 走**小时**数据（结论中标注"（小时数据）"）；PM₁₀、SO₂、NO₂、CO、O₃、NOX 走**5 分钟**数据 |
| **过程归并** | 同站同污染物持续异常合并为一个 **episode**；分钟数据 **30 分钟**、小时数据 **1.5 小时**无新告警即关闭，且距上次通报至少 60 分钟 |
| **重复通报抑制** | 30 分钟内**一律不重复通报**；30—60 分钟内只有偏差显著恶化（**相对偏差再上升 25 个百分点**）才再报；超过 60 分钟恢复正常通报 |
| **通报内容** | 固定两节：**一、告警概况**（告警时间、站点、中文告警类型、污染物、数据粒度、实测值、周边偏差说明）、**二、气象与质控**（观测时间、温湿度、风来向风速、是否可能受质控运维影响）。**每节 200 字以内** |
| **附图** | 站点浓度趋势图；观测指标 ≥ 2 种时附多因子综合表 |
| **产出** | 面向值班/运维人员的简明通报，**同一站点多污染物合并为一份**，按部署配置定向推送给值班用户 |
| **注意** | 用于**快速发现和现场核查**，不用于实时管控指令、贡献率计算或企业责任认定；**存在质控标记时必须先核查运维影响再下结论**；该任务不输出企业上风向分析结论 |

### 4.3 许昌未来 7 天天气形势分析报告

## 5. 推荐使用流程

1. **先明确问题和时间** — 说明城市、站点、污染物、起止时间，以及需要**查询**、**分析**还是**正式报告**。
2. **选对智能体** — 要数字和图选**问数生图**；问规则口径选**知识问答**；问原因选**专家分析**；要交材料选**报告生成**。
3. **看数据覆盖和质量** — 关注报告中的缺测、有效样本数、预报批次、质控标记和"证据不足"提示。
4. **区分三类结论** — **监测事实**、**分析线索**、**待核查事项**分别理解，不把线索当责任结论。
5. **看正式产物** — 报告模式完成后从页面报告入口或右侧资源面板预览 HTML、下载 Word/独立 HTML；定时任务产出从**任务工作区**或**执行结果列表**获取。
6. **需要补跑就用"立即执行"** — 不要重复新建对话重新描述背景。

## 7. 结果解读底线

1. **缺测不等于无污染。** 数据缺失、有效样本不足或质控标记存在时，结论一律降级为"证据不足/待核实"。
2. **线索不等于结论。** "上风向""轨迹覆盖""遥感高值""排放清单候选"均表示线索，**不等于污染来源、贡献率或企业责任**。
3. **口径不能混用。** AQI、业务高值和法定日均限值是不同口径，不能相互替换。
4. **气象风险不是浓度预测。** 报告中的气象风险是对扩散、累积或光化学生成条件的判断，不是污染物实测浓度预测。
5. **时段要看清。** 报告中的时间范围、时区、数据源和国标口径是结论成立的前提，引用结论时请一并引用。
6. **配置变更需留痕。** 调整数据源、阈值、通知对象或采集状态，应由系统管理员按部署流程变更并保留版本记录。
