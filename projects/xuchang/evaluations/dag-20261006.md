# 问数、专家 DAG 受控评测（2026-10-06）

本轮六次最终试运行均通过数值、已访问证据文件和结构化因果边界校验，未重复取数。
在这组小数据任务上，额外编排和子模型调用增加了耗时与 Token，没有取得效率收益。
因此同源同口径优先批量查询；DAG 用于确需专业分工、上下文隔离或依赖交付的任务。

## 方法与范围

- 使用本实例配置的 scnet / GLM-5.3-Flash，temperature=0；每个场景每种路径一次。
- 代码提交：55153de9acca50549d402f2b3dc7f386d06be8ed；单次执行硬超时150秒。
- 使用固定合成数据，模型提示不包含金标准数值；direct 允许一次批量查询多个城市。
- DAG 走生产 run_agent_workflow、依赖调度、资源句柄交接与结果压缩。
- 父/子推理采用有界评测循环，业务 schema 是最小替身；未覆盖完整生产 ReAct、
  固定问数阶段、记忆、SSE、子会话持久化、真实业务库或服务配额。
- journal/cache/log 和活动登记隔离；最终试运行不访问部署 Redis。
- Token 为供应商实际返回值，包含其输出计数；本次缓存Token均为0，不估算货币费用。
- 质量评分校验数值、来源文件可追溯和因果边界字段；解释文字与逐条结论的证据支持仍需人工复核。
