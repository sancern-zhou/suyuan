## 1. 口径决议（与需求方逐条确认）

| 决议项 | 结论 |
|---|---|
| 因子范围 | PM2.5 / PM10 / SO2 / NO2 / CO 共 5 个因子；**O3 暂不纳入** |
| 规则集 | 单点突升 DS / 连续抬升 CL / 站点离群 OL，共 5×6×3 = **90 条** |
| 冲突仲裁 | 表内冲突一律**以规则总表为准**；判定逻辑表只采纳 #23 升级例外、#24 优先级排序 |
| 选档 | 按**站点 × 污染物** 1 小时 IAQI 定 6 档（HJ 633—2026；PM2.5/PM10 用日平均断点，2026 过渡限值） |
| 输出 | **不再输出告警级别**（无一级/二级/三级），告警只带规则类型 + 污染等级 |
| 限值突破 | **R1 删除**，不再保留 |
| PM2.5 窗口 | 小时值；DS 基线取前一小时，CL 基线取抬升起点前一小时 |
| 区域范围 | 许昌全市 6 个国控站；OL 有效站**最少 4 个** |
| 邻站同向 | 总表只写"邻站未同向"，落地定义：同因子同窗口 ≥2 个邻站也命中各自 DS 阈值即视为区域同向 |
| CL 区域合并 | 同污染物同窗口 ≥4 个站点命中连续抬升 → 只推累计抬升最大的站点一条，正文附全站清单；其余站点以 `regional_merge` 抑制留痕（需求方补充决议，2026-11-03） |

## 2. 三类规则判定口径（规则总表）

触发式统一为 **Δ ≥ MAX(基线 × 比例阈值, 绝对增量阈值)**，比例与绝对值同时满足（取严）；绝对值是"增量"而非当前浓度下限。

| 规则 | 判定窗口 | 基线 | 持续要求 | 冷却期（PM2.5 / 其他） |
|---|---|---|---|---|
| 单点突升 DS | PM2.5 小时值；其余 5 分钟 | 前 15 分钟 3 个 5min 均值（PM2.5 前一小时） | 单窗口即成立；邻站同向不判 | 60 / 30 分钟 |
| 连续抬升 CL | PM2.5 连续 3 小时；其余连续 3 个 5min | 抬升起点前 15 分钟均值（PM2.5 起点前一小时），固定不滑动 | 3 段单调不减，每段 ≥ 总增量 15% | 120 / 60 分钟 |
| 站点离群 OL | PM2.5 小时值；其余 5 分钟 | 其余有效站同刻简单平均值（全部有效站，不去极值） | PM2.5 单窗口；其余连续 2 窗口 | 60 / 30 分钟 |

CL 窗口语义（代码与测试统一）：窗口 = 3 个基线槽 + 3 个抬升值；段增量 = [起点−基线, v2−起点, 末值−v2]，起点固定为基线后第一个值。因此单尖峰（首段吃掉全部增量、后两段为 0）与中途回落形态均不满足。

## 4. 关键实现决策

1. **选档数据源**：站点×污染物等级由该站该因子**上一完整小时**值算 IAQI 定档（PM2.5 当前小时即用当前值定档）；`aqi` 列不再参与告警选档。
2. **OL 对比口径**：总表"同区域有效站点同刻平均值"，按字面实现为其余有效站**简单平均**（不去极值、不用中位数）；有效站总数 <4 时整站跳过。
3. **#24 范围**：优先级抑制限定"同站同因子同窗口"；跨因子合并沿用既有工作流（每站一份通报），主告警按规则优先级 + 因子序选取，其余因子完整保留在结果里并附 `concurrent_rules`。
4. **#23 升级例外**：`commit_push` 记录 `last_air_level` 与 `first_event_id`；新候选等级代码更高时穿透 armed 与冷却，告警带 `is_upgrade`/`upgrade_from_level`/`upgrade_to_level`/`upgrade_of_event_id`，episode 侧并入首条过程。
5. **运营层保留但换基准**：恢复防抖（3 周期 ≤阈值×90%）、日限额（站点 8 / 全局 40，按站计数不分级）、免打扰 22:00–06:00 仅静默 OL——这些不在总表内，如需关闭可直接 JSON 覆盖（`site_daily_quota`/`global_daily_cap` 置大数、`quiet_suppress_rules` 置空）。
6. **区域过程豁免移除**：R2/R3 三级 ≥4 站豁免 OL 的旧逻辑删除；#24 的 CL>OL 优先级已覆盖同事件去重。
7. **CL 区域合并**（需求方补充）：`merge_regional_rises` 在引擎每个评估周期末尾执行——同粒度同污染物 ≥`cl_region_merge_sites`（默认 4）个站点命中 CL 时，取 `total_rise_abs` 最大的站点作主告警（`region_merged_count` 记合并数，`detail.region_stations` 附其余站点清单），其余站点候选移入 `outcome.region_merged`，由 service 以 `regional_merge` 原因拼入 `suppressed_alerts`（不推送、不占冷却、有流水）。DS 已有邻站同向闸门、OL 天然不触发，故只对 CL 做跨站合并。置 `cl_region_merge_sites: 0` 可关闭。通报正文由 `_rise_sentence` 追加"同窗口另有 N 个站点连续抬升（站点+数值），已合并为本条区域告警"。
8. **状态兼容**：`air_alert_state.json` 旧实例（v1）加载时自动补 `first_event_id`、`last_air_level` 等字段，无需清档；`last_level` 字段遗留但不再读写。

## 5. 配置覆盖

默认值即规则总表（`RULE_MATRIX`/`COOLDOWN_MINUTES`）。部署可用 JSON 覆盖（路径：环境变量 `XUCHANG_AIR_ALERT_CONFIG` 或 `DATA_REGISTRY/xuchang_station_deviation_alerts/air_alert_config.json`，深合并，文件缺失不报错）：

```json
{
  "rule_matrix": {
    "PM10": { "sudden_rise": { "良": [0.25, 12] } }
  },
  "cooldown_minutes": { "sudden_rise": { "default": 45 } },
  "min_region_stations": 5,
  "neighbor_same_direction_count": 3,
  "quiet_suppress_rules": []
}
```
