# 许昌空气质量分级告警算法实施说明

**日期**：2026-11-02
**依据**：《空气质量数据告警推送系统——算法需求文档》V1.0（2026-10-30）
**分支**：`xuchang`
**状态**：已实现并通过单元测试，未部署（部署前建议先在测试环境观察 1-2 天推送量）

---

## 1. 目标效果回顾

对 6 个国控站点的实时数据执行分级告警判定，识别**限值突破（R1）、突升（R2）、连续抬升（R3）、空间离群（R4）**四类异常，输出一级/二级/三级分级告警，并通过冷却期去重、恢复防抖、数量限额、免打扰、合并推送把正常天气日均推送压到 ≤3 条（污染过程 ≤15 条），一级告警不限量必达。

## 3. 规则实现要点（文档 → 代码映射）

### 3.1 数据适配

- **站点**：文档 S1~S6 → 中大表 6 个国控站（canonical 编码 `1003A/1005A/1008A/1009A/1011A/1012A`）。引擎按站点白名单过滤（分钟表按 `area` 查询可能返回非国控行）。
- **有效性约定**（§2.1）：中大 `_mark` 列有标记 ≙ P/C（异常剔除/校准），缺测或负值 ≙ M（缺测）；无效值不参与基线与判定，且当前槽缺测的实例连续计数清零（§11）。
- **污染等级**（§3.2）：沿用上一完整小时城市最高 AQI 折算（优/良/轻度/中度/重度/严重），5 分钟周期内不变。
- **数值比较**（§3.5）：统一保留 1 位小数比较；累计涨幅用 `value >= base × (1 + ratio)` 形式。

### 3.2 公共组件（§3）

| 组件 | 实现 |
|------|------|
| 基线 `baseline()` | 当前槽之前最近 12 个有效 5 分钟值的中位数；有效值 <8 返回 None（跳过 R2/R3，R1/R4 照常）。PM2.5 小时版：前 3 小时中位数，<2 跳过 |
| 去极值均值 `trim_mean_others()` | 其余站点去掉最大、最小后取均值；其余站有效值 <5（去极值后 <3）返回 None，跳过该站 R4 |
| 等级修正 `delta_ratio()` | 优/良 +10pp、轻/中度不变、重/严重 −10pp（下限 0.10） |

### 3.3 四条规则

- **R1 限值突破**（§4）：分档阈值表（良/轻度/中度/重度及以上）按当前限值版本查表；`值≥T` 三级、`≥1.2T` 二级、`≥1.5T 或 ≥1h 国标限值` 一级。限值版本表带生效区间：过渡版 2026-03-01 起；正式版 2031-01-01 起（文档仅明确 PM10 良 100、PM2.5 良 50，其余档次按 ×5/6 折算，与这两档精确一致）。
- **R2 突升**（§5）：三档基础比例 30%/50%/100% 经等级修正后查阈值，绝对底线 F(p)（PM10 100 / SO2 50 / NO2 60 / O3 120 / CO 2）；三级需连续 2 个周期确认（`streak_cnt`），二/一级即时；同时满足多档时取**最严档**。
- **R3 连续抬升**（§6）：逐期涨幅 ≥2% 计连续（`start_value` 在 0→1 时记录）；连续 4/6/8 周期且累计 ≥15%/30%/50% 对应三/二/一级，**先判一级（周期数+累计双门槛取先满足的最高档）**；上一槽缺测视为间断清零。
- **R4 空间离群**（§7）：本站 vs 其余站去极值均值；差值底线 D(p)（PM10 50 / SO2 30 / NO2 30 / O3 40 / CO 1）；倍率 1.5/2.0/3.0（重/严重污染各减 0.5）；三级持续 3 周期、二级 2 周期、一级即时。
- **区域过程豁免**（§7.2）："至少满足三级条件"解释为：R2 满足三级原始阈值（不论是否完成双周期确认）或 R3 达到三级触发条件；≥4 个站点命中时，本轮**全部** R4 候选标记 `region_event` 只入库不推送。
- **PM2.5 小时版**（§8）：R1 直接查 PM2.5 行；R2 三级 `V≥B×1.25 且 V−B≥15`、二级 `V≥B×1.5 且 V−B≥15`（均即时，无一级档）；R3 三级连续 2 小时且累计 ≥15%、二级 3 小时且 ≥30%；R4 三级 `V≥R×1.5 且差≥35` 持续 1 小时、二级 `V≥R×2.0 且差≥35` 即时。状态键带 `grain=hour`，与 5 分钟规则互不复用。

> **与文档伪代码的一处刻意偏差**：文档 §5.3/§7.3 伪代码用 `hit = max(hit, lv)` 合并分档命中。按级别语义（一级最严重、数字最小），同时命中多档时 `max` 会返回最宽松档（如值超一级阈值却报三级）。实现改为**迭代覆盖、取最严档**，与 §5.1 分档表的意图一致。

### 3.4 PM2.5 触发时机

生产 fetcher 调度为 `1-59/5 * * * *` + 30 秒延迟（每个槽闭合后 90 秒运行）。整点槽（`target_slot.minute == 0`，实际在 HH+1:01:30 运行）会追加触发上一完整小时的 PM2.5 小时版判定，等价于文档 §10 的 `if ts.hour in pm25_hours: job_pm25_hourly(ts)`。旧的 `granularity="hour"` 入口同样执行 PM2.5 小时版（生产调度中该入口此前无调用方）。

## 4. 推送管控（§9）

### 4.1 主链顺序（§10 依赖顺序）

```
规则判定（各规则独立产候选）
→ 区域过程豁免（region_event）
→ 恢复防抖检查（§9.2，每周期）
→ 免打扰过滤（§9.5）
→ 闸门（§9.1 armed + 冷却）
→ 数量限额（§9.4 站点日限额 + 全局日上限）
→ 同站合并（§9.3.1）
→ 推送落位（写 alert_state + 日计数）+ push_log 流水
```

被抑制的候选不落推送状态、不消耗冷却，只写 push_log（`suppressed_reason`）。

### 4.2 级别语义与"升级穿透"

级别数字**越小越严重**（一级=1 最严重）。文档 §9.1（armed 先拦截一切）与验收用例 T08（冷却期内升级立即推送）冲突，本实现按 T08 优先，闸门判定顺序：

1. **升级穿透**：新级别数字 < 已推送级别（如三级→二级）→ 无条件放行；
2. **armed 防抖**：未武装时同级及以下拦截（`hysteresis`）；
3. **冷却期**：武装但仍在冷却窗口内（三级 120 / 二级 90 / 一级 60 分钟，按 `last_level` 取时长）拦截（`cooldown`）。

与文档伪代码的另一处偏差：恢复防抖重新武装时**保留 `last_level`**（文档置 0），否则恢复后的冷却期失去时长参照，同级告警可在冷却期内重复推送；保留后冷却期兜底生效，升级穿透不受影响。

### 4.3 限额与免打扰（§9.4/§9.5）

- 站点日限额：三级 5 条 / 二级 8 条；全局日上限 40 条（只拦二/三级）；一级不限、计数但不被拦。
- 免打扰 22:00–06:00（可配置）：三级静默入库，一/二级不受限。
- 计数按自然日（Asia/Shanghai）自动重置，与 alert_state 同文件持久化。

### 4.4 合并推送（§9.3）

- 同站同窗口多条规则：保留**最高严重级别**一条为主告警，其余规则附注在 `concurrent_rules`（通报正文体现"同站同窗口还命中…"）。
- 跨站点/参数摘要：本轮全部推送生成 `window_summary` 文本随任务结果返回。**差异说明**：实际投递仍按既有"每站一份通报"的工作流执行（每站一次 Agent 分析 + 投递），未合并为单条跨站消息——如需严格单条摘要需调整任务编排，本次未动。

### 4.5 状态与流水存储

- `alert_state`：`DATA_REGISTRY/xuchang_station_deviation_alerts/air_alert_state.json`，键 `grain::station::pollutant::rule_type`，含 level/last_push_ts/last_level/armed/recover_cnt/streak_cnt/last_value/start_value/last_trigger_threshold；原子写 + 重启恢复（§11）。worker 单实例执行，与 episode 状态存储同模式。
- `push_log`：`DATA_REGISTRY/xuchang_station_deviation_alerts/push_log/YYYYMMDD.jsonl` 按日追加，每条候选（推送或抑制）都留痕：时间、站点、参数、规则、级别、动作、抑制原因。
- 文档中的 `cfg_rule/cfg_limit/cfg_push/cfg_notify` 数据库表**未建**：阈值配置以 JSON 覆盖文件承载（见 §5），状态/流水以 JSON/JSONL 承载。如后续需要 DB 镜像/多进程共享，可按 `episode_storage_db.py` 模式扩展。

## 5. 配置方式

默认值全部在 `AirAlertRuleConfig`（代码内即文档值）。部署可建 JSON 覆盖文件（键名与 dataclass 字段一致，dict 深合并、list→tuple），路径优先级：

1. 环境变量 `XUCHANG_AIR_ALERT_CONFIG` 指向的文件；
2. `DATA_REGISTRY/xuchang_station_deviation_alerts/air_alert_config.json`。

常用键：`baseline_window/baseline_min_valid`、`r1_secondary_multiple/r1_primary_multiple`、`limit_versions`（含 2031 版）、`r2_ratios/r2_confirm_periods/r2_floors`、`r3_periods/r3_cum_gains/r3_step_min`、`r4_multiples/r4_hold_periods/r4_diff_floors/r4_region_exempt_sites`、`pm25_*`（小时版）、`cooldown_minutes`、`recover_ratio/recover_periods`、`site_daily_quota/global_daily_cap`、`quiet_hours_start/quiet_hours_end/quiet_suppress_levels`。文件缺失不是错误（用默认值）。

## 6. 结果契约变化（下游注意）

`service.run()` 返回值：

- `alerts`：**仅含通过推送管控的告警**。新增字段：`rule_type`（limit_breach/sudden_rise/continuous_rise/spatial_outlier）、`rule_label`、`alert_level`（1/2/3，1 最严重）、`alert_level_name`、`detail`（规则明细与 `recovery_threshold`）。R4 保留 `peer_mean/absolute_delta/deviation_ratio` 兼容字段；R3 保留 `rise_window_values/total_rise_*`；R2 新增 `baseline/rise_percent`。同站合并时主告警带 `concurrent_rules`。
- 新增键：`suppressed_alerts`（含 reason：region_event/hysteresis/cooldown/quota/global_cap/quiet_hours）、`window_summary`、`region_event`、`region_event_stations`。
- `checks` 改为逐参数站点可用性观测（不再有 80% 数据率门槛——文档 R1/R2/R3/R4 各自有可判定条件，不设全局数据率门槛）。
- 不利气象结论（`meteorology_decision`）仍输出，但**不再缩放规则阈值**（分级阈值的灵敏度修正由污染等级承担，§3.4）。

## 9. 部署与回退

- 改动全部在 `xuchang` 分支；部署即随分支正常发布 web/worker 成对重启，无数据库迁移、无新环境变量（可选 `XUCHANG_AIR_ALERT_CONFIG`）。
- 首周期运行：`air_alert_state.json` 不存在时全部实例为初始态（armed、无 streak），首轮只会触发 R1/R2 二一级/R4 一级类即时规则，确认类规则（R2 三级、R3、R4 二三级）需 2-3 个周期积累状态。
- 回退：revert 本次提交即恢复旧单级别规则链路（旧函数与 episode 冷却原样保留）。
- 观察建议：上线后先看 `push_log/*.jsonl` 的 suppress 分布（quota/quiet/cooldown 命中量）与日均推送条数，再按 §5 调整 JSON 配置（改文件即生效需重启 worker）。
