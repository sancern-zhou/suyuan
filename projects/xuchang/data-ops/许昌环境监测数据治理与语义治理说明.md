# 许昌环境监测数据治理与语义治理说明

许昌空气质量智能体项目采用一条与江苏运维项目形态不同但治理思想一致的数据工程链路：从省级业务平台与官方报表采集/回补数据到 DataCrawler MySQL 采集库，通过**语义注册中心（registry.yaml）+ Cube schema** 定义口径与维度指标，再由 Agent 工具完成语义点数查询和受控明细取证。该项目没有独立的 dbt/ODS-mart 加工层——**语义治理的重心不是"加工宽表"，而是"把口径、适用范围、数据窗口和质量限制登记成 Agent 的解释边界"**。

其数据和语义治理核心同样是基于应用场景设计采集范围：

- **官方定版口径类数据不自行聚合**。月报统计（ProvinceMonth/CountyMonth）、年度考核目标（XuchangCity/CountyYearTarget）、168 城市全国排名（Rank168CityMonthly）等考核与统计指标，一律以人工回补的官方报表原值为准，**禁止用实时采集数据自行聚合出"官方口径"**——因为平台实时值未审核（与国家网定版有 1~5μg/m³ 差）、剔除沙尘等口径差异无法在采集端还原。这是"考核指标复用已有平台/官方接口"原则在本项目的落法。
- **高频查询、排名多变、需要取证的场景充分采集加工**。省实时发布平台的城市/区县/站点小时日值、排名重算、站点偏离告警、中大平台分钟级数据等，自动采集入库并定义好维度与指标模型，支撑"现在几点、许昌排第几、哪个站偏离了"这类高频问答。
- **每类数据都登记"解释边界"**。语义注册中心为每个数据集记录 grain（粒度）、applicability（适用范围）、source_window（数据窗口）、limitations（质量限制），Agent 回答时必须遵守（如乡镇站必须过滤 caliber 口径、-99 是无效值、2026-10 起源接口不发布 PM10 等）。

## （1）数据采集层

采集层由 suyan fetcher 直接抓取/回补写入 DataCrawler MySQL（MySQL 8，长历史监测库），**无独立 sync 脚本和 ODS 层**。按频率分四档：

**1、分钟级高频采集（5 分钟波次）**

- 河南省实时发布平台（SSFB）城市组：`XuchangHenanSsfbCityPublishFetcher`，每小时 14/20/55 分三波，写 `SsfbCityHour` / `SsfbCityDay`（18 城市组含济源，六参数+AQI）与 `SsfbDimCity` 维表；
- 县级站：`XuchangHenanSsfbSitePublishFetcher`，每小时 16/22/57 分三波，写 `SsfbSiteHour` / `SsfbSiteDay`（许昌县级站，剔除国控站）与 `SsfbDimSite` 维表；
- 中大平台站点分钟数据：`1-59/5 * * * *`，回看 25 分钟窗口（平台 5 分钟批次约滞后 1 分钟可查）；
- 站点偏离告警监测：`XuchangStationDeviationAlertFetcher`，`1-59/5 * * * *`，产出偏离事件（主库 `xuchang_station_alert_episodes`）并联动上风向道路调度建议。

波次分钟与采集窗口判定由同一元组生成（`wave_schedule()`），保证调度与窗口策略同源不漂移。

**2、小时级采集**

- 区县组：`XuchangHenanCountyPublishFetcher`，每小时 18/24/59 分三波，写 `SsfbCountyHour` / `SsfbCountyDay` 与 `SsfbDimCounty` 维表；
- 中大平台站点小时数据：每小时 10 分，回填 26 小时防跨日空白；
- 城市超标监测：每小时 20 分；日均达标预测滚动更新：每小时 25 分；NMC 逐小时气象预报：每小时 40 分；大屏快照：每小时 11/41 分。

**3、每日任务**

- 排名重算：每日 06:10，按省平台同口径重算城市月/年累计浓度排名，写 `SsfbCityRanking`（升序并列、不做综合指数，带官方对照列）；小时排名为查询期实时重算，不落表；
- 月/年累计加工：每日 07:40，`XuchangHenanMonthYearAccumulateFetcher` 维护月累计与年累计视图；
- 站点日污染/超标回顾：每日 02:05，读取前一整天原始小时数据做日值加工；
- 气象形势证据：每日 08:45（中国天气网 1-15 天预报每日 06:20）；
- 月度年度达标预测：每月 1 日 06:35。

**4、官方报表人工回补（无自动采集，`projects/xuchang/data-ops/backfill_*`）**

- `ProvinceMonthReport`：河南省环境空气质量月报官方附表（当月+1-N 月累计），城市月度及以上统计的**唯一官方口径**；
- `CountyMonthReport`：许昌县市区官方月报统计（剔除沙尘，2020-01 起）；
- `XuchangCityYearTarget` / `XuchangCountyYearTarget` / `HenanCityYearTarget`：许昌市/县市区/河南 18 地市年度目标与完成情况（国家网/省考核定版），**年度目标值全库唯一来源**；
- `Rank168CityMonthly`：生态环境部 168 重点城市全国排名（人工回补）。

**5、气象与外部数据：走 API 不复刻**

实况气象（Open-Meteo/WeatherAPI/NMC）、卫星、组分、碳度、火点、降尘等直接通过 Agent 查询工具实时调用外部接口，仅在主库做缓存（`observed_weather_data`、`weather_data_cache`、`era5_reanalysis_data` 等），不在采集库复制一份历史。

## （2）语义治理层

许昌项目以**语义注册中心**代替 dbt 建模层，由三件套构成（`projects/xuchang/data-ops/semantic/` + `cube/`）：

**1、表契约（table contracts）**：`data_table_contracts.yaml` 由采集库真实 `information_schema` 生成，渲染成紧凑 markdown 注入 `execute_crawler_sql_query` 工具描述，Agent 明细查询前先读契约，避免字段误用；fail-soft 降级为"先 describe_table"。

**2、语义注册中心（`semantic/registry.yaml`，version 2）**：Cube schema 负责执行，注册中心负责解释——每个数据集登记四项：

- `grain`：一行是什么（如"一行 = 城市 × 小时"）；
- `applicability`：适用范围（如"河南 18 城市组含济源"）；
- `source_window`：数据窗口（如"2025-12 与 2026-01~09 共十期，新月报发布后回补"）；
- `limitations`：质量限制与 Agent 解释边界（如"乡镇站必须过滤 caliber=app/src 否则重复计数""-99 为无效值不参与聚合""2026-10 起源接口不发布 PM10，缺失不得当作零""年度考核以定版表为准，与平台实时列有 1~5μg/m³ 差""省内排名与 168 排名不可混算"）。

配套 `validate_registry.py` 校验注册中心与 Cube schema 一致性，`gen_semantic_artifacts.py` 生成 `catalog.generated.yaml`，`result_contract.yaml` 约束查询结果契约（Agent 查询后做契约校验，违规告警日志）。

**3、Cube schema（`cube/schema/*.js`，16 个文件 22 个逻辑 cube）**：口径的执行定义与供数 API，上游直连 DataCrawler MySQL，下游是 `xuchang_cube_metrics` 工具。与江苏的 dbt 宽表不同，这里的"加工"主要是三类：排名本地重算（与省平台同口径）、乡镇站 src/app 双口径视图（`view_dat_town_hour_src/app`）、月/年累计视图。

## （3）Cube 语义层

22 个逻辑 cube 对应采集库数据集，按数据域分七组。每个 cube 的口径要点与质量限制（摘自注册中心）如下：

**实时发布·城市组（河南 18 城市组含济源）**

| Cube | 对应表 | grain 与口径要点 |
|---|---|---|
| SsfbCityHour | SsfbCityHour | 一行=城市×小时；采集源滚动窗口 |
| SsfbCityDay | SsfbCityDay | 一行=城市×日；**2026-10 起源接口不发布 PM10，缺失不得当作零或用于趋势判断** |
| SsfbCityHourRank | SsfbCityHourRank | 一行=小时×城市排名对象；实时重算窗口；排名越低越优，1 为最优，同值并列 |
| SsfbCityRanking | SsfbCityRanking | 一行=期次类型×期次×城市组；仅保留 daily 期次，月/年累计统计改走官方月报（ProvinceMonth/ProvinceMonthCum），monthly/yearly 已停用并删除历史行 |

**实时发布·区县组（含济源和功能区）**

| Cube | 对应表 | grain 与口径要点 |
|---|---|---|
| SsfbCountyHour / SsfbCountyDay | SsfbCountyHour / SsfbCountyDay | 一行=区县×小时/日 |
| SsfbCountyHourRank / SsfbCountyDayRank | 同名排名表 | 与省平台区县排名同口径；排名越低越优 |

**实时发布·站点组（许昌县级站，剔除国控）**

| Cube | 对应表 | grain 与口径要点 |
|---|---|---|
| SsfbSiteHour / SsfbSiteDay | SsfbSiteHour / SsfbSiteDay | 一行=站点×小时/日 |
| SsfbSiteHourRank / SsfbSiteDayRank | 同名排名表 | 许昌县级站排名；排名越低越优 |

**乡镇站（双口径）**

| Cube | 对应表 | grain 与口径要点 |
|---|---|---|
| TownHour | view_dat_town_hour_src/app | 一行=乡镇站×小时×口径；**必须过滤 caliber=app 或 src 否则重复计数**；官方结论优先 app，回退 src 须注明未审核；-99 无效值不参与聚合；2024-01 起 |
| TownDay | view_dat_town_day_src/app | 同上，日粒度，2024-08 起 |

**官方月报（统计与考核的唯一官方口径）**

| Cube | 对应表 | grain 与口径要点 |
|---|---|---|
| ProvinceMonth | ProvinceMonthReport | 一行=期次(Scope=month)×层级×区域；供暖季无 O3 列，区/县表无 SO2/NO2/CO/重污染天；同比列为官方变化率%；区域数量随期次变化 |
| ProvinceMonthCum | 同上 | 一行=期次(Scope=cum)×层级×区域；1-N 月累计，2026 年第 1 期无累计表 |
| CountyMonth | CountyMonthReport | 一行=区域×月；许昌县市区官方原值（剔沙尘）非明细聚合；**魏都/开发/东城/示范/建安=国家平台，鄢陵/襄城/禹州/长葛=省平台，两平台口径不同**；重污染天 2023 年起才有 |
| CountyMonthCum | 同上 | 一行=区域×累计截止月；个别区域累计与当月之和有 1~2 天官方修订差，原值入库勿互相换算 |

**年度目标与考核（人工回补定版）**

| Cube | 对应表 | grain 与口径要点 |
|---|---|---|
| XuchangCityYearTarget | XuchangCityYearTarget | 一行=年度；**年度目标值全库唯一来源**；实际值为国家网口径，与平台实时未审核列有 1~5μg/m³ 差；2026 年仅有目标值（在途年度） |
| XuchangCountyYearTarget | XuchangCountyYearTarget | 一行=区域×年度；官方考核剔沙尘定版；2023 年重污染天与月报差 3~4 天（月报未剔沙尘），年度口径以本表为准 |
| HenanCityYearTarget | HenanCityYearTarget | 一行=地市×年度；仅供省内横向比较；**优良天/重污染天 2021/2022/2024 为天数、2023/2025 为比例%，同列跨年口径不同** |

**全国排名**

| Cube | 对应表 | grain 与口径要点 |
|---|---|---|
| Rank168CityMonthly | Rank168CityMonthly | 一行=城市×期次类型×月份；综合指数+PM2.5 倒序；**仅用于全国排名对比，浓度绝对值以本地口径为准；与省内排名 SsfbCityRanking 不可混算** |

## （4）Agent 取数通道与治理边界

Agent 面前有三条受控取数通道，与江苏"Cube 点数 / SQL 明细 / 平台 API"的三分法对应：

1. **语义点数查询**：`xuchang_cube_metrics`（Cube REST，JWT 鉴权），指标口径唯一，查询结果过 `result_contract` 契约校验，带质量策略引导（quality_policy）；
2. **受控明细取证**：`execute_crawler_sql_query`（DataCrawler MySQL 只读，表契约注入工具描述）；业务库明细走 `execute_postgres_sql_query`；
3. **平台/外部接口复用**：国控 5 分钟数据、空气质量实况、气象、卫星、组分等走专用查询工具实时调用，不落采集库历史——这正是"考核/统计指标不进采集范围，复用已有平台接口"原则的另一半：**不回补官方报表的，就连数据也不复制，按需取用**。

治理规则收敛为一句话：**官方定版口径（月报/年度考核/168 排名）人工回补、原值入库、禁止换算；高频实时数据自动采集、本地重算排名但注明代理口径；一切口径限制写入 registry 的 limitations，作为 Agent 解释的硬边界。**
