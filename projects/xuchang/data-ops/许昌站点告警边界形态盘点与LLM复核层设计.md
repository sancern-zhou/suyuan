# 许昌站点告警边界形态盘点与 LLM 复核层设计

- 日期：2026-11-18（盘点数据截至 11-18 23:00）
- 范围：`xuchang_station_deviation` 场景（判据修订版，DS 单点突升 / CL 连续抬升 / OL 站点离群）
- 关联文档：《许昌空气质量浓度告警规则判据修订实施说明》；已上线改造 5a9af19c（DS 区域合并收口双站缝隙）

---

## 一、背景

当前快速告警完全由规则驱动。运行一周后发现，规则的"触发"能力是可靠的，但"定性"能力存在系统性边界盲区：部分触发并非其名称所暗示的现象（如"单点突升"同窗口双触发、"站点离群"实为片区一致偏高），也有真实异常因数据时序问题被漏报。本文档基于全量事件盘点给出边界情形分类，并设计 LLM 复核层承担"定性判断"，规则层保留"触发"职责。

## 二、盘点方法与数据范围

- 数据源：`xuchang_station_alert_episodes`（63 个 episode）、`push_log` 逐日 JSONL（65 条实际推送 + 约 140 条被 quiet_hours/hysteresis/cooldown/priority 抑制的候选）、XcAiDb 分钟/小时表。
- 方法：对每条实际推送告警还原触发时刻的六站完整现场（各站实测值、排序结构、最大间隙/全距、簇归属、伴生站偏离、DS 基线当日分位、质控标记、地理距离），逐条打结构标签。
- 范围：2026-11-13 ~ 11-18（判据修订版上线后 6 天）。

## 三、边界情形清单（六类，按严重度排序）

### 边界 1：双簇片区型 OL（占 OL 推送 8/23 ≈ 35%）

- **特征**：六站排序呈双簇（最大间隙 ≥ 全距 45%），候选站只在自己簇内略高；OL 以"其余 5 站均值"为参照，该均值落在两簇之间，导致高簇顶部被判"离群"；伴生站同向偏离 ≥0.5×阈值。
- **典型案例**：
  - 11-18 16:45 市一中 PM10=38：六站 18/19/20/31/37/38，前 3 站均值 19、后 3 站均值 35.3，间隙 11（全距 55%）；候选在自己簇内仅高 2.7，被周边均值 25 判为离群 52%。伴生望田路 11.8 = 阈值 12.5 的 94%。
  - 11-18 10:15 市一中（伴生 1.1×）+ 10:20 望田路（伴生 1.4×）双双过阈，**同一双簇事件推送 2 条**（间隔 5 分钟）；同型：16:25+16:45、11-17 06:05+06:25、11-16 21:55（3 站同簇仅推 1 条，覆盖不一致）。
- **地理佐证**：伴生对均为 2.7km 的市一中↔望田路。
- **后果**：片区现象误定性为"单站离群"，调度指令（核查本站周边积尘/烟尘）指向错误；同一事件重复推送。

### 边界 2：小时值迟到/事后修订（最严重，兼涉漏报与不可复盘）

- **漏报案例（本期最大遗漏）**：11-18 12/13 时市一中 PM2.5=41/44（剔除本站均值 5.6，偏差 38.4 = 3.2×阈值，全距 88% 的孤立高值）**零告警**——13:01 评估 12 时槽时该值尚未入库；PM2.5 小时槽每小时只评一次、永不回看。同一时段反而给开发区/望田路 Δ+6 的低洼反弹推了 DS。
- **不可复盘**：29 条小时 DS 推送中约 13 条（45%）事后被平台修订，现在回看 Δ≤0，触发证据已被洗掉；其中 4 条小时值后来带质控标记（PM/PF/H），按现行口径本属无效数据。
- **根因**：小时值迟到 + 每槽单次评估 + 平台事后修订，三者叠加。

### 边界 3：低基线反弹型 DS（约 7/29 ≈ 24%）

- **特征**：DS 基线（前一小时）处当日 0~35% 分位的异常低洼，小幅回升即过 max(基线×40%, 6) 下限。
- **典型案例**：11-18 18 时市一中（基线 6→15，分位 33%）+ 望田路（基线 5→14，分位 11%）双 DS——已由 5a9af19c 区域合并收口为一条，但反弹误报本身仍在；11-17 04:00 芙蓉广场基线 21→7（回看 Δ=-14，属边界 2）。
- **对照**：同日 17 时开发区基线分位 53%、+8 为真抬升。

### 边界 4：低浓度相对离群（CO 类，3 条）

- **特征**：优档 CO 绝对门槛 0.3 mg/m³ 在低浓度段被比例/下限轻易击穿。芙蓉广场 CO 0.315/0.34/0.407（其余站 0.01~0.3）一日三次，全部优档、绝对差仅 0.2~0.3 mg，无业务意义。
- **对照**：新元大道 CO 1.085→1.566（5 倍于邻站）为真异常，两条推送均有效——CO 规则能抓真事件，但低浓度段口径需分层。

### 边界 5：慢性偏离站的重复离群

- 望田路 PM10 一日 4 次 OL（13:50/15:15/16:25 + 此前 hysteresis 抑制的连续候选）；11-16 夜间 22:25~23:35 连续 13 个 5 分钟槽 OL 候选被 quiet_hours 拦截。新元大道 PM10 一日 3 次（08:00/15:30/18:30，均为真单高）。
- **性质**：真异常但形态是"持续偏离"而非瞬态，逐次推送价值递减，运营层（hysteresis/quiet）在兜，更适合汇总进日报。

### 边界 6：区域整体抬升时的选站噪声（CL/DS 侧）

- 11-17 00:00 新元大道 PM2.5 CL：六站 36~54 区域性齐升，CL 命中其中**较低**一站推单站通报。
- 11-17 19:30/19:35 芙蓉广场 SO2 同站 DS+CL 连推 2 条，而伴生新元大道（偏离 1.22×阈值）零通报——多站事件覆盖不一致。

### 对照组：判定干净的告警（约 40% 推送）

新元大道 NO2 07:30、PM10 08:00/15:30/18:30、CO 08:20/08:25（孤立单高或 5 倍跳升、地理孤立 10km）、市一中 SO2 06:50/11:00（单高 gap 0.8~1.0）、开发区 NO2 21:30 等——无伴生、绝对量显著，规则判定与业务直觉一致。**规则的触发能力不需要动**。

## 四、事件定性体系（四形态 + 两横切守卫）

| 形态 | 判据特征 | 处置 |
|---|---|---|
| ① 单站瞬态异常 | 孤立单高/跳变、无伴生、绝对量显著 | 按现状逐条推送 |
| ② 片区一致偏高 | 双簇 + ≥1 伴生同向过阈 + 地理邻近（2~5km） | 合并一条区域通报，片区排查指令 |
| ③ 区域整体抬升 | ≥3 站同向（≥4 站 CL 已有区域合并） | 城市级合并通报 |
| ④ 持续偏离 | 同站同因子当日 ≥3 次或连续多小时 | 降级汇总进日报 |
| 守卫 A：数据有效性 | 小时槽回看 2~3 小时（event_id 幂等去重）；修订后复核窗口 | 堵边界 2 漏报 |
| 守卫 B：低浓度下限 | 优档 CO 绝对门槛分层（如 ≥0.4）或加"邻站显著低于本站"反证 | 堵边界 4 |

## 五、LLM 复核层设计

### 5.1 架构位置：一次调用，两个产出

```
规则引擎(触发) → 运营闸门(冷却/防抖/限额/免打扰，代码) → ★LLM 复核★ → 通报生成(已有 LLM) → 推送
                                                              ↑
                                            本周期全部过闸候选一次性批量输入（非逐条调用）
```

核心思想：**把"定性判断"从代码拿出来交给 LLM，规则只负责"触发"**。场景 1（推/沉默）是场景 2（形态判定）的推导结果——同一槽位全部候选放进一次调用，LLM"看着整张六站快照"判定形态并给出处置：10:15 市一中 + 10:20 望田路天然归并为一个现象。簇间隙比例、伴生阈值等易碎数值判据不再硬编码。

### 5.2 裁决输出 schema（含校验约束）

```json
{
  "reviews": [{
    "event_id": "xuchang-air-...",
    "phenotype": "single_station_transient | district_co_elevation | regional_rise | sustained_deviation | data_quality_doubt | low_significance",
    "involved_station_ids": ["1005A", "1012A"],
    "action": "push | merge_into:<主告警event_id> | digest | suppress",
    "confidence": 0.85,
    "reason": "市一中37/望田路36与其余四站(11-20)形成双簇，站距2.7km，判片区一致偏高"
  }]
}
```

**确定性校验**（校验不过 → 按规则原判推送）：

1. `involved_station_ids` ⊆ 证据包站点集合；
2. `merge_into` 目标必须在同一批候选内；
3. `action=suppress` 只允许挂在 `data_quality_doubt` / `low_significance` / `sustained_deviation` 三种形态（沉默白名单）；
4. LLM 不能新增候选集之外的告警。

形态 → 处置映射：②→merge（复用已上线区域合并管线与 region_stations 通报附注）；④→digest（降级日报）；doubt/low_sig→suppress；①③→push。

### 5.3 证据包（全部来自引擎，禁止编造）

六站当前槽值、各站近 30 分钟/近 6 小时序列、候选站基线及当日分位、质控标记、当日同站同因子已推次数（慢性判断）、气象风向、站名/坐标/站距。few-shot 用本次盘点的真实标注案例（16:45 片区、18:00 双反弹、CO 低浓度、新元大道真离群、望田路慢性），temperature=0。

### 5.4 职责边界（代码 vs LLM）

| 层 | 归属 | 理由 |
|---|---|---|
| 规则触发（DS/CL/OL 计算） | 代码 | 灵敏度保证；LLM 只复核规则正候选，**不做发现** |
| 冷却/防抖/限额/免打扰 | 代码 | 运营政策，确定性执行 |
| fail-open | 代码 | LLM 超时/异常/低置信 → 按规则原判推送；沉默是高风险动作，宁可错报不可漏报 |
| 审计 | 代码 | 每条裁决写 push_log（action/phenotype/confidence/reason）；被沉默事件进当日摘要，人工可一键改判 |
| 形态判定 + 推送裁决 | LLM | 本文档场景 1+2 |
| 通报撰写 | LLM（已有） | 注入 phenotype 字段，按形态切换措辞与调度指令 |

### 5.5 风险与对策

| 风险 | 对策 |
|---|---|
| LLM 误杀真告警 | 沉默白名单 + 低置信放行 + 沉默事件日摘要人工复核 |
| 判定漂移/不一致 | temperature=0、few-shot 真实案例锚定、schema 硬校验、月度用调度回传复盘 precision |
| 时延 | 每周期一次批量调用 ~10-30s，5 分钟节奏可接受 |
| 模型服务不可用 | fail-open + 复核失败率监控 |
| 时延敏感的重大事件 | 视运行情况再考虑"轻度以上直通" |

### 5.6 灰度路线：先见习、后授权

- **Phase 1 影子模式（1~2 周）**：LLM 复核上线但只记录不改判，实际推送仍按规则走；将"LLM 说该沉默/该合并"与实际推送及现场回传结果对比，量化准确率（重点看：该沉默的是否真为噪声、该合并的是否同一现象）。
- **Phase 2 授权**：准确率达标后启用 merge/digest/suppress；已上线的 `ds_region_merge_sites`（5a9af19c）降级为 LLM 不可用时的粗粒度确定性兜底。
- **Phase 3**：证据包扩充（风向扇区、片区目录），按复盘结果迭代 few-shot。

## 七、验收指标

- 漏报数：以小时槽回看上线后捕获的"迟到大值"计数（基线：本期 1 起/6 天）。
- 定性准确率：影子期 LLM 判定与人工复核/现场回传的一致率（目标 ≥80% 再授权 suppress）。
- 重复推送：双簇事件合并后同一现象推送条数（基线：本期 4 起，每起 2 条）。
- 无效复盘率：推送后 Δ 被修订洗掉的 DS 占比（基线 45%，通过回看+复核窗口观察改善）。
- 日推送量与拦截结构：push_log 按形态统计，防止"沉默白名单"被滥用。
