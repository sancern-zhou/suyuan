## 一、总体架构：两条并行审核线

组分站与常规站审核流程一致，拆分为**两个每周定时任务**分别取数、跑规则、成稿并提交审核卡片：

| 任务 | 站点范围 | 工单类型 | 调度 | 表单数据来源 | 规则范围 |
|---|---|---|---|---|---|
| `gd_routine_work_order_audit`（广东例行工单审核·常规站） | 常规站（主网） | Check 运维单、SECCheck 现场检查单、SECCheckCnemc 计划内现场检查、SECFlightCheck 飞行检查、Inspection 巡检单、WorkRectify 运维工作整改单 | 每周一 10:00 | 主网 33 张 RF 分表（RF_W_*、RF_M_*、RF_Q_*、RF_TW_*、RF_HY_* 等） | 全量 81 条规则目录（含视觉与语义复核） |
| `gd_sup_station_work_order_audit`（广东例行工单审核·组分站） | 组分站（组分网） | SupCheck 组分网巡检单、SupSECCheck 组分网现场检查单 | 每周一 11:30（错峰） | `sup_rf_common` 通用宽表（306 列，一行=一张表单体）+ 组分站专用分表（sup_rf_deviceflowcheck、sup_rf_ambienttemperature、sup_rf_pm1monitorinspection 等） | 通用规则（流程/生命周期/必填/时间/设备/附件）+ 组分站专属 SUP_* 档案规则 |

两类任务共同点：

- **审核窗口**：`audit_window_preset="weekly_created"`，即上上周一 00:00 至上周一 00:00 创建且完成的工单（上上周完整自然周；如 10-26 运行审核 10-12~10-18）。已作废工单不参与审核。
- **排除范围**：故障类工单（Fault / SupFault）不在每周例行审核内。
- **运行方式**：只读数据，不创建或派发工单，不修改审核规则。
- **视觉识别**：定时审核默认不启用（`enable_visual=false`，只跑非视觉规则）；照片视觉审核 / 水印核验仅在用户明确要求时单独开启。
- **结果交付**：确认有问题的工单逐单生成审核卡片推送任务调度中心（category=工单审核，decision 按严重度选 needs_action / needs_evidence，checks 按命中规则逐项给出），单轮最多 20 张、按严重度优先；最后输出 200-400 字审核综述（总量、命中分布 Top5、问题集中站点、已提交卡片数、数据缺口），不输出内部技术语言。

### 数据结构差异（为什么规则分两套）

- 常规站表单：一类表单一张分表（RF_W_INSPECTION、RF_M_GASEOUSFLOWCHECK 等 33 张），列名语义化，规则引擎取数清单 `RF_TABLES` 直接覆盖。
- 组分站表单：全部进通用宽表 `sup_rf_common`（Sup_RF_Common，306 列，列名为 string1..string150 / bool_1..bool_50 / time1..time4 等通用命名），语义必须按 `ruleitemtag`（表单类型标签）逐类型维护；另有少量组分站专用分表为语义化列名。主网约 40 条绑定主网表单/字段的量值、公式、视觉类规则对组分站天然不命中，因此组分站在通用规则之外另建档案驱动的专属规则（二期）。

## 三、组分站审核规则

### 3.1 一期：通用规则覆盖

组分站工单取数走 sup_mode（请求类型全部为 SupCheck/SupSECCheck 时绕过主网排除口径，RF 表单改查 `sup_rf_common`，以 `SUP_RF_COMMON` 键进入 `rf_forms`），规则引擎/证据包/报告全链路通用消费。一期覆盖的通用规则（与常规站共用同一实现）：

| 类别 | 规则 | 组分站适配说明 |
|---|---|---|
| 流程链 | FLOW_MISSING / FLOW_NO_CREATE / FLOW_NO_CHECK | 直接复用（组分网流程环节 SupCheck_Check/Review/Approve 已在语义字典） |
| 生命周期闭环 | LIFECYCLE_FINISH_NEAR_DEADLINE / LIFECYCLE_FINISH_WITHOUT_EFFECTIVE_CLOSURE | 直接复用 |
| 表单必填/人员 | RF_REQUIRED_FIELD_LOW_VALUE / RF_AUDITOR_EMPTY | 字段档案加组分站别名：准备/复核/审核人员 = prepareuserid/reviewuserid/audituserid |
| 时间窗 | RF_CHECK_TIME_OUTSIDE_RANGE | 检查时间字段 CHECKDATE 已覆盖 |
| 设备一致性 | RF_DEVICE_IDENTITY_INCONSISTENT | 表单内品牌/型号/编号 vs 设备维度表（一期限制：组分站设备不在主网 dim_device 台账，待二期扩展） |
| 附件 | ATTACHMENT_REQUIRED_MISSING / ATTACHMENT_REPORT_MISSING 等 | 附件仍走 wo_commonfile，直接复用 |

主网表单专属的量值、公式、单位、多点线性、O3 传递等约 40 条规则对组分站不适用（表单结构与字段完全不同），规则输出为空属正常。

### 3.2 二期：档案驱动的组分站专属规则（SUP_*）

来源：`backend/app/services/ops_audit/rules/sup_form_rules.py`、`sup_attachment_rules.py`、`sup_watermark_rules.py`；判定逻辑全部来自 `configs/sup_form_profiles.yaml`（按 `ruleitemtag` 逐类型建档）。档案标注约定：

- `confirmed: false` 表示阈值/列语义来自数据推断与案例反推，待业务确认后置 true；
- `enabled: false` 可按表单类型停用全部规则；
- 命中率口径：近 90 天本地库，附件要求类型命中率 <5% 才纳入（避免把行业常态误报为问题）。

### 3.3 附件要求汇总

| 表单类别 | 必须上传 | 注意 |
|---|---|---|
| 年度维护检定（激光雷达/颗粒物等） | 年度维护/检定报告或证书扫描件 | 仅过程照片不算数 |
| 周质控（甲烷/非甲烷、水溶性离子、重金属、VOCs 单点、YT 单点） | 本周质控数据文件（Excel 等电子表格） | 仅零点/跨度照片不算数；数据文件须为当周（距检查日期 ≤7 天） |
| 甲烷/非甲烷总烃分析仪半年维护 | 现场照片为主 | 不强制报告 |
| 其他 | 按档案 required_attachments | 命中率 <5% 的类型不设硬性要求 |

- **豁免**：表单备注写明"无需送检、无需检定、不适用、无此项、未配置、停运"等原因时，跳过对应附件要求。
- **一致性**：附件必须与表单属同一监测项目；全部附件类型码指向其他监测项目时提示"疑似附件与表单不一致"（高）。

### 3.4 照片水印核验（试点：抽检 + 问题触发）

防止"拿别的站的照片交差"（案例锚点：博罗石下周质控附件照片水印为河源站点）。模式为抽检 + 问题触发，不做全量以控制视觉调用成本：

- **抽检范围**：已被其他规则命中的工单，照片全检（问题触发）；其余工单按工单号稳定哈希抽样，默认比例 30%（同一工单跨次运行判定一致）；每轮视觉任务硬顶 20 个、每单最多 2 张照片（可用环境变量 `OPS_AUDIT_SUP_WATERMARK_*` 覆盖）。
- **比对三维度**（任一不符 → 人工核验任务，中严重度，不直接判失败）：
  1. **地点**：水印地点与站点名称（2 字滑窗重合）、所属城市或地址相关，任一信号成立即视为相关（宁可漏报不误报）；
  2. **坐标**：站点台账有经纬度且水印含坐标时按 Haversine 距离判定，默认阈值 5 公里，台账缺坐标自动跳过；
  3. **时间**：拍摄时间应落在检查日前 7 天窗口至检查日之间（按表单档案 watermark_check 配置，周质控为 7 天）。
- **运行方式**：例行每周审核默认不做照片内容识别；水印核验在需要时单独开启（enable_visual=true）。
- **识别失败**：输出技术诊断（不进报告问题清单），与主网视觉规则口径一致。

### 3.5 保护性检查

如果某张组分站工单在系统里找不到任何表单数据，不会当作"没有问题"通过，而是单独提示"需核实是漏填报还是数据未同步"，避免数据缺口被静默漏掉。

## 四、问题严重程度与处理方式（两类任务通用）

| 级别 | 含义 | 典型处理 | 卡片 decision |
|---|---|---|---|
| 高 | 影响数据真实性、追溯性或流程完整性 | 退回整改：补附件、改填报、复测 | needs_action（需整改） |
| 中 | 存疑或证据不足，需要人工确认 | 人工复核：确认备注、照片是否说得通，补齐证据 | needs_evidence（需补充证据） |
| 低 | 风险提示 | 结合其他证据留意即可 | 视情况 |

`report_ready=false` 时，待核验项不入正式卡片，只在综述中说明待核验数量与原因。

## 五、组分站规则演进脉络（背景）

1. **一期之前**：组分站表单全部进 `sup_rf_common` 宽表，主网取数清单不含该表，且引擎曾显式排除 SupCheck——组分站实际无规则覆盖。
2. **一期（2026-10-25 落地）**：sup_mode 取数接入 + 字段档案扩展（人员三段流转字段、CHECKDATE）+ 放开流程链/生命周期/附件规则的 order_type 限制，通用规则端到端生效；拆分两个每周任务。
3. **二期（已落地）**：306 列语义普查（18 条人工排查案例 + 22 类仪器文档转录 + 全分表 tag 盘点）后，按 `ruleitemtag` 建档落 SUP_* 档案驱动规则：公式复算、阈值区间、必填、日期合理、周期及时、异常无备注、附件要求与项目一致性、水印试点。部分阈值 `confirmed: false` 待业务确认。
4. **已知待办**：组分站设备台账（一期设备一致性规则对组分站暂不命中）；水溶性离子柱压需读 xlsx 数据文件的判定；`confirmed: false` 阈值的业务确认。
