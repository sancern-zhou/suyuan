# 广东运维站点网络与工单数据集说明

## 站点网络

广东省空气质量监测网络由主网与组分网（超级站成分监测网）组成：主网含国控站点、省控站点、乡镇站等类型，站点信息包含站点编码、中文名称、经纬度、地址与站点类型；组分网单独成网。站点名录与归属关系的唯一权威来源是站点维度表 dim_station（每日全量刷新）：主网站点（ID 1000+）来自 base_station，组分网站点（ID 1~102）来自组分网视图，两组 ID 空间不重叠；组分站类型统一标注"组分站"，经纬度、地址与运维单位信息暂未同步。站点数量、按地市/区域分布等动态口径请通过站点目录工具或 dim_station 实时查询，本字典不维护具体数字。站点维度的中文名示例：从化天湖、南沙大稳。

组分站（组分网）单独成网，其巡检、现场检查、停运、故障、整改、校准与绩效审核使用 Sup 前缀的专属工单类型（SupCheck、SupSECCheck、SupPowerFailure、SupFault、SupWorkRectify、SupDeviceCalibrate、SupAchievement）。

## 站点运行监控口径

- 站点运行日报监控数据上传连续性：连续缺数超过 4 小时记为缺失事件，1-4 小时短时缺失不列入；数据恢复上传即停止跟进。
- 国控站点数据与省控站点数据来源不同通道，日报中分开列示。
- 部分候选编码站点在运状态待人工核实，未上传数据不自动等同于离线站点。

## 工单数据集结构（data-ops 同步链路，2026-10-24 起）

数据链路：运维源库（Operation_SC_GD）→ ODS 同步层（`guangdong_ods`，按水位增量）→ dbt 加工层（`guangdong_mart`，契约重建 + 数据测试）→ 语义层（Cube，指标口径唯一）。原 fetcher 直写方式已下线，数据刷新由运行时计划任务完成（小时级增量 + 每日全量）。

- 工单主表：一行一张工单，含工单号、站点、设备、类型、状态、紧急程度、维护周期、创建/更新/完成/计划完成时间、超时标记与费用。
- 工单处理明细：一行一个流程步骤，含环节代码、处理人、起止时间、处理状态、故障原因与处理描述；是时效分析与流程链核查的依据。
- 附件索引：一行一条附件记录，按工单号关联，用于附件完整性核查；附件文件本体存于源系统。
- 站点维度表：站点名录与归属区域；设备维度表：站点设备构成与品牌型号。
- 工单分析宽表（mart_work_order_analysis）：一行一张工单，预计算时效（响应/处理/修复时长）、超期（按计划完成时间重算，分母=有计划时间单）、30 天重复故障、附件计数与故障根因（首个故障原因）；是指标语义层与跨工单统计的首选入口。
- 字段契约唯一来源：`projects/guangdong/data-ops/sync/datasets/*.yaml`；指标业务口径登记：`projects/guangdong/data-ops/semantic/registry.yaml`。

## 审核要点（工单月度审核）

- 完整性：已完成工单的标题、内容、完成时间与处理人不得缺失。
- 时效：完成时间减创建时间应与维护周期匹配；计划完成时间超期需说明。
- 附件：质控类、巡检类工单应有关联表单附件。
- 流程链：处理明细的环节序列应符合工单类型对应工作流的定义。
