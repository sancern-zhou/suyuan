# 广东运维工单类型与流程字典

本文档定义广东省空气质量监测网络运维管理系统的工单类型体系、工作流对应关系与状态语义，是运维工单审核、统计与故障归类的语义基准。（数据核对：2026-10-31，基于 guangdong_mart 同步库实测。）

## 工单类型（工单类型代码 → 中文名 → 业务含义）

- Check（运维单）：例行动巡维护工单，覆盖周维护、月维护等周期性现场维护任务，是最主要的工单类型。
- Fault（故障单）：站点设备故障或数据异常触发的故障处理工单，需填写故障原因（AlarmReason）。
- SupFault（组分网故障单）：组分网设备故障或测值异常触发的故障处理工单（如 VOCs、重金属分析仪故障），走组分网专属流程，不填写 AlarmReason。
- SupCheck（组分网巡检单）：组分站（超级站成分监测网）的周期巡检工单。
- SupSECCheck（组分网现场检查单）：组分网的现场监督检查工单。
- SECCheckCnemc（计划内现场检查）：按计划安排的现场检查工单。
- SECOutsidePlan（计划外现场检查）：临时安排的计划外现场检查工单。
- SECFlightCheck（飞行检查工单）：飞行检查任务工单。
- QCBlackOut（自动质控报告工单）：自动质控（QC）停运期间的数据质控报告工单。
- StationBlackOut（临时停运申请）：站房临时停运的申请审批工单。
- SupPowerFailure（组分网停运工单）：组分网设备或站房停运工单。
- WorkRectify（运维工作整改单）：运维检查发现问题的整改工单。
- SupWorkRectify（组分网运维工作整改单）：组分网运维整改工单。
- Results（成效审核工单）：运维成效的审核工单。
- Performance（绩效审核工单·旧版）与 Performance2026（绩效审核工单·2026版）：运维绩效考核审核工单。
- SupAchievement（组分网绩效审核工单）：组分网绩效审核。
- DataMakeup（数据回补单）：监测数据缺失后的回补申请工单。
- AbnormalDataReview（数据审核异常工单）：数据审核发现的异常数据审核工单。
- PlanChangeMT（运维计划变更申请单）与 PlanChangeSC（现场计划变更申请单）：维护计划或现场计划变更审批工单。
- DeviceCalibration（设备校准单）与 SupDeviceCalibrate（组分网设备校准单）：设备校准任务工单。
- Inspection（巡检单）：一般巡检工单（源系统中另有同名"维护"流程版本）。
- SECCheck（现场检查单）：现场检查工单的通用流程。
- GreenHouseCheck（温室巡检单·日）：温室气体监测站点的日巡检工单。

类型字典覆盖源系统 WFL_WORKFLOW 的全部类型；当前同步窗口（数据以 2026 年为主）内实际出单的类型共 18 种：Check、SupCheck、Fault、SupFault、SupSECCheck、SECCheckCnemc、Performance、Performance2026、WorkRectify、QCBlackOut、StationBlackOut、SupPowerFailure、SupWorkRectify、Results、GreenHouseCheck、DataMakeup、SECFlightCheck、SupDeviceCalibrate。SECOutsidePlan、SupAchievement、AbnormalDataReview、PlanChangeMT、PlanChangeSC、DeviceCalibration、Inspection、SECCheck 在窗口内暂无工单，保留字典定义。

## 工单状态

- Finish（已完成）：工单流程全部走完。
- Doing（处理中）：工单正在流程中流转。
- Wait（待处理）：工单已创建但尚未开始处理。
- Invalid（已作废）：工单被作废。

统计工单量时必须按 order_status 显式过滤（全类型工单入表，含已作废 Invalid）。

## 紧急程度

Urgent（紧急）> Middle（一般）> Normal（普通）；空值表示创建时未填写。

## 维护周期（maintenance_type）

Day（日维护）、Week（周维护）、TwoWeek（双周维护）、Month（月维护）、Quarter（季度维护）、HalfYear（半年维护）、Year（年度维护）、AsNeed（按需维护）。例行维护工单按周期到期发起，超期未完成即为时效风险。

## 流程环节（process_step）

- 通用环节：CreateOrder（创建工单）→ Approve（审批）/ Review（审核）→ CheckOrder（工单核查）。
- 主网故障单：FaultProcess（故障处理），另见 FaultRepair（维修）、FaultJiaoZhun（校准）环节。
- 组分网巡检三级：SupCheck_Check（检查）→ SupCheck_Review（审核）→ SupCheck_Approve（审批）。
- 组分网故障单三级：SupFault_Review（审核）→ SupFault_Repaire（维修）→ SupFault_Approve（审批）。
- 组分网现场检查三级：Sup_SECCheck（检查）→ Sup_SECOperationCheck（运维核查）→ Sup_SECApprove（审批）。
- 整改链：Rectify_Check（检查）→ Rectify_Approve（审批）→ Rectify_Confirm（确认）；组分网对应 SupRectify_Check / SupRectify_Approve / SupRectify_Confirm。
- 现场检查与多级审批：SECCheckCnemc 与 OperationCheckCnemc（计划内现场检查与核查）、PF_SECCheck、PF_ProvincialCenter（含 2026 版 PF_ProvincialCenter2026）、TD_NetWorkApprove、TD_MasterApprove。
- 申请发起环节：QC_OperationApply（质控停运申请）、TD_OperationApply 与 TD_SupOperationApply（主网/组分网运营申请）。
- 成效与数据类环节：ResultsOrder（成效审核）、SJ_OperationEdit / SJ_DataReview（数据编辑与审核）；另有 ReceiveDevice（设备接收）、SupDevice_Review / SupDevice_Calibrate（组分网设备校准的审核与执行）。

## 典型关系

- 工单 属于 站点（每张工单归属一个监测站点）。
- 工单 关联 设备（故障单、校准单、巡检单通常明确涉及一台或多台设备）。
- 工单 遵循 工作流（每个工单类型对应一个或多个工作流定义）。
- 工单 处理人 用户（每个流程环节由运维人员处理）。
- 故障单 归因 故障原因（AlarmReason 字段记录根因，仅主网 Fault 单填写）。
- 例行运维单 遵循 维护周期（Week/Month 等周期约束完成时限）。
