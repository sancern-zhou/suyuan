# 站点故障诊断

## 适用范围

- 用户按站点、工单或异常现象发起即席诊断：站点数据异常（断数、超标、数值可疑）、设备故障、告警原因分析、故障工单根因。
- 与每日定时故障扫描任务互补；不做工单审核、不生成审核报告。
- 输出对象是运维统筹、监管督查和现场运维人员。

## 固定诊断流程

1. **明确诊断对象**：站点、设备、时间窗口和异常现象。信息不足时先用 `ask_user_question` 确认，不带着模糊对象取证。
2. **解析站点**：用 `guangdong_station_catalog` 核对站点编码、城市、站点类型、运维单位和人员；组分站无经纬度/运维单位/人员的缺口如实声明。
3. **图谱形成候选原因**：在已选知识库范围内调用 `knowledge_graph_query`，`depth=1`、`top_k<=5`，形成候选原因清单。图谱结果只是线索和候选关系，必须回到证据核验；无结果、超时或未选知识库时立即跳过，不投入多轮迭代。
4. **证据核验**：逐项核对以下证据，优先同站点、同设备、同污染物、同时间窗：
   - 运维工单：`mart_work_order_analysis` 查该站近期故障单、状态、响应与修复时长、故障根因、重复故障标记；`working_order_details` 查处置步骤和 `alarm_reason`。
   - 设备生命周期：`mart_device_lifecycle_analysis` 查近期检定、启用/停用、信息更新事件及关联工单。
   - 告警通知：`mart_alarm_notify_analysis` 查该站近期告警类型与时间分布；当前态势查 `mart_station_alarm_status`。
   - 站点监测数据：`query_gd_suncere_station_hour_new` 或 `query_gd_suncere_station_day_new` 查异常时段前后的小时/日数据形态；监测数据不与工单数据混算，不做跨源拼接结论。
   - 平台指标：需要站点覆盖、工单时效等口径时用 `guangdong_query_metrics`，口径唯一。
   - 现场信息：用户提供的照片、描述和处置记录。
5. **归因排序**：只保留最多三个有证据支撑的候选原因；无支持证据的常规可能性合并为"待现场排除项"，不逐项罗列。
6. **输出**：按下方结构返回。

## 故障归因参照

优先从广东平台近一年实测高频原因中取：平台误报警、站点网络信号异常、现场质控检查、站房申请停运、站房空气开关跳闸、站点所在区域线路整修停电、数采卡死、设备故障、雷雨天气跳闸、站房网络设备故障、工控机卡死、数采故障、工控机故障/系统故障、站点出现瞬时停电。用户现象与历史原因明显不符时再考虑其他原因并说明。需要分类型排查要点时读取 [分类型诊断手册](projects/guangdong/skills/station-alarm-diagnosis/references/fault-playbooks.md) 对应章节，最多读两个章节。

## 证据口径（硬约束）

- 告警通知是无闭环状态的流水，只能说明"何时何站发生了什么类型的告警通知"；不得推断"已处理/未处理"或处理时长。
- 当前告警态势覆盖面以源系统推送为准，只能表述为"推送范围内"，"未推送=无告警"不成立。
- 设备事件动作使用中文表述（周检/月检/季检/半年检/年检/启用/新增/停用/信息更新）；"QuaryCheck"是源系统对"季检"的拼写，对外统一说"季检"。
- 工单历史为今年窗口，今年之前不可查；实时流转状态以源库为准，本地数据集为非实时同步层。
- 监测突变、恒值或断数是症状，不自动等同于仪器故障；同时排查质控、采样、通信、供电和环境因素。
- 历史工单只提高相似原因优先级，不能独立证明本次根因。
- 每条证据标注时间与来源业务口径；同一现象多源证据冲突时并列呈现差异，不择优表述。
- 安全、供电、气路泄漏、设备高温等风险优先给出现场隔离和人工确认措施。

## 输出结构

1. **一句话结论**：症状、当前判断、置信边界和是否建议现场核查。
2. **关键证据**：最多 5 条，按"时间｜来源｜事实"写；只保留改变判断的证据。
3. **候选原因**：最多 3 条，每条一行，格式为"原因｜置信度｜支持证据｜缺口/确认动作"。
4. **处置与验证**：立即/现场动作合并列出最多 5 条，验证标准最多 3 条。
5. **缺失信息**：还需要什么数据或现场信息才能收敛结论。
6. **审核建议**：只列必须由人工确认的风险或缺失信息，最多 3 条。

区分三种表述：`已证实`、`推断`、`待核实`。不要输出已派单、已修复或已恢复，除非证据中存在对应的明确状态记录；不要声称已经创建工单或执行设备控制。

## 边界

- 只做诊断和建议，不创建、派发、修改或关闭工单，不执行设备反控。
- 不调用 `submit_task_review`：广东站点故障诊断的人工处置通过对话和右侧资源完成，聊天内不提交待办。
- 不调用江苏专用事件证据包或工具链。
