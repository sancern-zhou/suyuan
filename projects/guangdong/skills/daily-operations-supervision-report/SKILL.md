# 日常运维监管月度报告

## 适用场景

- 用户提出"本月/上月全省日常运维情况""工单完成与超期""故障响应与重复故障""告警通知分布""巡检完成与超期""绩效得分与金额""平台到报率""日常监管报告"等需求时使用。
- 目标是回答：基础运维工作是否落实、哪些站点/单位/指标异常、需要省站介入什么。
- 不适用：专项风险线索核验（使用 `运维风险监管报告`）、单点故障诊断、单张工单审核。

## 面向环境业务管理用户（强制）

报告读者是负责运维统筹、监管督查、绩效考核和资源安排的管理用户，不是技术人员：

- 正文只写业务事实、管理指标、问题清单和管理建议，用日常业务语言。
- 严禁出现接口名、字段名、表名、SQL、脚本、文件路径、工具名等技术语言。
- 每个数值结论说明统计对象、时间范围、分母和数据截至时间；口径声明用业务语言。
- 数据缺失、查询失败或已有口径限制时，如实说明影响，不编造、不用流畅文字掩盖。

## 工作原则

1. **不编数字**：所有数字来自取数或基于取数的确定性统计，可用 `execute_python` 复算，不心算。
2. **可回溯**：每个结论能回到站点、时间、工单号或记录；原始数据先落地留存。
3. **区分事实与判断**：确定问题、待核查线索、管理建议分开表述。
4. **量化优先**：优先用数字说话；无法量化时说明原因。
5. **先结论后论证**：先给核心指标总览与结论，再逐链路展开。
6. **如实披露**：空结果不等于无异常；未接入的数据在"数据盲区"列明。

## 编排方式

- 由 `operations_analysis` 父 Agent 加载本技能，父 Agent 不直接取数，只做拆解、委派、口径核对、结论整合和报告收口。
- 数据准备按数据域委派：工单 `gd_ops_data_workorder`、告警 `gd_ops_data_alarm`、巡检 `gd_ops_data_inspection`、绩效 `gd_ops_data_performance`、设备 `gd_ops_data_device`、站点台账 `gd_ops_data_station`、平台到报率 `gd_ops_data_rates`；一个节点只做本域，跨域另建节点。
- 常态问题委派 `gd_ops_regular_analysis`；风险假设委派 `gd_ops_risk_analysis`。内部节点不再次委派、不成稿、不发布、不提交审核。
- 简单问题用 `call_sub_agent` 串行调用；正式报告或复杂交叉分析用 `run_agent_workflow` 编排 DAG。
- 父 Agent 把日期、对象、指标定义、分母、数据盲区和阈值写入节点任务契约；同源数据一次准备，后续节点复用资源。
- 预算：并发最多 3、累计节点 12、节点重试 3、补图 2 次、累计 1200 秒；预算不足优先交付已完成成果并说明限制，不另建工作流绕过。

## 标准工作流程（九步方法论）

Define → Frame → Collect → Validate → Analyze → Synthesize → Compose → Review → Deliver。快问快答只需拆解与分析两步；正式报告走全程，步骤可并行迭代：

1. **明确任务边界**：报告给谁看、回答什么问题、支撑什么决策、统计周期与站点范围、交付格式和截止时间。
2. **拆解问题结构**：拆成可验证子问题，搭出结论先行的报告骨架，确定指标、分母和口径。
3. **数据获取**：本地数据优先，由对应数据子模式完成。指标类问题由数据子模式使用语义层口径取数；逐单明细、语义层未覆盖的统计和口径核对由数据子模式用受控查询取数；站点归属由站点数据子模式解析。父 Agent 不直接调用取数工具，只核对子节点返回的口径、覆盖和资源引用。
4. **校验与清洗**：检查缺失值、异常值、口径一致性、时间对齐和单位；关键数字复核分母与范围；语义层与明细口径冲突时并列说明，不择优。
5. **分析**：描述性统计 → 对比/趋势/结构 → 按需量化估算；用 Python 或 SQL 实际计算。
6. **提炼结论**：从数据到洞察到建议；区分事实、推断和建议，每条结论标注证据。
7. **成稿与可视化**：图表服务论点，每图配一句管理解读；标题、轴和图例用业务语言。
8. **质检**：数字前后一致、单位一致、图表与正文对得上、无未标注假设、空结果未被写成"无异常"。
9. **交付**：附数据来源、口径、关键假设和局限（含数据盲区）。

## 可开展的分析（指引，非全集）

1. **工单处置**：工单量与类型构成、完成率、故障单响应时效、超时在办、30 天重复故障站点、分单位/城市对比。例行单超期只看源系统超时标记。
2. **告警通知**：通知量、类型分布、站点与城市覆盖、逐日趋势；不得输出未处理率或处理时长。
3. **巡检执行**：任务项完成率、超期率、转工单率，按周期/监测项/站点/城市分组；最近 1-2 天完成态需声明滞后。
4. **绩效**：得分排名、低分清单、质控合格率、核减/扣款/实发金额；得分与金额为平台口径原值。
5. **平台到报率**：按站点/日期分布，直接使用平台统计结果。
6. **设备生命周期**：周期检查执行、启用/停用事件、关联工单的维修轨迹。
7. **站点台账**：站点构成、城市与运维单位覆盖、运维人员名册；组分站无经纬度/运维单位/人员须声明。

## 口径速查（硬约束）

- 工单量与时效结论必须声明是否含作废单、哪些类型；完成率分母含作废单。
- 超期率分母只计计划完成时间非空的单；故障单无计划完成时间，超期不可评估。
- 例行维护单（运维单、组分网巡检单等）超期只能引用源系统超时标记，禁止引用重算超期率。
- 响应类指标仅故障单可评估；重复故障仅故障单口径（同站同设备前 30 天）。
- 告警通知无处理闭环状态，未处理率、处理时长不可评估；当前态势只能表述为"推送范围内"。
- 巡检完成状态滞后于创建，超期=未完成且过计划结束日；转工单率分母为全部任务项。
- 绩效得分与金额为平台原值，不重算；金额单位元；组分站无运维单位信息，横向比较按合同分组。
- 到报率以平台统计为准，禁止自算；所有数据仅覆盖今年窗口，历史对比须说明起点。

## 报告结构

执行摘要 → 核心指标总览 → 各链路发现 → 问题与异常站点清单 → 管理建议 → 附录（数据来源、口径、明细）。图表服务论点，每图配一句管理解读。

## 结论边界与数据盲区

- 只做只读分析，不创建或变更工单，不修改监测数据，不认定责任。
- 确定问题与待核查线索分开表述，建议可执行、可跟踪。
- 当前未接入或不可用的数据：人员到站签到与轨迹、门禁记录、智能事件中心、质控任务明细与单站质控曲线、停运审批主表（历史停运主表已停更）、站点在线离线历史状态。相关分析只能列为数据盲区，不得推测补造。

## 报告交付

1. 先读 `backend/app/tools/report/report_package/references/index.md`。
2. 组织完整 `report.qmd`；图表由分析节点用业务图表工具生成，父 Agent 复用其图片资源。
3. 调用 `create_report_package`：`report_type='analysis'`，`output_formats=['html','docx','share_html']`。
4. 广东工具链没有独立渲染、验收和发布工具，不调用 `render_report_package`、`validate_report_package` 或 `publish_report`；失败时如实说明，不宣称报告完成。
