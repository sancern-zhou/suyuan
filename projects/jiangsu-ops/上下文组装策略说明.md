# 上下文组装策略说明

本文用于说明智能体每次调用模型前如何组装上下文，方便绘制部门架构图和排查提示词缓存命中率问题。

## 设计目标

- 高优先级规则始终在前，低优先级资料不能覆盖平台规则。
- 系统上下文保持稳定前缀，动态内容尽量追加在后面，提高提示词缓存命中率。
- 对话历史使用结构化消息传递，不再把历史转成大段文本重复塞进当前用户消息。
- 当前轮新增信息只追加，不改写前面的稳定部分。
- 不同模式的专属上下文互相隔离，避免江苏运维、画板、问数、图谱等场景串上下文。

## 总体结构

一次模型请求由三块组成：

1. 系统上下文
2. 历史消息
3. 当前轮用户消息

画图时可以按下面的主链路表达：

用户请求 -> 会话恢复 -> 活动上下文解析 -> 资源索引读取 -> 上下文构建器 -> 模型请求 -> 工具执行 -> 结果登记 -> 历史追加 -> 下一轮

## 系统上下文层级

系统上下文按固定顺序组装，顺序越靠前优先级越高：

1. 平台规则
2. 模式规则
3. 用户选择的技能
4. 会话固定规范
5. 验收清单
6. 会话资源索引
7. 长期记忆
8. 运行时元数据

各层职责如下：

| 层级 | 作用 | 变化频率 | 缓存策略 |
| --- | --- | --- | --- |
| 平台规则 | 规定优先级、循环控制、路径约定 | 很低 | 放在最前 |
| 模式规则 | 定义当前模式能力边界和工具使用方式 | 很低 | 稳定前缀截止点 |
| 用户选择的技能 | 当前任务选中的工作方法 | 中 | 追加在稳定前缀之后 |
| 会话固定规范 | 用户固定到会话的要求文档 | 中 | 追加在稳定前缀之后 |
| 验收清单 | 后续用于强制验收的结构化要求 | 中 | 追加在稳定前缀之后 |
| 会话资源索引 | 当前会话可用文件、产物、资源路径 | 高 | 追加在稳定前缀之后 |
| 长期记忆 | 模式级或用户级稳定背景 | 中 | 追加在动态层后段 |
| 运行时元数据 | 当前参考时间等临时信息 | 很高 | 放到最后 |

## 缓存命中率策略

提示词缓存依赖“前缀不变”。因此系统上下文不能把每轮都会变化的内容放在前面。

当前策略是：

- 平台规则和模式规则形成稳定前缀。
- 缓存断点放在模式规则之后。
- 用户技能、固定规范、资源索引、长期记忆、当前时间都放在断点之后。
- 当前时间不再放入平台规则，而是独立放到系统上下文最后。
- 不支持显式缓存标记的模型，只接收清理后的系统块，依靠服务端自动前缀缓存。
- 支持显式缓存标记的模型，只在稳定前缀末尾打标记，不缓存后面的动态层。

画图时可以画成：

稳定前缀：平台规则 -> 模式规则 -> 缓存断点

动态追加：技能 -> 固定规范 -> 验收清单 -> 会话资源 -> 长期记忆 -> 当前时间

## 历史消息策略

历史消息不进入系统上下文，也不重复写进当前用户消息。

处理顺序是：

1. 从会话恢复历史消息。
2. 必要时修复工具调用和工具结果的配对。
3. 超过阈值时压缩旧历史。
4. 压缩只作用于历史消息，不改写系统上下文。
5. 历史摘要放在旧历史位置的前段。
6. 最近消息保持原始结构，继续追加在历史摘要之后。
7. 当前轮用户消息放在最后。

画图时可以把消息层画成：

历史摘要 -> 最近消息 -> 当前轮用户消息

## 增量追加策略

一次运行内，尽量只追加新内容：

1. 先组装上下文并调用模型。
2. 当前用户消息在规划上下文构建完成后只写入一次。
3. 工具调用结果以结构化消息追加。
4. 最终回复追加到会话尾部。
5. 工具产生的新资源登记到会话资源目录。
6. 下一轮重新读取资源索引，但不会改写前面的平台规则和模式规则。

这样做的目的：

- 减少模型请求前缀变化。
- 避免历史消息重复注入。
- 避免工具结果丢失配对关系。
- 让长任务可以通过摘要继续推进。

## 模式隔离策略

不同模式只允许注入自己需要的上下文：

| 模式 | 允许的专属上下文 |
| --- | --- |
| 画板模式 | 画板结构、选中元素、当前图片输入 |
| 问数模式 | 地图交互事件、地图程序执行回执 |
| 图谱模式 | 当前知识库编号、选中节点或关系 |
| 社交模式 | 用户档案、长期记忆、心跳内容 |
| 普通分析模式 | 会话资源、固定规范、长期记忆 |

如果上游误传了不属于当前模式的上下文，构建器会清理掉，避免跨模式污染。

## 画架构图建议

建议画三张图：

1. 主流程图

用户请求 -> 会话恢复 -> 资源与活动上下文解析 -> 上下文构建器 -> 模型请求 -> 工具执行 -> 会话追加

2. 系统上下文层级图

从上到下画八层：平台规则、模式规则、技能、固定规范、验收清单、会话资源、长期记忆、运行时元数据。  
在“模式规则”后画一个“缓存断点”。

3. 历史消息追加图

旧历史 -> 历史摘要 -> 最近消息 -> 当前轮用户消息 -> 工具结果 -> 最终回复

## 排查要点

- 如果缓存命中率低，先看系统上下文前两层是否发生变化。
- 如果每轮都重新生成当前时间，要确认它仍在最后一层。
- 如果模型忘记文件，先看会话资源索引是否包含资源编号和路径。
- 如果工具调用报协议错误，先看历史消息里的工具调用和工具结果是否成对。
- 如果模式串线，先看模式隔离清理日志。
