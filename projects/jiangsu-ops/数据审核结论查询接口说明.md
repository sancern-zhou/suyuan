# 数据审核结论查询接口

面向江苏省审核联网平台及运维前端，提供 AI 数据审核复核结论的查询能力。结论由 `jiangsu_data_audit_review` 定时任务 Agent 生成，统一存储在 PostgreSQL（`task_reviews` 表）。

## 1. 概述

- 接口前缀：`/api/jiangsu/data-audit`
- 鉴权：需登录态（与平台其余业务接口一致，请求头携带平台登录令牌）。
- 结论粒度：一个**站点 + 审核日**对应一条结论，业务编号 `subject_id` 形如 `3001A:2026-09-14`。
- 数据来源：AI Agent 通过 `submit_task_review` 提交的结构化结论；平台人工审核日志回流后会合成人工决定并触发增量重审。

## 2. 结论列表

`GET /api/jiangsu/data-audit/conclusions`

### 请求参数（Query）

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `station_code` | string | 否 | — | 站点编码，精确匹配 |
| `city_name` | string | 否 | — | 城市名称，精确匹配 |
| `start_date` | string | 否 | — | 审核日起（含），`YYYY-MM-DD` |
| `end_date` | string | 否 | — | 审核日止（含），`YYYY-MM-DD`，不能早于 `start_date` |
| `decision` | string | 否 | — | AI 审核建议：`approve` / `reject` / `needs_evidence` / `needs_action` |
| `status` | string | 否 | — | 结论状态：`pending_review` / `in_disposal` / `archived` / `rejected` |
| `limit` | int | 否 | 50 | 每页条数，1～200 |
| `offset` | int | 否 | 0 | 起始偏移 |

## 4. 字段字典

### 结论字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `review_id` | string | 结论唯一标识，同一站点-审核日复用同一 ID，版本递进 |
| `subject_id` | string | 业务编号，`站点编码:审核日` |
| `station_code` / `station_name` / `city_name` | string | 站点编码、名称、城市；可能为 `null`（取 sections 缺失时） |
| `audit_day` | string | 审核日，`YYYY-MM-DD` |
| `title` | string | 结论标题 |
| `summary` | string | AI 审核结论，50 字以内，说明数据是否有效、原因与无效剔除时段 |
| `decision` | string | 审核建议，见下表 |
| `comment` | string | 给审核员的补充说明与需人工核查事项 |
| `status` | string | 结论状态，见下表 |
| `version` | int | 结论版本，每次提交或人工决定后递增 |
| `created_at` / `updated_at` | string | 创建/更新时间（ISO 8601，含时区） |
| `data_impact_count` / `checks_count` | int | 数据处置建议数 / 核验项数 |
| `human_decision` | object\|null | 人工决定；由平台审核日志合成时 `actor.username=jiangsu-audit-platform` |
| `human_feedback_status` | string\|null | 长期学习状态：`pending` 待学习 / `completed` 已学习 / `failed` 学习失败 |

### `decision` 取值

| 值 | 含义 |
|---|---|
| `approve` | 初审操作总体有证据支撑，数据无需处理 |
| `reject` | 存在应处理未处理或过度处理等实质问题 |
| `needs_evidence` | 关键页签取证失败，无法依据其余证据判断 |
| `needs_action` | 需处置（人工反馈合成时可能出现） |

### `status` 取值

| 值 | 含义 |
|---|---|
| `pending_review` | AI 已提交，待人工确认 |
| `in_disposal` | 人工处置中 |
| `archived` | 已归档（人工确认或平台审核日志闭环自动归档） |
| `rejected` | 已退回（触发增量重审） |

### `human_decision.action` 取值

`confirm` 确认 / `reject` 退回 / `start_disposal` 开始处置 / `complete` 完成。

### `sections` 关键字段

`sections` 为区块数组，`fields[].key` 中可用的业务字段：

| key | 说明 |
|---|---|
| `station_code` / `audit_day` | 站点编码 / 审核日（必填） |
| `station_name` / `city_name` | 站点名称 / 城市 |
| `initial_review_summary` | 初审结果页签摘要（必填） |
| `anomaly_summary` | 恒值/离群页签摘要（必填） |
| `tab_record_counts` | 三页签记录数 |
| `data_points_of_concern` | 分歧或需人工关注的数据点 |
| `evidence_gaps` | 页签取证失败或截断说明 |
| `overall_conclusion` | 整站整日整体结论 |

## 5. 错误响应

| HTTP | detail | 场景 |
|---|---|---|
| 401 | `Not authenticated` | 未携带或令牌无效 |
| 404 | `conclusion_not_found` | `review_id` 不存在或不属于数据审核任务 |
| 422 | `decision 取值不合法` / `status 取值不合法` | 过滤参数非法 |
| 422 | `end_date 不能早于 start_date` | 日期区间非法 |
| 422 | `start_date 必须是 YYYY-MM-DD` | 日期格式非法 |

## 6. 数据更新时机

1. 每日 07:30（可配置）抓取昨天与今天的站点审核状态，对已完成初审（状态非“待审核”）的站点-审核日生成证据包并触发 AI 复核，产生初版结论（`pending_review`）。
2. 次日起回捞平台人工初审/复核日志：与 AI 结论一致时合成 `confirm` 并归档，同时把人工反馈沉淀到案例库与长期记忆；存在分歧时合成 `reject` 并以 `continuity_context` 触发增量重审，重审结论自动归档。
3. `human_decision.actor.username` 为 `jiangsu-audit-platform` 表示该决定由平台审核日志自动合成，非平台界面人工操作。

## 7. 调用建议

- 按 `station_code` + `start_date`/`end_date` 增量拉取，`limit` 不超过 200。
- 结论可能随次日人工反馈更新，建议以 `updated_at` 和 `version` 判断是否需要刷新，缓存时间不宜超过 1 天。
- `summary` 面向业务，技术核验细节在 `checks` 与 `comment`；需要生效处置建议时读取顶层 `data_impact`。
