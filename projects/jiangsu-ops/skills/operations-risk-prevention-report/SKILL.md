# 运维风险防范监管报告

## 适用场景

- 用户提出"本月全省疑似风险""高值时段离线/停电合规""运维人员轨迹异常""报警积压""巡检落实风险""质控异常站点""风险防范报告"等需求时使用。
- 目标是输出：确定违规清单、疑似线索分级清单、人工复核建议。
- 不适用：常态化指标盘点（使用 `daily-operations-supervision-report`）、单点故障诊断、工单审核。

## 报告面向普通环境业务管理用户（强制）

- 正文只讲风险事实、判断依据、复核建议，用日常业务语言；严禁接口名、字段名、表名、SQL、脚本等技术语言。
- 疑似线索必须写"建议管理人员核查"，不得改写为违规、造假或责任认定。

## 工作原则

通用原则：

1. **不编数字**：所有数字来自真实取数或基于取数的确定性统计；可用 `execute_python` 复算。
2. **数据和结论必须可回溯**：每条线索标注涉及站点/人员、时间、判断依据；原始数据先留存本地，不做二手转述。
3. **区分事实与判断**：确定违规与疑似线索严格分离，确定违规仅限规则明确且记录完整者，疑似线索一律标注需人工复核；结论按「事实 / 推断 / 建议」三种强度表述。
4. **量化优先**：优先用数字说话，避免"较多、明显、严重"等模糊词；确实无法量化时说明原因。
5. **先结论后论证**：金字塔结构——先给风险总量与优先级结论，再逐类展开论点与数据佐证。

报告特有原则：

6. **如实披露**：数据缺失或结果为空必须说明影响，禁止把空结果表述为"无异常"。

## 标准工作流程（九步方法论）

按 Define → Frame → Collect → Validate → Analyze → Synthesize → Compose → Review → Deliver 推进。**流程可按需裁剪**：快问快答类需求只需第 2、5 步（拆解问题 + 分析给数）；正式报告走全程。各步是并行/迭代关系而非严格瀑布——分析中发现口径、边界或数据问题，回到第 1 步重新定义后再继续。

1. **明确任务边界（Define）**：报告给谁看、要回答什么问题、支撑什么决策、口径与范围、交付格式（Word/PPT/HTML/Excel）、截止时间。不确定的地方先给假设并在报告中标注。
2. **拆解问题结构（Frame）**：把大问题拆成可验证的子问题，搭出报告骨架（金字塔：结论先行、论点支撑、数据佐证）；确定所需指标体系与计算口径（对照「口径速查」）。
3. **数据获取（Collect）**：本地数据优先——按「数据能力地图」取数（mart 数据集 SQL → 平台接口取证 → 事件中心聚合）；其次联网检索（WebSearch/WebFetch）与连接器（Agent Mail、腾讯文档、资料库）；必要时调用专业数据源。原始数据落地保存，不做二手转述。
4. **校验与清洗（Validate）**：检查缺失值、异常值、口径一致性、时间对齐、单位统一；关键数字交叉验证（至少两个来源或两种算法，如 SQL 聚合与 `execute_python` 复算互核）。这一步经常决定报告可信度。
5. **分析（Analyze）**：描述性统计 → 对比/趋势/结构/归因 → 必要时建模或量化估算（敏感性分析、区间估计）。用 Python/SQL 实际算，不靠感觉给数。
6. **提炼结论（Synthesize）**：从数据到洞察到建议。每个结论必须有数据支撑并标注出处；区分「事实 / 推断 / 建议」三种强度（对应确定违规 / 疑似线索 / 复核建议）。
7. **成稿与可视化（Compose）**：先写结构再写文字；图表服务于论点（不是堆图），每图配管理解读；文字量化、避免模糊词；按「报告结构」组织成稿，面向业务管理用户的语言要求不变。
8. **质检（Review）**：自检清单——数字前后一致、单位一致、图表和正文对得上、结论能回答最初的问题、无未标注的假设、无遗留下一步的 TODO；确定违规与疑似线索未混级。
9. **交付（Deliver）**：输出到指定格式与路径，附上数据来源与口径说明、关键假设、局限性（含数据盲区）；需要的话同时给出可复用的取数/统计脚本或表格。

## 数据能力地图（按需取用）

**本地历史数据集** `execute_jiangsu_mart_sql`（只读 SELECT 带 LIMIT；自 2026-07-01 起；返回带数据截至时间）——**跨单风险筛查与聚合排名的首选**：

| 风险方向 | 数据集 | 关键风险信号 |
| --- | --- | --- |
| 报警处置 | `mart_alarm_event_analysis` | 未处理积压、持续时长、告警→工单转化断层 |
| 工单落实 | `mart_work_order_analysis` | 长期未闭环、超期、30天重复故障、响应时长异常 |
| 站点态势 | `mart_station_device_health` | 风险分级（高/中）、未处理告警集中度 |
| 巡检落实 | `mart_inspection_analysis` | 周期已结束未完成（超期）、完成率异常站点/人员 |
| 质控 | `mart_qc_execution_analysis` / `mart_qc_arrangement_analysis` | 不合格反复站点、任务过期未完成（约23个试点站） |
| 停电合规 | `mart_blackout_analysis` | 停电报备时段核对（仅65行，覆盖有限须注明） |
| 站点/设备 | `dim_station` / `dim_device` | 站点归属、城市维度、设备构成 |
| 趋势背景 | `mart_station_daily_profile` | 站点×日工单/告警计数，异常日识别 |

**平台接口**（取证与实时核实）：

- 到站签到 `jiangsu_fetch_attendance_records`；轨迹分析 `jiangsu_analyze_work_order_tracks`；工单清单与明细 `jiangsu_fetch_fault_work_orders`、`jiangsu_fetch_fault_work_order_detail`
- 站房告警与动环/供电历史 `jiangsu_fetch_station_alarm_logs`、`jiangsu_fetch_station_environment_history`（先定位异常站点与时段，再按最小窗口取数）
- 原始告警逐条复核（兜底，含电话记录）`jiangsu_fetch_alarm_records`（站点必填、≤24小时）。质控历史/状态与合格统计已由 `mart_qc_execution_analysis` / `mart_qc_arrangement_analysis` 覆盖，不再调平台质控接口；运行日志/监测曲线等质控取证在故障诊断模式下进行
- 获取率/有效率 `jiangsu_query_statistics`；站点目录与组织人员 `jiangsu_fetch_station_directory`、`jiangsu_query_operations_graph`

**事件中心** `execute_smart_event_sql_query`（告警与处置的结构化聚合，只读带 LIMIT）。

## 可开展的风险分析（指引，非全集）

按风险方向自由组合。**发现线索可随时下钻扩展**——从聚合排名下钻到单站明细、调单站动环/告警历史取证、扩大时间窗、跨数据集交叉核对——不受本清单限制：

1. **高值时段合规**：高值时段离线/停电——用停电报备单核对 + 动环供电历史佐证；高值时段到站但当期无对应故障/报警（疑似人为干预线索，只能低强度提示）。
2. **报警处置风险**：未处理积压排名（分站点/单位）、长期未处理告警、关键报警（断数/断电/超量程/离线）优先级、告警→工单转化断层。
3. **现场作业真实性**：到站与工单矛盾（有到站无工单、有工单无到站）。
4. **运维落实风险**：巡检超期未完成站点与人员集中度、工单长期未闭环排名、重复故障频发站点（设备可靠性）。
5. **质控风险**：不合格反复出现的站点、质控任务过期未完成的单位分布。
6. **交叉核查**：到站与工单不一致需同时核对当日签到与当日工单；高值离线需同时核对报警、供电历史与停电报备；报备单缺失时只能作为待核查线索。

## 口径速查

- 高值时段判定口径须固定并在报告中标注来源与界限。
- 工单超期按计划完成时间；大量长期未闭环单使超期率偏高，属数据现状。
- 质控仅约23个试点站，结论不得外推全网；巡检状态语义（未开始/处理中/已完成）为推断，待业务确认。
- 考核表窗口内无实际填报数据（最新实际 2025-04），考核维度当前只能说明数据现状。

## 报告结构（建议，可按内容调整）

执行摘要 →风险总览与分布 → 确定违规（如有，记录须完整）→ 疑似线索（按类别，每条含"事实—判断依据—为什么值得关注—建议核查动作"）→  结论 →  数据来源与口径。图表服务论点（风险分布、积压排名、时间轴证据），每图配管理解读；先给风险总量与优先级，再逐类展开。

## 结论边界

- 只做只读分析，不自动关闭报警、不修改监测数据、不认定责任。
- 疑似线索不得升级为违规；高值时段"人为干预"等判断只能作为低强度线索提示。
- 门禁进站记录（平台实测无数据，门禁-考勤一致性分析暂不可开展）、备机更换及时性与设备生命周期、排班、报备审批、停运管理、站点在线离线历史状态、数据补录明细。
