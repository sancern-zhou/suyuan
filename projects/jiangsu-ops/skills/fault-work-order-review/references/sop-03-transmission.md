# SOP-03：数据传输、平台离线与数据缺失

## 适用范围

本 SOP 仅判断小时数据有效性、缺失状态及小时剔除时段。5分钟数据仅供传输断点分析；重复、错位等分钟级线索须核验其对小时记录的实际影响，不直接生成分钟级剔除建议。

适用于站点离线、网络中断、平台未更新、工控机或数采仪通信异常、数据未上传、补传、断点续传、时间戳错位、重复上传和平台暂时不可见等工单。

工控机或通信模块只影响上传时归入 SOP-03；若同时造成仪器停机、采样中断、供电异常或测量失真，应按实际影响拆分，并对测量链部分转入 SOP-01 或 SOP-02。

## 必须核验的数据

| 数据组 | 必须核验的内容 | 用途 |
|---|---|---|
| 工单详单 | 离线原因、处置、恢复、设备、污染物和流程意见 | 建立传输故障时间线 |
| 监测数据 | 原始/审核 5 分钟、小时值、状态、标识、断点和重复 | 判断平台可见数据和缺失范围 |
| 本地数据 | 仪器或工控机本地数据、缓存状态、设备运行状态 | 区分未测量和已测量未上传 |
| 平台接收 | 最后接收、首次恢复接收、接收数量、接收率 | 验证上传链路中断和恢复 |
| 补传记录 | 补传起止、成功/失败数量、重传批次、回执 | 验证数据是否完整恢复 |
| 通信告警 | 网络、VPN、数采仪、工控机、平台链路告警 | 验证传输故障机理 |
| 附件 | 本地数据截图、通信设备照片、平台断点截图、补传回执 | 验证现场动作和对象 |

当前自动证据包若未接入本地缓存、平台接收或补传记录接口，必须将这些缺口写入 `gates`、`evidence_refs` 或 `review_comment`。不得用工单文字、平台当前状态或监测数据空结果替代本地数据和补传回执。

## 证据分层

- 核心闭环：工单详单、站点和设备对象、平台监测断点、本地数据/缓存状态、平台接收断点、补传结果、恢复验证和时间戳连续性。
- 辅助/反证：站房告警、自动巡检在线状态、附件截图、接收率统计、历史同类离线记录。
- 供电、站房温湿度、采样、泵或仪器参数直接影响测量时，不再只按 SOP-03 判断数据处置，应拆分到 SOP-02。

## 核验项

按“事实一致性 → 逻辑一致性”分析。T1–T6 核验传输对象、本地产生、缓存、平台接收、补传和时间戳事实；T7 集中判断数据分类与处置。流程节点不作为审核项，补传回执和截图属于 T5/T6 的事实证据。

| 核验项 | 必须回答的问题 | 合格条件 |
|---|---|---|
| T1 对象一致性 | 工单、站点、设备、污染物和数据源是否一致？ | 完整工单号、站点编码、设备和影响因子可唯一对应 |
| T2 数据产生状态 | 故障期间设备是否实际测量？ | 有设备运行、本地记录或相反证据；不能仅凭平台无数据判断 |
| T3 本地缓存 | 本地数据或缓存是否存在且连续？ | 能说明本地有/无数据、断点和时间范围 |
| T4 平台接收 | 平台接收何时中断和恢复？ | 有最后接收、首次恢复接收、接收数量或平台断点证据 |
| T5 补传闭环 | 是否补传成功，补传数据是否完整？ | 有补传起止、成功/失败数量、回执、截图和失败原因 |
| T6 时间戳连续性 | 补传或恢复后的数据是否无重复、错位和断点？ | 时间戳连续，重复/错位记录范围可定位，并有对应数据或平台证据 |
| T7 数据分类 | 数据属于保留、缺失、暂时不可见还是伪记录？ | 结合本地、平台和审核数据逐项分类 |

任一核心证据缺失且无法由其他核心证据补足时，工单或数据结论应为 `needs_evidence`。辅助证据缺失只需说明，不应默认阻断已经闭合的传输链路结论。

## 数据处置规则

- 设备运行、本地数据连续、平台接收中断、后续补传完整：传输异常，数据 `keep`。
- 设备未运行或本地没有产生数据，平台也无数据：无测量或缺失，数据 `missing_no_delete`。
- 平台暂时不可见但后续补传成功：不能因曾离线而剔除。
- 平台存在恒值、重复、错位或其他可定位伪记录：只对问题记录生成 `partial_exclude` 或 `exclude` 候选，并写明边界来源。
- 只有“离线”“未上传”或“已恢复”文字，没有本地数据、平台接收、补传或时间戳证据：`needs_evidence`。

## 时间段与边界

优先使用通信中断/恢复、平台接收断点、设备本地断点、补传起止和时间戳连续性作为边界。工单创建时间、故障处理时间、证据包取证窗口和“申请剔除 X 至 Y”只能作为线索。

传输中断但本地数据完整时，不生成数据无效区间。缺失数据应记录为“无测量/缺失”，不能表述为删除有效数据。没有恢复或补传证据时，不得把处置完成时间直接当作数据恢复时间。

## 人工升级条件

以下情形必须转人工并保留 `needs_evidence`，不得自动生成数据剔除结果：

- 无法确认设备是否实际测量或本地是否有缓存。
- 只有平台无数据或离线文字，没有通信、平台接收、补传或本地数据证据。
- 补传成功数量、失败数量、时间戳连续性或重复记录范围不清。
- 平台原始数据、审核数据、本地数据和附件存在关键冲突。
- 整站或多污染物缺失但无法区分供电、采样、通信和平台链路主因。
- 工单把“未上传”“无数据”直接等同为剔除，缺少污染物、起止时间或因果证据。
