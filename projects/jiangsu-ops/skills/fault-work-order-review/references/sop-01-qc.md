# SOP-01：质控/校准/仪器测量链异常

## 适用范围

本 SOP 仅判断小时数据有效性与小时剔除时段。5分钟数据用于异常、处置和恢复的参考分析，不形成分钟级处置结论。

适用于自动质控、零点、跨度、零跨、校准、标气、通零气、分析仪内部气路、光学、检测器和直接影响测量的部件异常。处置中出现泵、流量、冷凝水等采样链问题时，只有它们由质控暴露或直接影响质控任务，才作为 SOP-01 的测量链证据；否则应检查是否应路由到 SOP-02。

## 必须核验的数据

| 数据组 | 内容 | 用途 |
|---|---|---|
| 工单详单 | 现象、原因、处置、恢复、污染物、设备和时间 | 建立故障时间线 |
| 质控任务 | 类型、目标浓度、开始/结束时间、状态和结果 | 确认质控是否执行及影响窗口 |
| 质控日志/曲线 | 进气、稳态、采样、失败步骤、响应曲线 | 定位失败环节 |
| 设备信息 | 告警、流量、压力、温度、光强、泵状态 | 验证测量链状态 |
| 监测数据 | 原始和审核的 5 分钟、小时值、状态和标记 | 判断异常和既有处置 |
| 处置复测 | 维修、吹扫、重启、换件、校准、复测 | 验证恢复 |
| 附件 | 面板、质控报告、维修和复测记录 | 验证现场动作和设备身份 |

## 证据分层

- 核心闭环：质控任务、质控日志/曲线、工单详单、监测数据、处置复测和质控标识。
- 辅助/反证：设备告警、流量/泵/制冷等参数、附件照片和同城小时对比。
- 某些参数只在它们直接指向质控失败机理时才上升为核心证据；缺失辅助证据不应自动阻断结论。

## 分析维度与核验项

按“事实一致性 → 逻辑一致性”的顺序分析，使用 M1–M6 编号，编号不代表执行顺序。流程节点不纳入 SOP-01 审核，处置附件证据在 M3 中核验。

### 一、事实一致性：核验发生了什么

以工单声明与可回溯材料逐项对照，记录对象、动作、时间、结果和证据引用。事实核验仍需识别矛盾，但不在本层推导数据有效性或剔除范围。

| 核验项 | 必须回答的问题 | 核验要求 |
|---|---|---|
| M1 对象一致性 | 质控任务、工单、设备、站点和污染物是否对应同一对象？ | 站点编码、设备编号、污染物和质控类型可唯一对应 |
| M2 失败事实 | 实际发生的是失败、未执行、结果未上传，还是测量链异常？何时发生？ | 用任务结果、日志、截图或其他可核验材料确认异常类型、失败项和时间；仅工单文字不够，缺失记录不直接等于质控失败 |
| M6 数据标识 | 原始及审核数据实际带有什么标识，覆盖哪些污染物、粒度和起止时间？ | 记录实际标识、已有审核处置及其边界，并与质控起止和工单声明对照；标识缺口或冲突如实记录，标识是否合理及是否应剔除留给 M5 |
| M3 处置对应性 | 针对已确认异常，实际做了什么处置，是否对应同一设备、部件和失败项？维护处置是否有对应附件证据？ | 将维护处置逐项对应到可定位的附件照片、维修记录或平台截图，核验动作、对象、时间及原因是否相互印证；“已处理”不能替代实际处置证据，做过处置不等于已证明数据恢复有效；不要求无关辅助材料齐全 |
| M4 复测闭环 | 处置后是否实际重新质控、校准或复测，测了什么，结果如何？ | 记录复测对象、项目、时间、结果及合格状态；实际复测仍不合格时，失败事实已确认，但恢复闭环未通过；未复测或无法确认须明确指出 |

M6 判断记录与声明是否一致，不以“标识覆盖合理”为通过条件；即使 M6 事实一致，M5 仍可能判断标识覆盖不足。M4 的合格结果只证明该次复测结果，不直接证明此前数据有效，也不自动确定恢复边界。

### 二、逻辑一致性：判断数据影响

M5 数据影响集中回答下列三个问题。每项判断都要引用前述事实，说明从事实到结论的依据；事实成立不等于数据影响结论成立。

| 判断项 | 必须回答的问题 | 判断要求 |
|---|---|---|
| 数据是否有效 | 已确认的异常是否影响实际测量，数据应保留、剔除还是属于缺失？ | 结合故障机理、质控注入、监测表现和恢复证据，区分真实污染、测量失真、质控伪值、无测量及未上传；质控失败不自动等于监测数据无效，复测合格不追溯证明历史数据有效；`keep` 也须说明依据 |
| 剔除污染物范围 | 哪些污染物的数据受影响，哪些不受影响？ | 从异常部件、气路或共享采样链推导影响对象，并逐污染物核验；不得把单因子质控失败扩大为全站剔除，也不得仅凭共用设备认定全部因子无效 |
| 剔除时间段 | 各污染物哪些小时记录无效，何时恢复有效？ | 分别论证小时开始与结束边界，结合小时数据、有效性规则及质控和恢复证据；5分钟曲线仅作参考，不直接采用分钟异常、工单申请区间、取证窗口、维修完成或复测时间作为小时剔除边界 |

M5 的 `basis` 按“数据有效性；污染物范围；时间段”组织，分别给出依据与结论，再逐项落入 `data_impact` 和必要的 `exclusion_intervals`。不需要剔除时，后两项明确写“不适用”并说明原因；无法判断时写出具体缺口，不用“不适用”掩盖不确定性。M5 的 `pass` 表示数据处置推理有充分依据，不表示数据一定有效；有充分依据的剔除建议也可通过该核验项。

两类分析不替代 `scope` 的证据层级。任一核心闭环缺失且无法由其他核心证据补足时，不得直接判定工单通过；辅助/反证证据缺失只记缺口，不要自动降级为 `needs_evidence`。事实部分充分而数据有效性、污染物范围或边界仍不明确时，分别保留事实结论和 M5 的不确定项，不得用“已维修、复测合格”代替数据影响判断。

## 审核逻辑

质控异常成立需要：

```text
对应质控任务
+ 站点、设备、污染物一致
+ 任务时间与工单相符
+ 日志有失败步骤或结果不合格
= 质控异常得到系统证据支持
```

仪器故障导致数据失真需要：

```text
设备告警或参数异常
+ 对应污染物原始数据异常
+ 异常与设备事件时间重合
+ 维修、吹扫、重启或换件成立
+ 处置后数据恢复或复测合格
= 测量链故障导致数据失真的证据较充分
```

只有“已恢复正常”文字，没有告警、参数、数据或复测支撑时，输出 `needs_evidence`。

偏高、突增和异常波动应使用同城小时数据或其他可得对比证据辅助判断：本站异常而同城不同步、设备异常且处置后恢复，仪器异常可能性较高；本站与同城同步、设备参数正常且无告警，真实污染可能性较高，默认不剔除。

## 人工升级条件

以下情形保持 `needs_evidence`，不得自动生成剔除结果：

- 质控对象、设备编号、污染物或站点无法唯一匹配。
- 只有工单文字，没有质控任务、日志、数据或复测证据。
- 异常起止、标识边界或小时聚合规则不能确认。
- 质控记录、监测数据、附件或工单详单存在关键冲突。
- 复测不合格、未复测或复测对象不一致。
