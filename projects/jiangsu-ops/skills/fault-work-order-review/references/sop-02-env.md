# SOP-02：监测数据与采样、供电、站房环境异常

## 适用范围

本 SOP 仅判断小时数据有效性与小时剔除时段。5分钟数据用于异常、处置和恢复的参考分析，不形成分钟级处置结论；小时区间须有小时记录与有效性规则支持。

适用于高值、低值、零值、恒值、缺失、冷凝水、采样管、采样总管、泵、流量、制冷、供电、断电、防雷、站房温湿度、颗粒物纸带、切割器和平台抬放等异常。处置中补做质控只作为恢复或复测证据，不自动改归 SOP-01。

## 必须核验的数据

| 数据组 | 必须核验的内容 | 用途 |
|---|---|---|
| 工单详单 | 现象、原因、处置、设备、污染物和时间 | 建立事件时间线 |
| 监测数据 | 原始 5 分钟、小时值、状态、标识和断点 | 判断异常、缺失和数据影响 |
| 设备参数 | 流量、压力、泵状态、制冷温度、切割器或纸带状态 | 验证采样与测量链状态 |
| 动环与供电 | 温度、湿度、电压、电流、空调、UPS、防雷和断电记录 | 验证站房及供电原因 |
| 关联污染物 | 本站其他污染物、共享采样链涉及因子 | 判断单因子或多因子影响 |
| 同区站 | 同污染物小时原始数据确定性统计摘要、区域同步性和污染过程；原始全量只作为追溯资源 | 区分真实污染与测量异常 |
| 处置与复测 | 清理、吹扫、换件、复电、调温、重启和处置后运行 | 验证原因对应性与恢复 |
| 附件 | 现场照片、仪器面板、参数截图、趋势图和维修记录 | 验证现场动作、对象和状态 |

所有 SOP 仅抓取和使用原始监测数据，不补抓审核数据，不将未抓取审核数据作为证据缺口。

自动取证按站点目录中的区县编码筛选同区站点，使用经纬度计算直线距离，优先抓取并展示距离较近的站点。核对 `comparison_scope=same_district`、`comparison_stations`、`distance_ranking_complete` 和 `selection_note`；坐标不完整时只能称“已知距离最近”，不能声称已验证全区最近站点。区县无法确定时不扩大到全市。

为兼容历史证据，字段名保留 `same_city_monitoring` 及统计子字段 `same_city`，实际范围由 `comparison_scope` 决定；历史 `same_city` 范围不能当作同区证据。当证据包提供 `same_city_monitoring.summary_mode=deterministic_summary_with_raw_resource` 时，优先使用 `pollutant_summaries` 中的目标站值、同区最小/中位/最大值、排序、分类和 `notable_hours` 判断区域同步性；不要默认读取 `raw_resource` 指向的同区全量原始记录。只有摘要缺失、分类与其他核心证据冲突、或需要复核具体边界来源时，才读取同区原始资源。

## 证据分层

### 城市气象与污染物变化

使用所属城市内有数据的气象观测站，无需等待城区站确认。优先选有数据的配置站，否则按有效小时覆盖数降序、站号升序选定一站。分析和图表标明实际 `station_name`、`station_code`，不将同城观测称为监测站原位气象。请求耗时和错误见 `requests`，已完成小时可由缓存复用。

读取证据包 `city_weather`，时间窗口与 `evidence_time_window` 及本站监测取证窗口一致。核对 `station_code`、`station_name`、`status`、`missing_hours`、`missing_parameters` 和 `gaps`；整个窗口使用同一气象站，不按不同小时拼接不同站点，明确空间代表性限制。

在 E2/E3 中将温度、相对湿度、降水、风速、风向、气压的变化与目标污染物小时原始时序对齐，分析高低值是否可能由气象变化支持，并结合 E4 关联污染物和同区变化核验。可分析风速变化与积累/扩散、风向转变与输送、降水与清除，以及温湿度、气压变化的时间对应关系；注意不同污染物的响应差异、可能的滞后和城市气象站的空间代表性。风向是环形变量，359 度到 1 度不能解释为大幅转向；静风时不将风向作为可靠输送依据。

在 `comment` 中明确写出“气象支持真实变化 / 不支持或有矛盾 / 证据不足”及具体时段、参数和污染物证据，将引用写入 E2/E3 的 `basis`、`evidence`。相关性不能证明因果；无气象变化也不能单独证明仪器故障。气象证据属于辅助证据，缺失只说明核验未覆盖，不单独触发退回补材料。E7/E8 仍独立依据核心事实判断有效性和小时边界，禁止根据气象变化自动生成剔除区间。

- 核心闭环：工单详单、本站监测原始时序、异常起止、处置与恢复、必要的动环/供电证据、影响范围和附件照片。
- 辅助/反证：采样流量、泵状态、切割器/纸带状态、平台抬放状态、同区小时对比、现场照片、面板截图和设备日志。
- 当工单直接指向流量、泵、切割器/纸带或平台抬放时，这些参数可以上升为核心证据；否则默认作为辅助或反证，不要把它们写成前置硬门槛。

## 核验项

按“事实一致性 → 逻辑一致性”分析。E1–E6 核验对象、异常、机理、影响范围、处置及恢复事实；E7–E8 集中判断数据分类与影响边界。流程节点不作为审核项，处置附件证据并入 E5，恢复附件证据并入 E6。

| 核验项 | 必须回答的问题 | 合格条件 |
|---|---|---|
| E1 对象一致性 | 工单、设备、站点、污染物和现场证据是否一致？ | 站点编码、设备编号和影响因子可唯一对应 |
| E2 异常事实 | 异常是高/低/零/恒值、缺失，还是参数异常？ | 有原始数据、告警、动环或现场直接证据；仅描述不够 |
| E3 机理证据 | 异常机理是否被参数或现场检查支持？ | 采样、泵、制冷、供电或环境证据与异常时间重合；若缺少这些辅助证据，只要核心闭环成立也可继续判断 |
| E4 影响范围 | 是否核验本站关联污染物和共享环节？ | 明确单通道、共享采样、多设备或整站影响范围 |
| E5 处置对应性 | 处置是否针对已确认原因，且有附件证据证明发生？ | 维修动作、附件证据与故障部件、异常表现和时间相匹配 |
| E6 恢复验证 | 处置后是否恢复并稳定，且有恢复证据？ | 有恢复时间、参数正常、数据恢复、复测或附件证据 |
| E7 数据分类 | 数据属于有效异常、疑似无效数据、缺失还是暂时不可见？ | 结合原始数据及其状态和本地/平台差异逐项判断 |
| E8 边界与标识 | 影响起止、稳定期和标识是否明确？ | 边界来源可追溯，标识与影响区间一致；标识只用于确认事实一致性，不能用于逻辑一致性分析或直接证明数据无效 |

E8 中的数据标识沿用 SOP-01 的代码释义表（包括 H、W、BB、D、B、R、r、HSp、LSp、PZ、PS、AS、CZ、CS、TZS、TSS、TSL、TSR、RM、ZO、PCB、GCE、PF、PM、PT、LT、LP、NT、NP、M）。审核必须写出代码含义并核对污染物、粒度、起止边界与工单声明。标识由设备自动或运维人员手动产生，是被审核对象而非证据；E7/E8 的逻辑判断必须基于原始监测数据实际变化、故障机理和处置/恢复事实。

任一核心证据缺失且无法由其他核心证据补足时，工单或数据结论应为 `needs_evidence`。辅助/反证证据缺失只需说明，不要默认拦截结论。

## 证据闭环与文字瑕疵

审核优先判断事实链路是否闭环，而不是优先查找工单文字瑕疵。若工单详单、附件照片、平台截图、本站监测原始数据和异常边界能够相互印证，应直接给出审核结论和数据处置建议；工单中不影响对象、原因、时段或处置结果的表述不严谨，只写入备注或人工关注项，不单独触发 `needs_evidence`。

只有以下冲突无法由其他核心证据补足时，才作为退回补材料依据：

- 对象冲突：站点、设备、污染物或工单号无法唯一对应。
- 事实冲突：附件、平台截图或本站监测数据不能支持工单描述的异常事实。
- 分类冲突：无法区分真实污染、疑似无效数据、缺失或暂时不可见。
- 处置冲突：现场动作、故障原因和异常表现不能对应。
- 边界冲突：异常起止、原始数据标识或稳定期无法追溯到明确时段。

若冲突仅表现为工单措辞重复、前后表述不严谨，但附件、截图、监测数据、原始数据标识和影响时段已经闭环，不应退回要求运维修改文字。

## 数据分类

- `affected`：故障导致数据受到影响，但是否剔除还需看边界和标识。
- `pseudo_value`：有设备、参数、现场或同区反证支持的异常高值、异常低值、零值或恒值等疑似无效数据。
- `missing`：设备无测量、断电、采样中断或平台缺失导致无可用数据。
- `unaffected`：有证据证明故障未影响对应污染物、粒度或时间段。
- `uncertain`：证据不足、接口失败、字段缺失或证据冲突。

无测量、断电、平台缺失或暂时不可见场景，优先判断 `missing_no_delete` 或 `needs_evidence`，不得把缺失自动转成剔除候选。

## 异常边界与剔除规则

剔除区间必须来自可核验边界，例如：

- 原始 5 分钟数据首次异常、恢复正常或状态变化。
- 小时原始数据标识、缺失、疑似无效数据或附件中的平台处置记录。
- 设备告警开始/恢复、流量/压力/温湿度/电压等参数异常起止。
- 维修、换件、重启、吹扫、复电、复测合格或稳定观察记录。
- 同区小时原始数据对真实污染或区域同步性的支持/反证。

不得直接使用以下内容作为剔除边界：

- 工单创建时间。
- 故障处理时间。
- 证据包取证窗口起止。
- 工单正文中的“申请剔除 X 至 Y”。
- 没有原始数据、参数或恢复验证支撑的“已恢复正常”。

没有恢复证据时，不得把处置完成时间直接当作数据恢复时间。

## 人工升级条件

以下情形必须转人工并保留 `needs_evidence`，不得自动生成数据剔除结果：

- 只有高值、低值或“现场正常”文字，没有原始数据、参数或现场证据。
- 无法区分真实污染、仪器疑似无效数据和采样故障。
- 颗粒物异常但切割器、纸带、流量或平台状态未核验。
- 断电、泵停机或站房异常时，无法判断是否实际测量或是否产生疑似无效数据。
- 共享采样链、供电或站房公共环节可能影响多个污染物，但影响范围未拆分。
- 处置动作与故障原因不匹配，或恢复后仍异常、复发。
- 影响起止、稳定期、标识含义或小时处置规则未确认。
- 原始数据、告警、动环、同区数据和附件存在会影响事实、分类、处置或边界判断的关键冲突，且无法由其他核心证据补足。

提交字段统一以 `references/output-contract.md` 为准；本文中的故障事实、处置、恢复、复测等业务摘要使用通用 `sections` 区块表达，不作为顶层工具参数。
