# 故障工单审核记忆维护规范

本文件定义故障工单审核中哪些内容可以随任务演进，供任务级案例库和长期记忆维护使用。它不是审核 SOP，不改变当前事实核验、数据影响判断或输出字段要求。

## 稳定规则与可迭代知识

以下内容只维护在 `fault-work-order-review` Skill 和 SOP 手册中：

- SOP 路由、事实一致性/逻辑一致性的分析框架及核验项编号；
- 输出契约、状态枚举、`data_impact` 与 `exclusion_intervals` 字段要求；
- 证据包边界、禁止自动修改平台数据、禁止把取证窗口直接当作剔除边界等不可变约束；
- 当前任务必须执行的读取顺序和提交工具。

以下内容维护在任务长期记忆中，不复制回 SOP：

- 已确认的典型故障模式、站点/设备/污染物的重复表现；
- 某类附件、参数、告警、质控曲线对事实判断或数据影响判断的实际证明力；
- 历史审核中形成的边界经验，例如某类故障的首次异常、稳定恢复和小时聚合处理方式；
- 常见证据冲突及已经验证有效的补证路径；
- 经人工确认的审核偏好、易错点和当前需要持续跟踪的问题。

长期记忆只能提供检索线索和经验参考，不能替代本次证据包中的事实核验。历史经验与本次证据冲突时，以本次证据为准，并在案例中记录变化原因。

## 案例与长期记忆的分工

- **案例库**记录一次审核已经发生的事实、结论、数据处置和关键证据发现，不写面向未来的规则。
- **长期记忆**从多个案例中提炼可复用模式、经验教训、输出偏好和当前关注；只有人工确认或多次案例支持的内容才提升为稳定经验。
- 单次工单中的猜测、未确认的相关性和临时补查结果只能留在案例或当前关注，不得直接写成长期规则。

## 建议的长期记忆骨架

沿用任务巩固器的六个固定标题；故障表现、判定示例、边界经验在相应标题下按 SOP 分组，统一在系统注入的任务长期记忆中维护，不在技能目录保留经验副本。无子分类编码要求。

```markdown
# 任务记忆：江苏故障工单审核
## 使命与背景
## 已确认的模式与规律
### SOP-01 质控/校准/测量链
### SOP-02 采样/供电/站房环境
### SOP-03 传输/平台离线/数据缺失
## 经验教训
### 初始参考经验与待验证示例
### 证据判别与边界经验
## 输出偏好
## 当前关注
```

每条经验尽量包含：适用条件、观察到的证据、支持的结论、不能推出的结论、来源案例或人工确认时间。不要把具体工单号、一次性时间段或未经确认的剔除区间写成通用规则。

## 执行时的使用方式

1. 使用执行前注入的当前任务长期记忆；有必要且已开启历史检索时查询相关案例，提取与站点、设备、污染物、SOP 和异常表现相关的经验。未注入记忆时明确经验未覆盖，继续按固定 SOP 核验，不猜测记忆路径。
2. 用记忆生成待核验假设或补查优先级，不直接生成审核结论。
3. 完成本次事实一致性和逻辑一致性判断后，将“本次已确认事实”和“与历史经验的相同/变化”写入案例。
4. 只有跨案例重复出现，或人工明确确认的经验，才在长期记忆中新增、合并或修订条目。

## 冲突与淘汰

长期记忆中的规则与固定 SOP 冲突时，固定 SOP 优先，记忆条目标记为待修订；长期记忆与本次证据冲突时，本次证据优先，案例记录冲突。过时的模式、已被新证据推翻的边界经验和不再适用的站点配置应从“已确认的模式与规律”移到“经验教训”或删除，不保留含糊的并列结论。
