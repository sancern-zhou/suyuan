# 运维工单审核报告输出规范

本规范由主 Agent 读取并执行；复核子 Agent 只负责输出 `excluded_items`、`reviewed_issue_list_path` 和 `report_input_path`。

生成正式审核报告、QMD 报告或报告包前，完整读取并执行本规范。

## 唯一数据口径

- 问题明细只使用最终复核后的 `retained_items`，即本轮 `final_issue_list.items` 扣除已校验的 `excluded_items`。
- 被排除项不得出现在正文、附录、分类统计、运维单位统计或问题总数中。
- 不得使用语义候选、语义任务、抽样结果、旧报告或历史输出补充问题。
- 报告可以整理、分组和改写已有问题，但不得重新判断、发现或新增问题。

## 报告结构

至少包含：

```markdown
# 运维工单审核报告

## 审核范围

## 数据覆盖情况

## 总体结论

## 审核规则与口径

## 问题工单明细

## 证据摘要
```

明确数据来源、筛选时间字段、时间范围、完成状态、其他筛选条件和视觉识别是否启用。不得把未验证候选写成确定结论。

## 问题明细分组

- 必须按 `operation_unit` 运维单位分组，每个单位单独列表。
- `operation_unit` 缺失时归入“未关联运维单位”。
- 每条保留问题单独占一行；同一工单命中多条规则时工单号可以重复。
- 必须完整列出所有保留问题，不按固定条数截断，不询问是否继续，不使用“另有 N 条略”“待补查”“需通过工具补全”等占位表达。

每个分组使用以下列名和顺序：

| 站点 | 中文表单 | 工单号 | 问题描述 | 原始备注/说明 | 命中规则 |
|---|---|---|---|---|---|

字段来源：

- `站点`：优先使用 `station_name`，缺失时使用同轮数据集中的 `base_station.NAME`；两者都没有时明确标记缺失，不猜测。
- `中文表单`：使用 `rf_form_name`；不得向用户展示内部英文表名 `rf_table`。
- `工单号`：使用完整 `working_order_code`。
- `问题描述`：根据本条 `message` 与 `evidence` 展开为可核查事实。
- `原始备注/说明`：优先使用与当前异常直接相关的原始备注；对于 `RF_RANGE_OUT_OF_SPEC`、`RF_ABNORMAL_VALUE_NO_REMARK` 等需要语义复核的规则，只展示能解释当前异常的字段级备注及原文，格式为“字段显示名/字段名：备注原文”；多条备注用 `<br>` 分隔。没有 `original_remarks` 时使用 `original_remark_text`。备注审核要求存在但内容为空时写“未填写”；没有备注相关元数据时写“未涉及备注审核”。不得只把备注藏在 `evidence` JSON、附录或证据摘要中。
- `命中规则`：使用 `rule_id`。

## 问题描述约束

- 引用具体字段名和值，使读者可以直接对照原始表单。
- 日期问题列出相关日期及其先后关系；数值问题列出实际值、期望范围或单位及偏差方向。
- 枚举问题列出实际值和允许值；缺失问题列出缺失字段或附件类型。
- 不使用“日期异常”“数值不合理”等无法核验的笼统描述。
- `evidence.violations` 有多条明细时，必须列出每条违规字段、填写值、期望值/允许范围、差值或原因，不得只写第一条。
- 公式复算类问题必须列出实填值、复算值、容差/允许偏差和关键输入字段，便于用户复核计算。
- 表单与附件/XLS 比对问题必须列出附件文件名、表单字段、表单值、附件单元格和值；缺附件问题必须列出附件要求、缺失类型、当前附件数量和已有附件类型。
- 原始值需要解析或换算的问题必须同时列出原始填写值、解析/换算值和期望范围，避免只展示处理后的值。
- `RF_DEVICE_IDENTITY_INCONSISTENT` 必须从 `evidence.comparisons` 提取当前值、对比值、对比工单号和对比工单创建时间，逐项使用“字段名：当前工单填写 当前值，对比工单（工单号，创建时间）填写 对比值”的格式。品牌、型号、编号成组变化时，明确变化方向，便于判断设备更换或填报错误。
- `RF_RANGE_OUT_OF_SPEC`、`RF_ABNORMAL_VALUE_NO_REMARK` 以及其他依赖备注语义复核的规则，必须在同一行展示原始备注/说明，便于用户直接判断异常是否已有合理说明。

## 生成与验收

1. 必要时读取同轮 `dataset_path` 或 `audit_result_path` 补充范围和统计，但不改变问题明细。
2. 组织完整 `report.qmd`，调用 `create_report_package` 生成报告包。
3. 图表资源使用报告包内相对路径，例如 `assets/charts/chart_01.png`。
4. 调用 `validate_report_package` 验收 QMD、图片引用和 HTML 预览；失败时修复后重新验收。
5. 交付时说明右侧面板可预览并下载 QMD 或 Word，不把本地绝对路径作为主要交付内容，不手工拼接下载链接。
