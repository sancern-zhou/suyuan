# 研判规则

## 数据影响、合规解释与等级

先尝试调用当前事件可用的监测、报警、仪器、气象、区域和运维接口，再核验已成功取得的实测数据是否存在断数、恒值、负值、无效值或其他异常，以及事件与数据变化的时序及逻辑方向。真实环境浓度升高、超限或接口取数失败不直接等于监测数据受损；接口失败、未接入或空结果也不构成某一类型的反证。只要可用证据已经支持某一类型，就应完成分类，不得因缺失来源机械选择“数据异常待研判”。无法确认影响时填“待确认”，说明具体缺口。

合规解释取“完全解释、部分解释、不能解释、无合规记录”。只有记录的对象、时间和作业内容能够解释全部相关事实时才选完全解释；报备存在本身不代表解释成立。

按下表定级；关键证据不足不能套用低风险等级，使用“待确认”：

| 条件 | 建议等级 |
| --- | --- |
| 疑似人为干扰，有数据影响，且合规记录不能完全解释 | P0 |
| 其他有数据影响，且合规记录不能完全解释 | P1 |
| 有数据影响，但合规记录完全解释 | P2 |
| 无数据影响，但仍存在未消除的设备、环境或行为风险 | P2 |
| 无数据影响，且全部线索已合理解释、无剩余异常或风险 | P3 |

P3 仍提交人工确认后归档。AI 与 `system_data_impact` 不一致时，在人工复核建议中说明分歧与证据；`ai_task_priority` 只决定执行先后。

## 连续性研判（增量轮次）

同站点同自然日的新线索始终属于同一事件。输入含 `continuity_context` 时比较新增线索、上一轮结论及现场反馈：同因填 `same_cause="true"`，明确不同原因填 `"false"`，证据不足填 `"待确认"`。不同原因分项描述，不能改事件编号或丢弃旧事实，也不要求拆分新事件。

反馈触发的轮次以现场反馈为基准：反馈来自处理人员的一手事实，其确认的事件类型、根因和处理结果优先于上一轮 AI 推断，据此重新选择事件类型并更新数据影响、建议等级和结论字段；不得仅因证据包存在缺口而维持“数据异常待研判”“其他待人工复核”等待定类型。反馈与证据包明显矛盾时仍按反馈更新结论，同时在人工复核建议中说明分歧证据。

提交覆盖全部已核验事实的完整结论，说明连续性依据及反馈如何修正判断。不输出供系统解析的文本标记行。

## 供电、UPS和站点级断数

确认供电/UPS、数采、监测中断和动环是否同一时间发生，区分整站、多仪器和单仪器影响。停电通知、UPS 状态和恢复后的设备自检只能作为相互印证的证据；没有直接证据时使用“疑似”或“待核实”。

## 数采网络和数据延迟

核对最后有效时间、影响污染物范围、数据时间戳递增、数采报警、站房报警和补传情况。不能把暂时无记录直接解释为仪器故障，也不能虚构缺失数据。

数采报警先经过证据层过滤，只使用数据重发堆积、数据上报/网络通讯失败、设备离线、数据传输中断及采样/质控链路告警。主机资源阈值、软件进程资源或错误日志、数据库资源或泛化 SQL 错误、自动更新失败不参与诊断；除非另有独立的数据缺失、延迟、错位或多仪器中断证据，否则不得将其写成数采入库风险。

## 仪器、质控和参数异常

对齐设备、参数、实测值和限值，检查仪器状态、采样流量/压力、质控记录、动环和历史工单。单污染物异常伴设备报警时提高仪器故障假设；多污染物同向变化且设备正常时保留真实环境影响。

## 站房环境、外界环境和超限

结合温湿度、空调/除湿、气象、片区对比和多污染物变化，区分站房环境影响、真实局地污染和设备数据影响。「疑似外界环境影响」指真实外界环境污染过程（超限或与周边同步升高）；雾炮喷淋、人员进入采样区属于人为干扰，两类不得混用。

片区对比证据的使用顺序：先看 `regional_deltas.event_hourly_alignment`（事件窗口前后各 3 小时的逐小时对齐序列，含本站与周边站点六项污染物），核验异常开始、持续、结束时间上是否同步，并直接引用对齐后的小时级数值；`event_trend_comparison` 和 `trend_comparison` 是事件窗口/全天的方向与相关系数统计，只作整窗概括，不能替代逐小时核验。`comparison.data` 保留本站与同区周边站点的原始逐小时记录，可回查任意时点；同区邻站数量以 `nearby_stations.station_count` 为准。只有 comparison 来源为空、失败或未接入时才可声明"缺少周边站点小时数据"，并登记为证据缺口。

`trend_comparison` 按同小时对齐本站与同区县站点，结合总体方向和 Pearson 相关系数判断趋势一致性。相关系数只是同步变化的辅助证据，不能单独证明区域传输、外界干扰或仪器故障；共同小时不足时按"数据不足"处理。气象接口失败、未接入或空结果时给出数据缺口，不作"没有气象影响"的否定性结论；如果其他可用证据已满足类型条件，不得因气象缺失阻止定类。

## 视频和合规线索

视频标签（雾炮喷淋、洒水冲洗、人员进入采样区等）由专业识别算法打标，直接采信为已发生的行为事实，不得重新做图像识别或再判断行为是否发生。仍需证据核验的是该行为是否影响监测数据；进站、维修、校准或喷淋报备可解释相关线索，但必须结合监测和报警证据判断是否属于合规运维核查。

视频识别结果或图片不是所有类型的必需证据。若视频来源为未接入、不可用、空结果，或证据包没有图片，跳过视频核验并将其记为非阻断性缺口；不得描述不存在的画面，也不得把视频缺失当作行为未发生。只要其他证据已经满足类型字典的判定条件，仍应完成事件分类，并在结论中说明视频缺口及其对置信度的影响。

门禁/人员进站记录同样不是必需证据。接口为空、失败或不可用时仅记录缺口，不得将其解释为“无人进站”，也不得单独触发待研判类型；继续使用可用的视频标签、工单、设备状态、报警和监测时序完成判断。

工单附件只用于补强具体操作的证明和审计，不是工单解释成立的前置条件。优先使用工单类型、对象、时间、标题、内容、状态和处置记录；只有这些字段无法核对具体操作时，才打开详单和附件。

最多保留三个有证据支撑的候选原因。每个原因写支持证据和确认动作；无支持证据的可能性合并为待现场排除项。
