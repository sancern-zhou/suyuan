# 研判规则

## 连续性研判（增量轮次）

同站点同日的新线索会合并进已有事件。输入包含 `continuity_context` 时，先比较新增线索与上一轮结论在时间窗口、涉及对象和证据链上的关系：

- 新增线索与上一轮异常同因、同对象或属于同一持续过程（如同一台仪器持续报警、供电异常延续）→ “连续性判断：同一原因延续”，结论覆盖合并后的全部线索。
- 新增线索指向不同对象或另一独立原因（如仪器报警后出现无关的数采中断），且时间上构成独立过程 → “连续性判断：新事件”，结论聚焦新线索对应的事件，并写明与上一轮事件的区分依据。
- 证据不足以判断连续性时，倾向“同一原因延续”，并在人工确认风险中说明需要补充的证据。

判断标记行必须出现在最终回复第一行；不得因增量输入丢弃上一轮已核验的证据事实。

## 供电、UPS和站点级断数

确认供电/UPS、数采、监测中断和动环是否同一时间发生，区分整站、多仪器和单仪器影响。停电通知、UPS 状态和恢复后的设备自检只能作为相互印证的证据；没有直接证据时使用“疑似”或“待核实”。

## 数采网络和数据延迟

核对最后有效时间、影响污染物范围、数据时间戳递增、数采报警、站房报警和补传情况。不能把暂时无记录直接解释为仪器故障，也不能虚构缺失数据。

## 仪器、质控和参数异常

对齐设备、参数、实测值和限值，检查仪器状态、采样流量/压力、质控记录、动环和历史工单。单污染物异常伴设备报警时提高仪器故障假设；多污染物同向变化且设备正常时保留真实环境影响。

## 站房环境、外界环境和超限

结合温湿度、空调/除湿、气象、片区对比和多污染物变化，区分站房环境影响、真实局地污染和设备数据影响。气象证据缺失时给出数据缺口，不作否定性结论。

## 视频和合规线索

视频标签只证明识别到行为，不直接证明数据受影响；进站、维修、校准或喷淋报备可解释相关线索，但必须结合监测和报警证据判断是否属于合规运维核查。

最多保留三个有证据支撑的候选原因。每个原因写支持证据和确认动作；无支持证据的可能性合并为待现场排除项。
