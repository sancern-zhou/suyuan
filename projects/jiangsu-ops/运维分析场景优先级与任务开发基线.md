# 江苏运维分析场景优先级与任务开发基线

更新日期：2026-09-14

## 判断口径

优先级同时考虑：平台接口当前可用性、规则能否确定性复现、监管价值、证据闭环和开发成本。只有数据源可稳定取得且结果可审计的场景，才进入自动定时任务；数据缺失的场景保留为交互分析或“数据不可用”任务，不生成空的合规结论。

## 场景排序

| 优先级 | 场景 | 当前数据接口 | 推荐任务形态 | 结论 |
| --- | --- | --- | --- | --- |
| P0 | 全网巡检异常汇总 | 站房自动巡检/异常汇总接口，可用 | 每日工作流 | 已具备 `jiangsu_network_inspection_workflow`，作为首个稳定值守任务 |
| P0 | 站点故障与智能事件证据采集 | 告警、故障工单、站房环境、质控历史，可用 | 事件触发工作流 + Agent 解释 | 已具备自动扫描、证据采集和待审核链路，优先补齐运行监控 |
| P0 | 故障工单批量审核 | 工单、流程、表单、附件、告警和电话记录，可用 | 日/周批处理 + 人工复核 | 规则审核和报告生成已具备，适合直接扩大覆盖 |
| P1 | 数据质量巡检（断数、缺测、有效率） | 江苏空气质量小时/日/5分钟接口，可用 | 每日工作流 | 先做事实清单和趋势，不直接归因责任 |
| P1 | 备机更换及时性/超期使用 | 设备上架、设备生命周期、备机备案接口尚未在当前工具层确认 | 取数验证后再开发 | 暂不定时上线，先做接口探测和字段样本 |
| P2 | 高值时段离线/停电合规 | 高值监测可用；离线、设备操作、报备需跨接口核验 | 混合分析 | 证据链接口未完整打通前，不输出“疑似人为干预” |
| P2 | 报警积压与长期未处置 | 告警接口可用，故障工单可用 | 每日工作流 | 可复用告警扫描，补充状态/时限规则后开发 |
| P2 | 门禁-考勤-工单三方一致性 | 门禁接口已接入；考勤当前不稳定；工单可用 | 混合分析 | 等考勤稳定后再做三方规则 |
| P3 | 工单轨迹合理性月报 | `GetAttendanceManagement` 已配置，但当前环境无法稳定返回签到数据 | Agent + 分析服务 | 暂停正式报告；支持分页后仍须先完成数据源验收 |
| P3 | 手工补录合规风险 | 补录业务接口当前未在江苏工具层确认 | 取数验证后再开发 | 暂不编写规则结论 |

## 首批任务开发

首批上线顺序为：

1. `jiangsu_network_inspection_watch`：每日巡检汇总，输出覆盖量、异常站点、城市/类别排名和人工核查待办。
2. `jiangsu_station_event_evidence_refresh`：告警/事件触发证据采集，失败重试、快照和待审核状态由工作流负责。
3. `jiangsu_work_order_audit_batch`：按日/周或单位批量审核工单，复用现有规则引擎、报告和人工复核。
4. `jiangsu_data_quality_daily`：在江苏空气质量接口上实现缺测、断数、有效率事实清单。

本轮新增的确定性计算模块为 `app.services.jiangsu_operations_reports`：

- `build_fault_monthly_report`：按站点/类别聚合故障量、处理时长和高频站点；把同站点同类、间隔不超过 24 小时且至少 3 次的连续断电/停电/断数/通信/离线事件从总体统计剔除，同时单独保留为“重复故障站点”专项清单。
- `build_backup_quarterly_report`：计算故障到备机启用小时数、备机连续运行天数、48 小时超时、30 天超期和站点备机更换频次；存在有效备案时不计入违规清单，但保留备案标记。

这两个函数只负责可审计的指标计算，报告编排、图表、DOCX 渲染和发布应由定时任务调用现有报告工具完成。

轨迹月报暂不列入首批自动任务。签到接口缺失时，任务必须返回 `status=failed` 或 `status=empty` 并说明数据范围、接口和缺失原因，禁止把空结果当作“没有异常”。

## 验收门槛

- 每个任务保存接口来源、查询时间范围、返回总数、分页覆盖情况和工具版本。
- 规则类结果必须可由原始记录复核；疑似线索不得改写为确定违规。
- 接口失败、超时、空数据和字段缺失分别展示，不能静默降级。
- 定时任务具备幂等键、失败重试和人工待办状态；不自动关闭告警、修改监测数据或认定责任。
- 轨迹分析正式启用前，至少验收连续两个完整月份的签到总量、分页完整性、人员/站点字段和坐标覆盖率。
