# 江苏空气站智能运维中枢 Demo 实施总结

> 实施日期：2026-08-18
> 项目分支：`project/jiangsu-ops`
> 演示地址：`http://127.0.0.1:5175/?command-center=1`

## 1. 项目目标

本次实施面向江苏空气站智能运维中枢大屏 Demo，目标不是提前确定完整技术方案，而是先通过可运行页面验证业务场景、首页定位和汇报故事，作为后续业务交流与方案确认的基础。

页面核心理念如下：

1. 采用轻入口设计，从“选择工具”转向“直接说目标”，由智能体承接复杂业务规则和分析过程。
2. 首页不是固定不变的数据大屏，而是“关键证据可视化 + 动态 AI 对话”的可生成工作台。
3. 不按领导、运维管理人员等固定角色完全切割页面，而是提供默认视角，再根据当前目标和场景重新组织内容。
4. 大屏默认支持语音交互，不设置传统左侧导航。
5. 大屏负责态势展示、问题发现、分析钻取和建议表达；具体审核、任务确认等执行操作回到苏小环首页完成，避免两个页面定位重叠。
6. 所有页面必须在大屏视口内完整展示，不依赖向下滚动。

## 2. 页面定位

### 2.1 智能运维中枢大屏

- 面向值守、汇报和管理分析场景。
- 强调“一屏知态势、语音做钻取、关键结论主动呈现”。
- 智能体根据用户目标生成或切换当前关注内容。
- 展示判断依据、分析边界和建议，不直接执行高风险业务动作。

### 2.2 苏小环首页

- 面向日常工作和业务执行。
- 承载完整任务草案、审核、确认、专业工作区跳转等操作。
- 接收大屏产生的待确认事项，形成人工审核闭环。

## 3. Demo 故事结构

本次 Demo 组织为三条核心业务场景：颗粒物数据中断、智慧运维调度和外部环境干扰识别。当前共保留十二个演示推进节点，并映射到四个持续工作上下文：值守入口、异常调查、智慧调度和干扰识别。

十二个推进节点仅用于语音意图识别和现场键盘兜底，不对应十二张独立页面。用户追问时，系统保留当前会话记忆和已展示的关键证据，在 AI 对话区继续追加数据、假设、人员或策略结论。

### 3.1 场景一：主动发现单站异常

连续调查链路：

`今日值守总览 → 主动异常提醒 → 单站异常专题 → 原因分析 → 附近人员分析 → 任务草案`

以上节点在同一个异常调查工作区内逐步生长，而不是切换专题页。主要内容：

- 智能体主动发现源创包装厂房站点（1002A）颗粒物数据中断。
- 关联五分钟监测数据、站房状态、现场画面和事件时间线。
- 初步判断更可能是采集或传输链路异常。
- 明确当前缺少通信日志、设备状态和近期维护记录，不能直接认定为分析仪故障。
- 根据距离、技能经验和当前负荷推荐到站人员。
- 生成核查任务草案，但任务调度仍需人工确认，并提示回到苏小环首页完成审核。

### 3.2 场景二：智慧运维调度与资源优化

连续分析链路：

`全省运维态势 → 建立调度资源上下文 → 四类调度洞察 → 综合资源优化建议`

该场景不再把“跨市运维”作为独立主题，而是以智慧运维调度为总主题。跨市任务只是判断调度合理性的一类证据，需要与运维单位覆盖、人员活动轨迹、站点到访需求和技能负荷共同分析，避免从单一轨迹直接推断人员不足或履职异常。

当前故事重点为：

- **跨市运维：**识别频繁跨市、重复往返和可由属地技能人员承接的任务；模拟分析包含 41 次跨市任务，其中 14 次具备属地承接条件。
- **运维单位轨迹：**观察不同运维单位的服务覆盖和协作路线，发现服务范围交叉、同路任务以及可以合并协作的区域。
- **运维人员轨迹：**结合人员位置、连续跨区情况、技能经验和任务负荷，识别负荷不均与调度半径过大的人员。
- **频繁到站站点：**识别短期内反复到站的站点，区分正常巡检、可合并任务和需要转入专项治理的重复问题。
- **综合调度优化：**不以简单增加人员为默认答案，而是给出“属地优先 → 技能匹配 → 负荷校准 → 同路合并 → 高频问题专项治理 → 跨市能力兜底”的建议。

地图顶部的证据图层入口支持联动：鼠标悬停或键盘聚焦某一维度时，地图突出对应的跨市任务、运维单位、运维人员或频繁到站站点图层，并弱化其他图层。默认状态同时呈现四类信号，右侧 AI 对话负责解释数据、判断边界和调度结论。

### 3.3 场景三：外部环境干扰识别

连续调查链路：

`视频识别与告警筛选 → 时空关联 → 数据影响判断 → 证据包生成 → 调度处置`

该场景用于识别可能影响站房运行、监测数据正常性或站点监测代表性的外界环境与人为行为。当前以南京恩梯恩精密机械公司站点（1006A）的模拟喷淋雾炮事件为主线，同时提供车辆停靠、人员靠近和摄像头遮挡等典型视频识别示例。

当前故事重点为：

- **视频识别：**识别喷淋雾炮、车辆停靠、人员靠近和摄像头遮挡，保留原始视频片段、目标框、时间戳与置信度。
- **告警筛选：**过滤摄像头抖动、光照变化和短暂停留等低价值告警，将需要进一步研判的候选事件送入关联分析。
- **时空关联：**关联事件位置与时间、风向风速、站点分钟数据和邻近站点变化，判断目标是否位于采样影响路径。
- **数据影响判断：**结合监测数据、设备状态、质控状态和运维记录，判断是否疑似影响本站数据或监测代表性；只给出复核建议，不自动判定数据无效。
- **证据包生成：**将视频证据、监测数据、气象条件、设备状态和运维记录形成完整证据链。
- **调度处置：**生成属地人员现场核查和证据保全草案，最终确认与业务执行仍回到详细操作工作台完成。

### 3.4 智能工作区形态

当前页面按值守入口和三类专项分析工作区组织：

- 值守总览以江苏地图为主视觉，右侧仅保留颗粒物数据中断、智慧运维调度和外部环境干扰识别三张事件摘要卡。
- 颗粒物数据中断采用双区工作区：左侧以大幅对话历史承载 AI 回答、文字证据、截图和调度计划，右侧用趋势图或监控视频展示关键证据，不再重复设置事件栏。
- 单站异常按照“事件进入 → 数据与截图证据 → 原因研判 → 人员匹配 → 调度计划”在同一段对话中逐步展开。
- 智慧调度不再设置“持续态势底座 / 江苏全省 · 今日值守”侧栏，避免与主分析区重复占用空间。
- 智慧调度采用“左侧关键地图证据 + 右侧连续 AI 对话”双区结构，四类数据、分析结论和模拟效果均在对话中自然展开。
- 智慧调度按照“提出管理问题 → 建立单位、人员、任务和站点上下文 → 展示关键截图 → 解释四类调度信号 → 形成综合建议 → 打开详细操作工作台”逐步展开。
- 除用于进入详细操作工作台的调度优化方案草案外，智慧调度分析不使用独立指标卡片。
- 外部环境干扰识别采用“左侧连续 AI 对话 + 右侧视频/数据/证据链”双区结构，六个分析环节在同一工作区逐步生长。
- 干扰识别过程中的数据与结论直接写入对话，仅将最终处置草案设计为可进入详细操作工作台的卡片。
- 底部 AI 交互入口始终保留，语音不是页面遥控器，而是向同一工作上下文追加目标和追问。

## 6. 视觉设计实施

### 6.1 大屏布局

- 页面固定占满视口，禁止整体滚动。
- 适配 1920×1080 汇报大屏。
- 顶部保留项目名称、当前持续会话、系统状态和返回入口。
- 值守总览采用“大地图 + 三张事件摘要卡”布局，不显示大段引导文字、指标带和额外栏目。
- 颗粒物调查采用“大幅对话与证据链 + 图表/视频证据”双区布局，信息沿调查过程自然累积。
- 智慧运维调度采用“关键地图证据 + AI 对话”布局，不显示独立的持续态势侧栏；地图承载截图和图层证据，对话承载数据解释、判断边界与资源优化结论。
- 外部环境干扰识别采用“AI 对话 + 关键证据视图”布局，关键证据可在视频识别、数据影响和完整证据链之间切换。
- 底部设置常驻语音交互区，显示智能体状态、回答内容、推荐语句和麦克风入口。

### 6.2 无框化设计

初版各模块采用独立容器边框，视觉上较为机械。本次在无框化基础上进一步取消传统卡片矩阵：

- 删除主要模块的外边框、圆角和卡片阴影。
- 使用留白、字号、色彩、背景明暗和局部光晕建立内容层级。
- 首屏以全省地图为主，事件仅用三张简短卡片提供摘要和场景入口。
- 单站调查、智慧调度和干扰识别均采用连续对话，关键数据、AI 小结和建议直接作为对话文字呈现；除首屏场景入口外，卡片仅用于可进入详细操作工作台的任务或方案草案。
- 地图轨迹、证据链、会话步骤和交互按钮保留业务所需线条。

### 6.3 中文化与可读性

- 页面可见栏目标题、状态标签和单位已统一为中文。
- 将“公里”“分钟”等单位改为中文显示。
- 保留站点编码 `1002A`、`PM2.5`、`PM10`、`SO₂` 等业务标准编码和污染物符号。
- 放大地图城市名、核心数字、路线说明和管理结论，改善远距离阅读体验。
- 调整关键地图证据与右侧 AI 对话区比例，增强对话结论的视觉权重。

### 6.4 颜色规则

- 青蓝色：常态运行、站点和基础信息。
- 橙红色：异常、高优先级、需要关注的跨市往返和频繁到站。
- 琥珀色：外部环境或人为干扰候选目标、视频识别框和待复核影响。
- 绿色：闭环状态和优化效果。
- 跨市任务、单位轨迹、人员轨迹和高频站点采用有限的差异色，并在联动聚焦时弱化非目标图层。

## 11. 后续建议

当前版本适合用于 Demo 汇报和业务方案讨论。业务方案确认后，可继续讨论以下技术与数据接入事项：

1. 接入实时异常事件、监测数据和设备状态。
2. 接入真实工单、签到、单位与人员轨迹、排班、人员技能、任务负荷和到站记录。
3. 明确跨市任务、单位服务覆盖、人员活动轨迹、频繁到站和响应时间的业务统计口径。
4. 将综合调度建议与实际派单审批、跨单位协作和专项治理流程衔接。
5. 接入真实视频流、视频算法告警、气象分钟数据和设备运行状态，建立视频事件与监测数据的统一时间基准。
6. 明确喷淋雾炮、车辆停靠、人员靠近、摄像头遮挡等行为的筛选规则、影响判定口径和人工复核流程。
7. 建立实时数据、模拟数据和历史快照的统一标识规范。
8. 根据实际大屏尺寸、观看距离和汇报环境继续校准字号与对比度。

在进入上述技术实施前，建议优先确认五项业务问题：单位、人员和视频数据的合法使用范围；跨市和属地任务的判定规则；频繁到站转专项治理的触发条件；外部干扰与数据代表性影响的认定口径；以及调度或干扰处置建议的最终审核责任人。
