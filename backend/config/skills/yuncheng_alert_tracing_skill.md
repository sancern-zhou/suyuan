# 运城市告警溯源分析 Skill

## 使用场景

当社交模式定时任务发现运城市小时盯守告警脚本输出 `has_alert=true` 时，由社交模式发现告警时间并调用助手模式执行本 skill。助手模式调用专家子 Agent 分析，生成报告和微信摘要后把结果返回社交模式；社交模式收到回复后推送报告给微信用户。

## 场景流程

1. 社交模式定时任务启动运城小时盯守。
2. 盯守脚本发现告警时间，输出 `latest_alert.json`。
3. 社交模式调用助手模式执行本 skill，并传入告警路径、上下文 manifest 路径和报告目录。
4. 助手模式读取正式 skill 和输入资产。
5. 助手模式调用专家子 Agent 分析，生成气象和常规分析草稿。
6. 助手模式生成报告、Word 文件和微信摘要。
7. 助手模式返回报告路径、Word 路径和微信摘要，不直接推送微信。
8. 社交模式收到回复后推送报告给微信用户。

## 输入

- `latest_alert.json`
- `tracing_context_manifest.json`
- manifest 中列出的监测、气象、图像和预报资产
- 气象分析专家子 Agent 草稿：`weather_analysis_draft.md`
- 常规分析专家子 Agent 草稿：`routine_analysis_draft.md`
- `latest_alert.json.rule_hits` 是触发告警的主规则
- `latest_alert.json.supporting_rule_hits` 是辅助解释线索，只能作为提示性证据

## 业务边界

- 不确认具体污染源。
- 不写“某企业导致污染”。
- 只能写“监测事实”“气象提示”“可能机制”“需本地数据核实”。
- 如果关键资产缺失，必须在报告中写入“数据缺口与不确定性”。
- 第一版小时盯守只抓取城市小时数据，不抓取站点数据。
- 第一版不得输出“某站点数据无效”“某站点仪器异常”等站点质控结论。
- 不重新判断告警是否成立，告警触发以脚本输出为准。

## 专家子 Agent 调度

主 Agent 不直接一次性完成全部分析，必须先调用两个 expert 模式子 Agent 生成草稿：

1. 气象分析专家子 Agent
   - 执行前阅读通用专家 skill：`backend/docs/skills/weather_analysis_expert.md`。
   - 按本运城 skill 的输入资产和草稿路径执行具体任务。
   - 负责气象历史、后向轨迹、风场、降水、温度预报和输送条件。
   - 生成 `{report_dir}/weather_analysis_draft.md`。
   - 返回最小 JSON：

```json
{
  "expert_type": "weather",
  "draft_path": "{report_dir}/weather_analysis_draft.md"
}
```

2. 常规分析专家子 Agent
   - 执行前阅读通用专家 skill：`backend/docs/skills/routine_monitoring_analysis_expert.md`。
   - 按本运城 skill 的输入资产和草稿路径执行具体任务。
   - 负责空气质量小时数据、AQI 口径、周边城市联动、未来风险和驻场建议草稿。
   - 生成 `{report_dir}/routine_analysis_draft.md`。
   - 返回最小 JSON：

```json
{
  "expert_type": "routine",
  "draft_path": "{report_dir}/routine_analysis_draft.md"
}
```

主 Agent 只依赖 `expert_type` 和 `draft_path` 定位专家草稿。详细分析、图表说明、证据限制和不确定性必须写在草稿文档中。

## 主 Agent 审核整合

- 读取两个专家草稿后再生成最终 `report.qmd`。
- 检查两个草稿是否存在跨领域越界结论；越界内容不得直接进入最终报告。
- 检查 AQI 口径、驻场建议可执行性、缺失资产说明和不确定性是否完整。
- 如两个专家结论冲突，最终报告必须写明“证据不一致或不足”，不得强行给出确定结论。
- 最终结论、微信摘要和 Word 导出由主 Agent 统一完成。

## AQI 口径

- AQI 告警使用 `AQI 小时值` 口径，触发条件为 `AQI > 100`，对应空气质量进入轻度污染及以上水平。
- `AQI > 100` 是综合空气质量指数超标提示，不等同于单项污染物小时浓度超过 100。
- 报告中必须同时写明首要污染物或主要贡献污染物；如果资产中没有首要污染物字段，只能写“需结合分项污染物确认主导污染因子”。
- 分析 AQI 告警时，优先对照 PM2.5、PM10、O3、NO2、SO2、CO 的小时变化，避免把 AQI 告警直接归因到单一污染物。

## 报告结构

1. 告警摘要
   - 告警时间
   - 告警污染物
   - 告警等级
   - 一句话判断

2. 监测事实
   - 目标城市污染物小时变化
   - 告警前若干小时变化
   - 周边城市同步变化
   - 是否存在区域同步抬升
   - 告警主规则命中情况
   - 辅助规则命中情况，例如 PM2.5/PM10 同步上升、PM2.5/CO 同步上升、NO2/O3 关系异常

3. 气象和输送条件
   - 告警前时段风向、风速、湿度、降水
   - 后向轨迹图提示的潜在输送方向
   - 逐小时风场图提示的区域流场
   - 降水、最高气温和未来天气对污染物演变的影响

4. 未来风险
   - 未来 5 天空气质量预报
   - 未来 24-48 小时重点污染物风险
   - 是否建议加密盯守

5. 初步溯源研判
   - 本地累积可能性
   - 区域传输可能性
   - 光化学生成可能性
   - 颗粒物二次转化或燃烧源提示
   - 每条判断都必须写证据和不确定性

6. 驻场工作建议
   - 每条建议必须可执行，至少包含：建议时间窗、核查范围、现场动作、补充数据、升级条件。
   - 建议时间窗：写清“立即”“未来 1-2 小时”“当天夜间”等具体执行时段。
   - 核查范围：写清上风向、周边城市联动方向、重点道路/工业片区/施工区域等范围；没有本地清单时写“建议由驻场团队按本地清单匹配”。
   - 现场动作：写清巡查、走航、企业工况核实、扬尘源排查、移动源管控建议、加密会商等动作。
   - 补充数据：写清需要补充的站点小时数据、污染源清单、企业门禁、卡口、走航、执法巡查、组分或雷达数据。
   - 升级条件：写清 AQI 或主导污染物连续上升、周边同步抬升、静稳持续、后向轨迹指向明确等触发升级会商或现场核查的条件。
   - 可转发给业主的简短建议

7. 数据缺口与不确定性
   - 未接入本地污染源清单
   - 第一版未接入站点小时数据，不能开展同城站点偏差和站点趋势一致性判断
   - 未接入企业门禁、卡口、移动源轨迹
   - 未接入执法巡查和走航结果

## QMD 输出要求

- 输出文件名为 `report.qmd`。
- 必须包含可渲染的 YAML header。
- 图片使用相对路径引用。
- 表格使用 Markdown 表格。
- 不使用需要联网加载的资源。
- 缺失的资产不得留空占位，必须在数据缺口章节说明。

## 助手模式返回要求

助手模式不直接推送微信。完成报告后必须向社交模式返回：

```json
{
  "success": true,
  "report_qmd_path": "{report_dir}/report.qmd",
  "report_docx_path": "{report_dir}/report.docx",
  "wechat_summary": "500字以内微信摘要"
}
```

## 微信摘要要求

微信正文控制在 500 字以内，格式：

```text
【运城市空气质量告警】
时间：
污染物：
等级：
结论：
建议：
报告：见附件 Word。
```
