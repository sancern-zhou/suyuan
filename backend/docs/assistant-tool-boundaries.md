# 助手工具边界与委派运行

助手使用 `manage_assistant_memory` 维护本人档案，使用 `manage_assistant_runs` 跟踪实际委派。
不再向助手暴露 `read_file`、`edit_file`、`wait_task`，也不开放 Bash、CLI 或脚本执行。
办公模式保留文件处理能力，专业执行器继续承担业务数据、图表、知识库与报告职责。

## 个人记忆

- 服务端将当前运行的隔离记忆空间和档案绑定到执行上下文，不接受模型指定的用户或路径。
- `document=long_term/profile` 支持 `read/update/delete`；修改需使用读取所得的 revision。
- 更新默认追加条目；指定 old_text 时精确替换唯一条目。删除只删除指定的唯一条目。
- 复用常驻记忆容量上限；文件锁保护并发修改，原子替换保存；后台任务不能修改个人档案。
- `document=fact` 只允许按当前个人索引的 fact_id 读取未过期事实，不允许编辑事实层。
- 普通材料经会话资源工具读取或委派 office，核心身份配置由平台维护。

## 委派运行

- social 调用 `call_sub_agent`、`run_agent_workflow` 时记录独立 delegation ID。
- 记录位于 DATA_REGISTRY_DIR 下 assistant_runs，按项目和服务端解析的用户标识隔离。
  不迁移旧任务或按旧 ID 查询。
- `list/get/result` 从持久记录查询；result 分页返回真实工具结果，避免将大结果一次塞入模型上下文。
- `cancel` 复用 ActiveWorkflowRegistry 及已配置的跨进程取消状态存储。
  接受取消请求不等于已停止，只有执行器退出后的记录才会显示 cancelled。
- `steer` 仅向仍接受输入的单个办公子会话提交文本；不支持向运行中的 DAG 修改图或向专业叶节点强行注入。
  accepted 只是排队受理，不能声称已执行补充要求。
- 子会话复用必须命中本人的委派记录；不自动复用全局最近的专业子会话。
- 执行器丢失、进程重启或控制存储不可用时，无法确认的运行显示 unknown，不自动重跑，也不宣称完成。
- 进程内任务持有运行句柄，持久记录保留结果；这里没有增加可跨重启自动恢复的后台任务执行器。
  需要稳定定时执行的工作使用统一计划工具，不能把临时后台委派当成持久调度。

## 检索与验证

`session_search` 不再提供 rebuild 参数，索引重建属于后台维护。
本轮测试使用临时目录、隔离数据库和共享内存控制存储模拟两个 worker；没有启动服务、连接真实模型或渠道，
也未验证部署环境的 Redis、浏览器、微信或 App 端到端行为。
