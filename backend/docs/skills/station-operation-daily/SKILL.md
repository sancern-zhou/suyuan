# 站点运行监控日报

## 概述

定时任务使用 `workflow` 模式，绑定 `station_operation_daily_report` 固定工作流，依次执行取数计算、固定字段填充、模板验收、PDF预览和资源发布，常规生成不调用LLM。`station_operation_daily` 保留供对话补跑或记录反馈。脚本及持久化记录提供事实，原始 Word 提供版式。

## 模板与格式

- 用户提供的版式基准：`backend/backend_data_registry/uploads/9e0901af-e0ea-4041-a807-fd8498dc330b.docx`。部署时保存模板副本，实际生成使用运行配置的 `template_path`；`template_sha256` 标识批准的模板版本。
- 直接打开模板并替换数据，不从空白文档重建。保留原有红色两行标题、字体字号、段落格式、红色分隔线、正文纵向和附件横向页面、页边距、页码、表格边框与列宽。
- 正文依次为标题、日期、单位和期号、统计说明、国控站点、省控站点、编制和校核、主送和抄送。名称和数量来自本轮数据，不复制示例中的旧站点、旧日期或旧期号；编制、校核和主送抄送为固定内容。
- 两张附表标题分别为“国控站点离线记录表”“省控站点离线记录表”。九列依次为序号、城市、站点、离线时间、是否已恢复、影响数据时长（小时）、是否影响数据有效性、排查结果、备注。没有事件时数据行填 `/`。
- 期号使用配置值，未提供则标为待确认。编制固定为许凡，校核固定为张涛；主送固定为省生态环境厅监测处，抄送固定为各驻市站。四项直接保留批准模板原文与格式，不开放给AI、报告参数或人员配置覆盖。
- 正式Word只含模板原有正文及两张附表，禁止添加“数据核查说明”等新章节。数据来源、候选名单及限制保存在 report_input.json 和任务结果中。
- 第一页底部固定保留东莞南城元岭、莞城梨川、东城主山三站交接后纳入省控监控的说明（完整文字见字段规则），11磅仿宋，使用首页专用页脚，后续页不重复；原有页码保留。该说明不由LLM或本轮数据改写。
- 工具在保存后比较模板和输出的页面分节、标题样式、分隔线、页眉页脚、表头与表格属性，并输出格式校验记录。模板版本或结构校验失败时报告失败，不交付为成功日报。模板升级或版式代码调整后须进行 Word/PDF 渲染比对，检查换页、溢出和字体替代；日常内容不同不要求页数或文字位置完全相同。

## 固定字段与用语约束

总述严格保留模板的检查系统名称和“其余国控和省控站点运行正常。”结尾，仅替换时间、数量和类别；取数不完整不得发布正式报告。详细对比依据和字段白名单见 [模板字段与用语](references/template-fields.md)。新增两份样例用于确认写法，原批准的 Word 仍是版式基准，不自动切换模板版本。

- 正文站点条目固定为“城市站点：〔经核实为具体原因，〕累计影响数据时长N小时，现已恢复正常/正在持续跟进〔，数据已回补/数据待回补/数据无法回补〕。”原因只在有核实记录时填写。
- 表格“排查结果”只填已核实的故障原因，未知填 `/`；“是否影响数据有效性”只在有明确核实结论时填“是/否”，未知填 `/`，不得根据时长、恢复或回补状态推断。
- “备注”使用“数据已回补”“持续跟进”“数据待回补”“数据无法回补”等业务用语。样例中的处置计划必须有实际核实依据，不复制到其他站点。
- 禁止向正文或表格加入“缺失项目：CO、NO₂……”等污染物清单、数据源名称、“历史未结跟进”“反馈人/反馈时间/关闭跟进”等技术或流程内容；这些只留在 report_input.json、原始证据与反馈记录中。正文不重复表格的离线起止时间。
- 标题、单位、固定说明措辞、主送抄送、表头和样式不自由改写。站点数量按唯一站点计数，不把同站多次缺失当作多个站点。

## 时间和判定要求

- 每天北京时间（Asia/Shanghai）10:30开始，统计昨日10:00至今日10:00。接口按小时结束标签采用 `(昨日10:00, 今日10:00]`，共24小时，去掉重复端点。
- 记录门槛：只把连续缺数超过4小时（即5个及以上连续缺失小时）的事件记入日报；1—4小时的短时缺失和单项污染物短时缺失只保留在原始快照中，不列入日报。相邻缺失小时合并为同一事件，非连续缺失分段记录并各自计时；连续时长按相邻缺失小时数累计，回补不缩短原观察时长。跟踪窗口以缺失时段为准：已恢复上传的事件仅在缺失时段与过去24小时窗口相交时列出，注明恢复及回补状态；缺失时段完全早于窗口后不再跟进，晚到的恢复或回补也不使旧事件重新出现。仅一直未恢复上传的事件继续跨日跟进，不设3天或3期上限。恢复后的新一轮缺失单独记录，不重新打开此前已恢复的历史事件。状态库与快照仍保留证据。
- 分别说明恢复和回补，恢复优先。截止小时缺失项目的数据重新返回才记为恢复，数据恢复即结束跟进；其他项目有值不能证明缺失项目恢复。回补状态仅作备注展示。此结论不证明设备恢复时间或故障原因。
- 国控：在已配置的省控监测源、空气质量发布源中，任一来源完整补齐该事件缺失时段的六参数即可注明“数据已回补”。当前仅有一个经验证的站点级来源时保留单源限制；城市发布库的城市聚合数据不能用来断言单站恢复或回补。
- 省控：只依据省控小时来源，区分已回补、待回补、无法回补。无法回补必须有覆盖事件时段的核实记录，包含原因、依据、确认人和时间；不能按缺失天数推测。
- 使用原始值和历史观察快照；首次观察缺失与后续补齐必须可追溯。不要把未知质量标记、占位符或接口转成的0当作已核实事实。
- 用户反馈闭环：用户在对话中说明某缺失事件的缺失原因或是否无法回补时，调用 `station_operation_daily(action="record_feedback", station=<站点编码或名称>, reason=<缺失原因>, unrecoverable=<是否无法回补>, start=<缺失开始时间,可选>, end=<缺失结束时间,可选>, feedback_by=<反馈人,可选>)`。反馈当期日报在“排查结果”列只显示已核实原因；反馈人、时间和关闭跟进记录保存在核查数据中，之后该事件不再列入日报；`unrecoverable=true` 时采集端同步停止该区间的重复补查。`unrecoverable` 必须按用户明确表述传入，不得代用户推断；反馈记录失败或站点不匹配时如实告知并重新确认。
- 查询失败不认定站点离线；无记录且在运状态未确认的候选站点单列待核实，不计入已确认离线。初次采集前的已回补事件可能无法重建，保留覆盖限制。

## 执行与交付

1. 定时执行固定工作流 `station_operation_daily_report`；对话中补跑可调用 `station_operation_daily(action="report")`。仅在明确补跑日期时传入 `date`，不另行抓取平台网页或用语言模型重算数据。
2. 使用本轮工具返回的 Word 资源、`report_input_path` 和格式校验结果，保持来源、事件数量、恢复与回补结论一致。
3. `report_ready=false` 时只交付标为待核实的样稿并说明取数异常，不宣称全体站点正常。工具或格式校验失败时报告错误，不编造替代日报。
4. 工具必须在返回值顶层 `resources` 声明 Word 主资源及关联的 PDF 预览资源，由执行器写入会话资源库；仅返回路径或 `data.resources` 不算注册。直接交付已注册的 Word 资源，简述异常与历史跟进事项。此任务不包含重启、启用任务或对外发送；这些操作按当前用户授权执行。
