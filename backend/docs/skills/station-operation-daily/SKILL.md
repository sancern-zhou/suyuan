# 站点运行监控日报

## 概述

定时任务 Agent 调用 `station_operation_daily` 完成取数、计算、模板填充和交付。脚本及持久化记录提供事实，原始 Word 提供版式；Agent 不重新计算事件或重排 Word。

## 模板与格式

- 用户提供的版式基准：`backend/backend_data_registry/uploads/9e0901af-e0ea-4041-a807-fd8498dc330b.docx`。部署时保存模板副本，实际生成使用运行配置的 `template_path`；`template_sha256` 标识批准的模板版本。
- 直接打开模板并替换数据，不从空白文档重建。保留原有红色两行标题、字体字号、段落格式、红色分隔线、正文纵向和附件横向页面、页边距、页码、表格边框与列宽。
- 正文依次为标题、日期、单位和期号、统计说明、国控站点、省控站点、编制和校核、主送和抄送。名称和数量来自本轮数据，不复制示例中的旧站点、旧日期、旧期号或人员。
- 两张附表标题分别为“国控站点离线记录表”“省控站点离线记录表”。九列依次为序号、城市、站点、离线时间、是否已恢复、影响数据时长（小时）、是否影响数据有效性、排查结果、备注。没有事件时数据行填 `/`。
- 期号、编制、校核使用配置值，未提供则标为待确认。模板中的样例人员和事实不代表本次核实结果。
- 数据来源、候选名单及取数限制放在另起页的“数据核查说明”中，保留报告正文与两张附表的结构。
- 工具在保存后比较模板和输出的页面分节、标题样式、分隔线、页眉页脚、表头与表格属性，并输出格式校验记录。模板版本或结构校验失败时报告失败，不交付为成功日报。模板升级或版式代码调整后须进行 Word/PDF 渲染比对，检查换页、溢出和字体替代；日常内容不同不要求页数或文字位置完全相同。

## 时间和判定要求

- 每天北京时间（Asia/Shanghai）10:30开始，统计昨日10:00至今日10:00。接口按小时结束标签采用 `(昨日10:00, 今日10:00]`，共24小时，去掉重复端点。
- 全部已观察的数据缺失均纳入日报，包含1小时、2—4小时的短时缺失和单项污染物缺失；模板中的“超4小时”仅为示例表述，不作为筛选门槛。相邻缺失小时可合并为事件，非连续缺失分段记录。前天及更早仍未恢复或仍待回补的事件继续列出，说明截止时恢复情况和历史回补情况；已恢复但待回补不能结束跟进。
- 分别说明恢复和回补。截止小时缺失项目的数据重新返回才记为恢复；其他项目有值不能证明缺失项目恢复。此结论不证明设备恢复时间或故障原因。
- 国控：在已配置的省控监测源、空气质量发布源中，任一来源完整补齐该事件缺失时段的六参数即可注明“数据已回补”。当前仅有一个经验证的站点级来源时保留单源限制；城市发布库的城市聚合数据不能用来断言单站恢复或回补。
- 省控：只依据省控小时来源，区分已回补、待回补、无法回补。无法回补必须有覆盖事件时段的核实记录，包含原因、依据、确认人和时间；不能按缺失天数推测。
- 使用原始值和历史观察快照；首次观察缺失与后续补齐必须可追溯。不要把未知质量标记、占位符或接口转成的0当作已核实事实。
- 查询失败不认定站点离线；无记录且在运状态未确认的候选站点单列待核实，不计入已确认离线。初次采集前的已回补事件可能无法重建，保留覆盖限制。

## 执行与交付

1. 调用 `station_operation_daily(action="report")`。仅在明确补跑日期时传入 `date`，不另行抓取平台网页或用语言模型重算数据。
2. 使用本轮工具返回的 Word 资源、`report_input_path` 和格式校验结果，保持来源、事件数量、恢复与回补结论一致。
3. `report_ready=false` 时只交付标为待核实的样稿并说明取数异常，不宣称全体站点正常。工具或格式校验失败时报告错误，不编造替代日报。
4. 工具必须在返回值顶层 `resources` 声明 Word 主资源及关联的 PDF 预览资源，由执行器写入会话资源库；仅返回路径或 `data.resources` 不算注册。直接交付已注册的 Word 资源，简述异常与历史跟进事项。此任务不包含重启、启用任务或对外发送；这些操作按当前用户授权执行。
