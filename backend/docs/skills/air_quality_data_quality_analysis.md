# 空气质量数据质量自动分析技能

适用场景：定时任务 `air_quality_data_quality_monitor` 已生成 `quality_package.json`，需要 Agent 判断疑似异常数据是否更像仪器/质控问题，还是可解释的真实环境污染变化。

## 输入

必须先读取 `quality_package.json`，再按其中 `data_files` 读取：

- `issues.json`：算法命中的疑似问题列表。
- `station_hour_monitoring.json`：原始站点小时数据和来源摘要。
- `station_summary.json`：各站点污染物统计摘要。

## 分析步骤

1. 先列出可观察事实：
   - 城市、时间范围、站点数量、总记录数。
   - 最高严重度规则、涉及站点、涉及污染物。
   - 是否为持续偏高、持续偏低、日均/日最大偏差、趋势不一致或污染物规律异常。

2. 逐条验证规则命中：
   - 核查站点值、同城其他站点均值、偏差比例和阈值。
   - 核查持续异常的开始、结束、持续小时数。
   - 核查趋势相关性是否有足够点数支撑。
   - 对低点数、缺测、同城站点太少的结论降级。

3. 主动寻找真实污染反证：
   - 若多个邻近站点同步变化，不应简单判为无效。
   - PM2.5 与 PM10 同步、PM2.5 与 CO 同步，可能是真实颗粒物或燃烧过程。
   - NO2 升高同时 O3 下降，可能符合滴定消耗规律。
   - O3 早晚低、中午高的日变化形态可支持数据有效。
   - 特殊气象或局地污染可能造成短时站点差异；短时偶发不应直接剔除。

4. 主动寻找仪器/质控证据：
   - 启停机、停电恢复、设备调试、更换设备恢复期。
   - 通零气、标气、标准膜检查、校准期间。
   - 质控检查不合格且维护前的数据。
   - 突降并持续低于同城站点，维护后恢复正常。
   - 施工、站房温湿度或采样条件不满足要求。

### 已确认停机的"十三五"站点处理

以下两个"十三五"站点已确认停机，巡检时直接标记为无效，不再重复报警：

| 城市 | 站点名称 | 状态 | 确认时间 |
|------|---------|------|---------|
| 深圳 | 西乡（十三五） | 已停机 | 2026-05-12 |
| 佛山 | 容桂街道办（十三五） | 已停机 | 2026-05-12 |

处理规则：
- 上述站点所有污染物持续为0时，直接判定为 `invalid_review`，结论中注明"已确认停机"。
- 在巡检报告中不再作为"新发现的疑似异常"重复推送，仅作为已知停机状态备注。
- 如后续该站点数据恢复正常（非零值），应重新纳入正常巡检流程。

5. 给出处置建议：
   - `invalid_review`：建议进入无效审核。
   - `needs_manual_qc_check`：需要质控/运维记录确认。
   - `likely_valid_pollution`：更像真实污染过程，暂不剔除。
   - `insufficient_evidence`：证据不足，只保留观察。

## 输出

在 `quality_package.json` 同目录写入 `data_quality_analysis.md`，结构如下：

```markdown

## 结论
- 建议动作：

- 主要理由：

## 规则核查矩阵

## 疑似无效时段
| 站点 | 污染物 | 开始 | 结束 | 原因 | 建议 |

## 真实污染反证

## 需要补充的证据

## 审核建议
```

如果没有足够证据，不要把异常高值直接判为无效；应明确写为“需人工核查质控/运维记录”。
