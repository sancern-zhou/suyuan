# 城市污染过程自动分析技能

## 概述
用于 `city_pollution_event_monitor` 工具生成的城市污染过程证据包。助手必须基于已落盘数据自主提出假设、验证证据、检查反证，并输出可追踪的污染过程分析结论。

## 触发条件

当用户或定时任务提到以下内容时使用本技能：

- 城市污染过程识别告警
- `evidence_pack.json`
- `analysis_request.md`
- 自动分析污染过程
- 数据质量检查后的污染过程解释
- 定时巡检发现异常后需要假设验证

## 输入

优先读取以下文件：

- `evidence_pack.json`
- `event.json`
- `city_hour_monitoring.json`
- `data_quality_report.json`
- `station_hour_monitoring.json`
- `weather_hourly.json`
- `pm25_components.json`，如存在
- `vocs_components.json`，如存在

如果只拿到事件目录，先读取该目录下的 `evidence_pack.json`。

## 总原则

算法负责发现事实，助手负责解释事实。不要重新发明异常识别算法，也不要跳过证据直接归因。

必须区分：

- 观测事实：数据中直接可见的时间、浓度、站点、气象、组分变化
- 推理判断：基于事实推导的可能机制
- 不确定性：缺失数据、反证不足、证据冲突
- 后续动作：建议继续查询或现场核查的对象

## 工作流程

### 1. 读取证据包

先读取 `evidence_pack.json`，建立证据清单：

| 证据类型 | 文件 | 是否可用 | 主要字段 | 用途 |
|---|---|---|---|---|
| 事件摘要 | event.json |  |  |  |
| 城市小时数据 | city_hour_monitoring.json |  |  |  |
| 数据质量 | data_quality_report.json |  |  |  |
| 站点小时数据 | station_hour_monitoring.json |  |  |  |
| 气象数据 | weather_hourly.json |  |  |  |
| PM2.5组分 | pm25_components.json |  |  |  |
| VOCs组分 | vocs_components.json |  |  |  |

如果 `data_quality.status` 为 `poor`，必须先说明哪些结论会降置信度。

### 2. 复述事件事实

用简短结构复述算法发现，不要泛泛描述：

- 城市
- 事件时间段
- 主污染物
- 峰值和峰值时间
- 上升速度或持续时长
- 是否多污染物同步变化
- 站点是否同步、是否有领先站点
- 风速、风向、湿度、降水等关键气象

### 3. 建立假设

至少提出 2 个、最多 4 个可检验假设。常见假设包括：

- 本地短时排放冲击
- 低风速静稳累积
- 区域传输或上风向输入
- 扬尘或粗颗粒影响
- 二次生成增强
- 臭氧光化学生成或区域输送
- 数据异常或设备问题

每个假设必须写成下面结构：

```text
假设：
如果为真，应该看到：
当前支持证据：
当前反证/不足：
还需补充：
```

### 4. 验证和反证

按假设逐项核查，不要只找支持证据。

必须检查：

- 时间链路：污染物是否先升、同步升、滞后升
- 空间链路：站点之间是否同步，是否有明显高值站或领先站
- 气象链路：风速、风向、湿度、降水、边界层条件是否支持机制
- 污染物链路：PM2.5/NO2、PM10/PM2.5、O3/NO2、CO/NO2 等是否符合假设
- 组分链路：离子、OC/EC、VOCs 类别是否支持二次生成、燃烧源、扬尘或臭氧生成潜势
- 数据质量：缺测、突刺、长时间恒定、PM2.5 大于 PM10 等是否影响结论

证据强度标记只能用：

- `supports`
- `weakly_supports`
- `contradicts`
- `insufficient`

### 5. 输出结论

最终输出必须包含：

```markdown
## 城市污染过程自动分析

### 核心判断

### 观测事实

### 假设验证矩阵
| 假设 | 支持证据 | 反证/不足 | 验证结果 | 置信度 |
|---|---|---|---|---|

### 证据链说明

### 数据质量影响

### 结论

### 建议动作
```

置信度只能使用 `高`、`中`、`低`。

`高` 只能用于至少两类独立证据一致的结论，例如城市小时变化 + 站点空间差异 + 气象链路同时支持。

### 6. 写回文件

如果有事件目录写权限，必须在 `evidence_pack.json` 同目录写入：

- `reasoning_analysis.md`

内容使用上面的输出结构。

## 禁止事项

- 不要仅凭“浓度升高”直接判定来源。
- 不要把相关性写成确定因果。
- 不要忽略数据质量问题。
- 不要在没有组分、风向、站点空间证据时声称明确源解析。
- 不要把算法事件类型原样当作最终结论，必须重新验证。

## 快速调用范式

当定时任务触发时，可按如下步骤执行：

1. 调用 `city_pollution_event_monitor(city="广州", hours=24)`。
2. 读取返回的 `event_artifacts[].evidence_pack`。
3. 按本技能完成假设验证。
4. 将结果写入同目录 `reasoning_analysis.md`。
5. 回复用户时只摘要核心发现、置信度和下一步建议。
