# 设计规范（design-rules）

检查阈值与 validate_office 联动：按本规范设计 → QA 自然通过。

## 1. 工作簿组织

- 一主题一 sheet，表名即主题（中文 ≤31 字符，禁 `\ / * ? : [ ]`）。
- 首个 sheet 放汇总/结论表（"汇总"），明细随后（"站点明细""逐日数据"…）。
- 无内容的空表删除（QA 判 `xlsx_empty_sheet`）；模板页放最后一个 sheet 并命名"说明"。

## 2. 表头规范（QA 硬检查）

- 首行 = 表头：中文列名，单位写进列名（"PM2.5 浓度 (μg/m³)"）。
- 表头样式：加粗 + 底色 #F8FAFC + 四边细边框；行高 20。
- `freeze_panes = "A2"` 冻结首行（>15 行数据的表未冻结会被 QA 提示）。
- 首行开启自动筛选（`auto_filter.ref`）。

## 3. 列宽（QA 硬检查）

- 显式设置每列宽度：`max(最长内容显示宽, 表头宽) + 2`；中文按 2 字符宽估算
  （"站点名称"4 字 → 8 宽）。日期列 12，数值列按含单位表头。
- 内容显示宽 >20 且列宽不足会被判 `xlsx_column_overflow`。
- 禁止留默认宽度（8.43）装长文本。

## 4. 数字格式

| 数据 | 格式 | number_format |
|---|---|---|
| 日期 | yyyy-mm-dd | `YYYY-MM-DD` |
| 百分比 | 保留 1 位 | `0.0%` |
| 浓度 μg/m³ | 保留 1 位 | `0.0` |
| 大数 | 千分位 | `#,##0` |
| 编号/站点代码 | 文本（防前导零丢失） | `@` |

- 禁止文本型数字（左上角绿三角）；日期用真日期值，不写字符串。

## 5. 公式与数据（data_manual 继承）

- 可计算的值写公式（汇总行 SUM/AVERAGE、跨表引用），不硬编码。
- 空值留空（None），不写 "0" 或 "-" 冒充缺失（QA 的错误值扫描与读回核验会暴露错位）。
- 修改现有文件用 openpyxl 直接改（保样式/公式/合并），不要 pandas.to_excel 覆盖。

## 6. 样式克制

- 主题色体系与 PPT/Word 一致：表头底色 #F8FAFC、边框 #E2E8F0、
  强调 #0F766E（语义色：优 #22C55E / 良 #EAB308 / 轻度 #F97316 / 中度 #EF4444）。
- 条件格式可用于达标着色（Excel 端有效）；注意前端 SheetJS 预览不保真
  样式与条件格式——关键信息不能只靠颜色传达，必须另设"等级"文字列。
- 不加装饰图表；确需图表放独立 sheet 且不作为主要传达渠道。

## 7. 兼容性与公式纪律（政务接收方多为 WPS/旧版 Office）

- 🚫 **禁用动态数组函数**：FILTER/UNIQUE/XLOOKUP/SORT/SORTBY/XMATCH/SEQUENCE/LET/LAMBDA/RANDARRAY
  在 WPS 与旧版 Excel 全部不可用——查找用 INDEX+MATCH/VLOOKUP，多条件聚合用 SUMPRODUCT/COUNTIFS。
- **除法一律包错**：`IFERROR(a/b, "—")` 或 `IF(denom=0, "—", a/b)`；共享分母用绝对引用（`$C$42`）。
  交付文件公式错误值必须为零。
- 文本内容以 `=` 开头必须加 `'` 前缀转义，否则被解析为公式。
- **改旧文件时既有模式优先**：现有数据用 `0` 表示空就继续用 `0`，不擅自换 `—`；用户要求与既有数据
  模式冲突时按既有模式走并向用户说明差异。

## 8. 公式值与机器核验的取舍

- 原则上派生值写公式（表格保持活性，data_manual 继承）；**例外**：该文件将被程序读回核验时
  （openpyxl `data_only=True` 对新写公式返回 None，读不到值），汇总行可写计算值 + 公式写在单元格
  批注里备查。validate_office 的错误值扫描依赖缓存值——新生成文件经其 LibreOffice 重算通道
  填充缓存后才能扫出 #REF! 类错误。
