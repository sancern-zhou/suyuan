# 分析报告通用工作流

## 概述
面向生态环境管理用户的分析报告通用方法：明确任务边界、拆解问题结构、数据获取、校验与清洗、分析、提炼结论、成稿与可视化、质检、交付九步全流程，配套工作原则（不编数字、可回溯、区分事实与判断、量化优先、先结论后论证）。正式报告走全程，快问快答可裁剪为"拆解+分析"；流程可并行迭代，不是严格瀑布。

## 适用范围

- 适用于报告模式的正式报告生成、专家模式的专业分析研判，以及其他模式的分析成稿类任务。
- **按需裁剪**：正式报告（Word/PPT/HTML/Excel 等交付物）走全程；会话内快问快答只需第 2 步（拆解）+ 第 5 步（分析），直接给结论，不生成报告文件。
- **并行迭代**：步骤不是严格瀑布。数据获取可以并发；分析中发现口径、范围或数据问题，回到第 1 步重新定义后再继续，不将错就错。
- 在报告模式中，本技能用于补足任务边界、校验清洗、分析建模、结论提炼、质检和交付约束；报告模式内部完成任务拆解并直接执行，不要求用户确认查询计划或选择计划模板。

## 九步工作流

1. **明确任务边界（Define）**：确认报告给谁看（结合用户角色确定详略与侧重）、要回答什么问题、支撑什么决策、统计口径与时间范围、交付格式（Word/PPT/HTML/Excel）、截止时间。不确定的地方先给出假设并明确标注，不得把假设写成事实。
2. **拆解问题结构（Frame）**：把大问题拆成可验证的子问题，搭出报告骨架（金字塔结构：结论先行，论点支撑，数据佐证）；确定所需指标体系与计算口径。
3. **数据获取（Collect）**：本地文件优先（Excel/CSV/已读取的报告、附件），其次平台数据查询工具和数据库 SQL；具备联网检索工具时再获取公开来源补证。原始数据落地保存（`save_data` 或文件），不做二手转述；数据不可得时明确说明数据边界，不猜测补齐。
4. **校验与清洗（Validate）**：检查缺失值、异常值、口径一致性、时间对齐、单位统一；关键数字交叉验证（至少两个来源或两种算法）。这一步决定报告可信度，不得跳过。
5. **分析（Analyze）**：描述性统计 → 对比/趋势/结构/归因 → 必要时建模或量化估算（敏感性分析、区间估计）。数值一律用 `execute_python` 或查询工具实际计算，说明输入范围和单位，不靠感觉给数。
6. **提炼结论（Synthesize）**：从数据到洞察到建议。每个结论必须有数据支撑并标注出处；内部严格区分"事实 / 推断 / 建议"三种强度，防止把推断写成事实。
7. **成稿与可视化（Compose）**：先结构后文字；图表服务于论点（不堆图）；文字量化，避免"明显""一定程度"等模糊词；排版按用途选模板（公文/研报/商务报告）。
8. **质检（Review）**：按下方自检清单逐项检查，不通过必须改写后再交付。
9. **交付（Deliver）**：输出到指定格式与路径（报告模式用 `create_report_package` 收口）；附数据来源与口径说明、关键假设、局限性；需要时给出可复用的脚本或表格。

## 工作原则

- **不编数字**：所有数字必须来自工具结果、已读取的数据文件、报告或用户提供内容；来源没有的不推断、不编写。
- **可回溯**：数据和结论必须能对应到具体来源；结论标注出处。
- **区分事实与判断**：内部严格区分事实/推断/建议；面向用户输出时按部署规范转述为业务语言，不暴露内部接口、字段名和技术标识。
- **量化优先**：用具体数值、倍数、百分比和对照基准说话。
- **先结论后论证**：金字塔结构，每章首段给结论，摘要一页定全貌。

## 质检清单（Review 自检）

- [ ] 数字前后一致（摘要=正文=表格=图表），单位统一、时间对齐。
- [ ] 每个图表与正文论点对应，图表数值与正文引用一致。
- [ ] 结论能回答最初定义的问题；未回答的部分明确说明。
- [ ] 假设均已标注，无未标注的假设；无把推断表述成事实的句子。
- [ ] 无遗留 TODO、无占位内容；交付附带数据来源与口径说明。
