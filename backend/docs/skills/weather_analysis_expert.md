# 天气形势与污染扩散分析

## 概述
按参考 DOCX 的章节、表头和逐日卡片生成许昌未来7天详细分析及第8—15天展望，以表格和图片为主、短句为辅。Agent 自主研判天气过程和风险，最终展示结构必须遵守本技能。

## 职责与参考样本

- 任务 Prompt 负责查询、分析、绘图、报告导出和投递的流程编排；本技能负责数据口径、分析方法、报告结构、字段、样式和内容自查。
- 参考样本：`backend/backend_data_registry/uploads/893bab5b-c2be-4edf-9e79-9fab2d20c289.docx`。以下标题和表头已从该文件提取，每次执行直接遵循本技能，不必反复读取样本。
- 固定章节标题、顺序、表头文字、列顺序和卡片字段；只替换日期、真实数据、图表和分析内容。不得按历史报告或任务记忆改写本结构。
- 表格、图片优先；表格单元格用短语，必要时单元格内换行。不得用长段文字代替表格，不另加“综合结论”“不利扩散时段汇总”“数据来源”等一级章节。
- 样本中的数值、日期、阶段结论和错误统计口径不得照搬；源数据缺失时保留字段，写“未提供”或“证据不足”。

## 数据口径与分析方法

- 以北京时间执行日 D 为第1天，前7天为 D 至 D+6，第8—15天为 D+7 至 D+14；不是当月8日至15日。两个窗口连续且不重叠。
- 前7天气象仅查询 `dbo.XuchangNmcHourlyWeatherForecast` 中许昌 `city_name=N'许昌市'` 的最新 `publish_time` 批次，`forecast_time >= D` 且 `< D+7`。读取 `forecast_time`、`weather_text`、`temperature`、`humidity`、`pressure`、`wind_direction`、`wind_direction_degrees`、`wind_speed`、`precipitation_probability`、`precipitation_text`、`publish_time`、`fetched_at`。不得以其他气象源静默补齐。
- 空气质量预报另外查询 `dbo.WeatherForecast7Day`，按 `cityname=N'许昌市'` 筛选，`TimePoint >= D` 且 `< D+7`。先核对表结构，读取 `TimePoint`、`MinAqi`、`MaxAqi`、`MaxPollution`、`UpdateDate`、`UpdateTime`；按该城市最新发布批次获取并核对日期，不混用旧批次来填满7天。该源仅填空气质量字段，不替代 NMC 气象数据。
- `AQI范围` 使用真实 `MinAqi~MaxAqi`；`首要污染物` 使用 `MaxPollution`。`等级` 使用预报源等级或平台已有 AQI 分级规则，跨等级范围须同时列出，不能拿扩散等级代替。无可靠 AQI 时等级也写“未提供”。
- 当前 `WeatherForecast7Day` 表未声明 O3 浓度字段，不得虚构查询列。`O3(ug/m3)` 保留并写“未提供”；仅当实际查询结果包含有明确统计口径的 O3 浓度预报时才填数值并在表下注明口径。不得由 AQI 或气温反推 O3 浓度，不得将 O3 日最大8小时均值写成日均值。PM2.5/O3 的定性气象风险与数值预报须区分。
- 第8—15天查询 `dbo.XuchangWeatherComDailyForecast`，`city_code='101180401'`，`forecast_date >= D+7` 且 `< D+15`；读取 `forecast_date`、`weather_text`、`temp_max`、`temp_min`、`wind_direction_day`、`wind_direction_night`、`wind_force`、`fetched_at`。按城市和日期更新的表需逐日核查时效，不把旧记录当作当前预报；不使用已移除的 `source_update_time`。
- 对外表头不附加源名称。来源、批次、覆盖范围在内部核查；影响结论的缺测、冲突或时效问题只在相邻表下注明一句，不另设数据来源章节。
- NMC 日温度范围是3小时采样点范围，不是官方最高/最低温；在2.2表下注明一次。降水概率不等于降水量，风力等级不等于精确 m/s。
- 分时统计统一使用左闭右开区间；上午为当日08:00—14:00，午后14:00—20:00，夜间当日20:00—次日08:00；“最高湿”取同一夜间窗口的可用预报最大相对湿度及完整日期时间。超出 NMC 七日覆盖或缺测时写“部分覆盖/证据不足”，不延长查询窗口、不插值。
- 2.1每个时段先对实际风速采样点分级，单元格按时间显示等级变化（如“一般→差”）；若全段同级则只写该级，底色取该时段最差的已知等级。缺测单元格用中性底色并注明部分覆盖，不将单点结论写成全时段结论。
- 扩散分级统一为：好（>=5 m/s）、一般（2—<5 m/s）、较差（1.5—<2 m/s）、差（<1.5 m/s）。不得增加“极好/极差”等额外等级；综合风险可结合实际温湿度、风场及降水条件，注明触发因素，不确认具体污染源。
- 风险时段按实际时次描述，跨日写清完整起止日期；离散3小时点不能无依据外推成连续风险时长。没有边界层、辐射等数据时，不把这些因素的推断写成确定数值或事实。

## 固定报告结构（标题必须逐字一致）

报告抬头依次为“许昌市未来7天-15天”“污染扩散条件与空气质量分析报告”“(YYYY年M月D日)”。各章日期由 D 动态生成，不复制样本日期。

### 一、未来7天空气质量预报总览

只输出一句总体概括（建议不超过80字）和一张7行数据表；必要表注不超过一句。不输出多段背景说明。

表头逐字且按顺序为：

| 日期 | AQI范围 | 等级 | 首要污染物 | O3(ug/m3) | 扩散条件 | 气象特点 |
| --- | --- | --- | --- | --- | --- | --- |

日期格式为“M/D 周X”，按 D 至 D+6 排列；气象特点使用短语。空气质量缺测时首句仅概括有证据的天气和扩散趋势，不宣称空气质量优良。

### 二、未来7天逐日污染扩散条件分析

本章依次且仅包含下列四个小节：

#### 2.1逐日各时段扩散条件汇总

一张4行×7日的扩散矩阵。首列表头固定“时段”，后7列表头按 D 至 D+6 显示“M/D”，不加其他列。行标签与顺序固定：

| 时段 | D（M/D） | D+1（M/D） | D+2（M/D） | D+3（M/D） | D+4（M/D） | D+5（M/D） | D+6（M/D） |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 02~08时 | | | | | | | |
| 08~14时 | | | | | | | |
| 14~20时 | | | | | | | |
| 20~02时 | | | | | | | |

上述 D 表示日期占位，正式表头只显示实际日期。“20~02时”为该列日期20:00至次日02:00。表后只保留风速分级图例及必要的跨日/缺测注释。

#### 2.2逐日气象要素详情

一张7行数据表，表头逐字且按顺序为：

| 日期 | 天气/温度 | 上午风 | 午后风 | 夜间风 | 最高湿 | 扩散条件 | PM2.5 | O3 | 不利时段 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

- 日期用“M/D 周X”；天气/温度写天气短语与采样点温度范围。
- 上午风、午后风、夜间风写对应窗口的风向与风速范围；最高湿写“数值%（M/D HH时）”。扩散条件写日内阶段变化，与2.1保持一致。
- PM2.5、O3列主要用短语写有依据的气象风险，如“夜间弱风，有累积风险”，不写无浓度预报支持的“本周最高”“全天低值”。不利时段写具体时间和触发因子。
- 表下注明上午、午后、夜间、最高湿统计窗口及温度采样口径，可分两行；不再另用一大段文字重复表格。

#### 2.3气象小时变化趋势分析

本节必须插入一张覆盖第1—7天的连续小时气象分析图。一次调用 `create_report_chart(chart_type="weather_timeseries", options={"expected_interval_hours": 3, "line_width": 1.0})`，将 D 至 D+6 的全部有效记录按时间排序放入 `data.records`，字段为 `forecast_time`、`wind_speed`、`wind_direction_degrees`、`temperature`、`precipitation_probability`、`humidity`。有实际风险时段时在同一个 options 中加入 `risk_periods`。

图中五要素共用一条连续7日时间轴，含日期/小时刻度、风向箭头、风速和温湿度/降水概率曲线，沿用统一图例及风险色。风向箭头统一为细长等长箭头，中心固定在图上方同一水平线上，仅旋转表达风向，不随风速或纵轴数值改变高度、长度。调用时给出包含本次 execution_id 的唯一 `chart_id`，避免覆盖其他报告图片。不得拆成7张日图、拼接7张图片或把不同日期叠加在同一日横轴上；历史记忆中“工具只支持单日、须逐日调用”的要求已失效。

识别到有数据依据的风险时段时，必须在调用 `create_report_chart` 的同一个 `options` 中传入 `risk_periods`，由工具直接绘制背景色块及风险名称，不仅在正文中说明，也不另行手工编辑图片。工具已支持该参数（`areas` 为同类区域标注参数）。每项包含：

- `start`、`end`：实际风险起止时间，使用完整北京时间 `YYYY-MM-DD HH:MM:SS`；跨日仍写完整日期，按时间排序，限制在真实预报覆盖内，不跨越缺测区间外推。
- `name`：简短风险名称与主导因子，例如“弱风累积风险”“高湿关注”；与2.1、2.2、2.4的判断一致，不把气象风险写成污染实测等级。
- `level`：`high`、`medium` 或 `low`；由实际风险研判确定，不为填满图表虚构风险。
- `color`：高风险 `#FFC7CE`、中风险 `#FCE4D6`、低风险 `#FFEB9C`；`alpha` 统一为 `0.2`，用浅色背景保留曲线可读性。

相邻且同类同等级、有连续证据支撑的时段可以合并，避免标注重叠。没有可靠风险窗口时传空列表并保持图表正常输出；只有孤立低值点时注明该时次，不臆造持续时长。图注简要解释已使用的风险颜色。

使用工具返回的正式图片路径，将这唯一一张气象分析图放在本节标题之后，附一句短图注（建议不超过40字）。源数据为3小时间隔，图注注明“3小时预报时次”，不插值伪造逐小时数据；缺测处断线，未覆盖日期作简短注释。全部数据缺失时明确注明无法生成图，不伪造图片或声称成功。Agent 可按实际天气过程划分阶段，每阶段仅用一个短条目写“阶段日期：变化→扩散影响”（建议不超过60字），不写长段、不另建章节。

#### 2.4逐日气象扩散条件分析

按模板的7行单列表格展示7张逐日信息卡，不另造横向表头。每张卡片固定按以下顺序排列，标签不可缺少：

- 卡片首行：M月D日（周X） 天气 | 温度范围 | 风向及风力/风速。
- 扩散条件：等级及日内变化；日均风速：实际计算值 m/s。
- 形势分析：一句话（建议不超过40字）。
- PM2.5：一句气象风险提示。
- O₃：一句气象风险提示。
- 风险评级：风险类型及高/中/低，或“暂未识别明显气象风险/证据不足”。

日均风速必须计算并核对全天覆盖，不能像样本那样把某时刻峰值称为日均风速；仅部分时次可用时保留“日均风速”标签并写“证据不足（已覆盖时次均值…）”。样本的“全天优良”等空气质量表述仅在真实空气质量预报支持时使用。卡片每个字段一行，避免小作文和重复抄写2.2整行数值。

### 三、逐小时关键时点数据

一张关键时点表，表头逐字且按顺序为：

| 时间 | 天气 | 温度 | 风向 | 风速 | 湿度 | 气压 | 扩散提示 |
| --- | --- | --- | --- | --- | --- | --- | --- |

按时间先后列每日关键转折、风速低值、湿度高值等真实时次，通常每日1—3个；时间用“M/D HH:MM”。NMC只有3小时间隔预报，标题沿用模板，但只列源端真实时次，不插值成逐小时数据。气压列不得改成“气压/降水概率”；缺气压填“未提供”。表前最多一句说明，表后只放图例及单位注释，不重复解释全部时点。

### 四、未来8-15天的气象扩散条件分析

一张8行日预报表，表头逐字且按顺序为：

| 日期 | 天气 | 最高温 | 最低温 | 主导风向 | 风力 | 午后风速 | 扩散条件与风险 |
| --- | --- | --- | --- | --- | --- | --- | --- |

- 日期按 D+7 至 D+14 排列，格式“M/D”；源端未发布的日期仍保留。
- 主导风向按源端日风向或转向过程展示，不强行拆成白天/夜间。最高温、最低温填日预报值并带℃；风力保留源端“级”。
- “午后风速”必须保留；当前日预报未提供午后定量风速时填“未提供”，不能由“<3级”等推算 m/s，更不能挪用前7天 NMC 风速。
- 扩散条件与风险用一个短语概括日尺度趋势及原因；不能依据风力等级套用小时风速分级，也不推断小时湿度、边界层或风险持续时长。
- 表后最多一句中期趋势提示，避免1—2段长文字。必要时用一句表注说明“午后风速未提供，日尺度展望需滚动更新”。全段缺测也保留本章、表头和8个日期行。

## 表格、图例与颜色规范

报告中的表格必须使用可渲染的 HTML 表格或带 HTML 属性的 Markdown 表格，不得使用由空格拼出的纯文本表格。所有主要表格统一遵循以下样式：

- 表头背景色：`#1F4E79`；表头文字：白色；文字水平居中；
- 表格边框：`1px solid #D9E2F3`；单元格适当留白，保证 DOCX 和 HTML 中均可读；
- 扩散条件单元格按等级着色：
  - 好：背景 `#C6EFCE`，文字 `#375623`，class 使用 `diff-good`；
  - 一般：背景 `#FFEB9C`，文字 `#9C6500`，class 使用 `diff-normal`；
  - 较差：背景 `#FCE4D6`，文字 `#974706`，class 使用 `diff-poor`；
  - 差：背景 `#FFC7CE`，文字 `#9C0006`，class 使用 `diff-bad`；
- 风险等级单元格统一使用：高风险 `#FFC7CE`、中风险 `#FCE4D6`、低风险 `#FFEB9C`，class 分别为 `risk-high`、`risk-medium`、`risk-low`；
- 数值风险提示可使用：高值 `value-high`（红色）、关注 `value-watch`（黄色）、正常 `value-normal`（绿色）；只有存在明确业务依据时才着色，不得为了美观随意标红。

- 每张 HTML 表格置于 `<div class="weekly-weather-report">` 内，使上述表头与边框选择器实际生效；不要用一个 HTML 容器包住全部 Markdown 正文而使标题失去结构。
- 所有缺测或无法判定的单元格使用中性底色，不标绿。AQI等级、扩散等级、综合气象风险分别表达，不能共用一套判定规则。
- 保留模板表头原文：例如 `O3(ug/m3)`、`最高温`、`最低温`、`风速`、`气压`；单位在单元格或表下注明，不通过增改列名解决。温度用℃、风速用m/s、湿度用%、气压用hPa。
- 不照搬样本第三章与四级分级冲突的“红色=极差”图例，所有章节统一使用本技能四级图例及配色。

## 成文与交付自查

1. 逐项核对四个一级标题和2.1—2.4小节的文字、标点及顺序，尤其第四章使用模板原文的 `8-15`；不得另加结论章。
2. 核对一、2.2、三、四的表头及顺序与上文逐字一致；2.1为“时段”加7个实际日期，四行时段固定；2.4为7行单列卡片且标签完整。
3. 第一章和2.2各7行，第四章8行；缺测也保留日期与列，不出现未替换的 D 占位符。2.3内只放一张包含第1—7天数据的气象分析图，核对工具返回的实际覆盖时间及有效记录数与输入一致；不拆成7张图、不单设时序分析章。
