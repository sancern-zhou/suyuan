# Draw.io Layered System Pattern

适用于平台能力图、产品架构、能力地图、治理体系、分层系统图和支撑体系图。

## 布局

1. 使用横向层级带或嵌套容器表达上下层关系。
2. 每层内部节点按业务域、能力域或技术域分组。
3. 支撑能力、治理能力、安全能力、观测能力放在侧边栏或底座区。
4. 层与层之间只画关键依赖，不画所有依赖。

## Shape 语义

1. 容器/泳道：层级、领域、平台边界。
2. 圆角矩形：能力、产品模块、服务入口。
3. 矩形：底层组件、工具、作业。
4. 注释框：建设目标、原则、约束。

## 连接

1. 分层系统图可少画连接线，优先用空间位置表达归属和支撑关系。
2. 如果必须画连接，只画跨层关键依赖。
3. 不要在同一层内部画复杂网状连接。

## 质量门槛

1. 每层标题必须具体，例如“数据治理能力”优于“治理层”。
2. 同层节点数量超过 8 个时，按能力域分组。
3. 不同时表达时间计划和系统调用；需要时拆成时间线或架构图。
