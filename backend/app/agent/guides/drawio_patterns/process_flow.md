# Draw.io Process Flow Pattern

适用于业务流程、审批流程、处置流程、算法步骤、运维流程和操作手册。

## 布局

1. 默认从左到右或从上到下，不混用两个主方向。
2. 长流程按阶段分组，每组 3 到 6 个节点。
3. 并行流程使用泳道或并行分支，汇合点要明确。
4. 异常路径放在主流程下方或右侧，不穿插主路径。

## Shape 语义

1. 圆角矩形：开始、结束、人工动作、业务步骤。
2. 矩形：系统处理、计算、自动任务。
3. 菱形：判断节点；只用于确实存在分支的条件。
4. 容器/泳道：部门、角色、系统或阶段。
5. 注释框：限制、风险、口径说明，不承载主流程。

## 连接

1. 主流程使用实线箭头。
2. 判断节点必须有 2 到 3 条明确分支，并在线上标注条件。
3. 异常、回退、重试路径使用虚线或弱化样式，并标注触发条件。
4. 不要让连线回穿主流程；必要时从外侧绕行。

## 文本

1. 节点文本使用动宾短语，例如“采集数据”“计算排名”“生成报告”。
2. 单个节点文本超过 18 个中文字符时，拆成短标题和注释节点。
3. 同一层级节点命名风格保持一致。

## 质量门槛

1. 判断节点连续超过 3 个时，考虑改为决策树。
2. 步骤超过 18 个时，按阶段拆图。
3. 如果流程涉及多个角色，优先使用泳道。
