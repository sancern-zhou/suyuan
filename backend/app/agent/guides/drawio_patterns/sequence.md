# Draw.io Sequence Diagram Pattern

适用于展示多个参与者之间按时间顺序发生的请求、响应、回调、重试和超时。

## 布局

1. 时间只能从上到下推进，参与者从左到右排列。
2. 建议不超过 5 条生命线；超过时拆分主链路和异常链路。
3. 同一消息层级保持水平，连续消息之间至少留出一个文本高度。
4. 分支、可选和循环片段使用明确容器，并标注 `ALT`、`OPT` 或 `LOOP`。

## Shape 语义

1. 顶部节点：参与者、系统或服务。
2. 竖向虚线：生命线。
3. 细长矩形：激活区间，仅在确有处理持续时间时使用。
4. 横向箭头：消息；回到自身的消息使用短 U 形折线。

## 连接与文本

1. 同步调用使用实线实心箭头，异步消息使用实线开放箭头，返回使用虚线。
2. 消息标签使用动作或接口名，不写“调用”“返回”等无信息词。
3. 主成功路径最多强调 1 至 2 条消息。
4. 分支条件必须写在片段区域顶部，不得只依赖颜色。

## 质量门槛

1. 单图建议不超过 16 条消息和 1 个主要组合片段。
2. 不混用流程图菱形；条件分支由组合片段表达。
3. 生命线、消息标签和箭头不得相互遮挡。
