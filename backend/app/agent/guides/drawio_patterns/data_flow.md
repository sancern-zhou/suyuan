# Draw.io Data Flow Pattern

适用于数据采集、清洗、转换、分析、报表、模型推理、数据血缘和数据平台链路。

## 布局

1. 数据源放左侧，消费端放右侧，中间按处理阶段排列。
2. 常见顺序为：数据源、采集、存储、清洗、计算、服务、报表/模型/应用。
3. 批处理和实时流应分通道表达，不混成一条线。
4. 字段级血缘和系统级数据流不要混在同一张图里。

## Shape 语义

1. 圆柱：数据库、数据湖、缓存、文件存储。
2. 矩形：ETL、计算任务、清洗规则、模型服务。
3. 圆角矩形：人工校核、报表消费、业务应用。
4. 细长矩形或胶囊：消息队列、流处理通道、事件总线。
5. 容器：数据域、主题域、离线区、实时区、安全边界。

## 连接

1. 每条边标注主要数据对象或格式，例如 `小时值`、`AQI日报`、`Parquet`、`JSON`。
2. 批处理使用实线，实时/事件使用虚线或带事件标签的箭头。
3. 如果边表示转换，应标注动作，例如 `清洗`、`聚合`、`标准化`。
4. 数据回流路径必须清楚标注，避免被误解为主链路。

## 质量门槛

1. 数据源超过 6 个时，先合并为来源分组。
2. 处理阶段超过 5 层时，拆成总览图和局部图。
3. 存储节点过多时，按数据域或生命周期分组。
