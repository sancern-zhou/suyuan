# Draw.io Org and Responsibility Tree Pattern

适用于组织层级、岗位归属、Agent 路由、责任升级和父子结构。

## 布局

1. 根节点位于顶部，子节点逐层向下展开；不得混入时间流程语义。
2. 建议深度不超过 4 层、节点不超过 12 个。
3. 同一父节点的子节点等间距排列，父节点位于子节点组中心。
4. 同层节点较多时按责任域分组，或拆分为总览和部门详情。

## Shape 语义

1. 人员、团队、岗位、Agent 使用同一类基础节点，但通过类型标签区分。
2. 外部顾问、协作方或非汇报关系使用弱化或虚线样式。
3. 升级责任、审批权限等特殊关系必须在线上标注。

## 连接

1. 汇报或归属使用自上而下实线。
2. 协作、支持和虚线汇报不得与主层级线混在同一通道。
3. 同一父节点的连线使用独立锚点，不得堆叠成一条无法追踪的线。

## 质量门槛

1. 每个非根节点应有且只有一个主父节点。
2. 组织树不得出现未解释的闭环。
3. 节点名称使用组织或责任名称，长职责说明放入注释。
