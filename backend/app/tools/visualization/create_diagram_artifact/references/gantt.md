# Gantt Chart Template

适用于实施计划、项目排期、里程碑、版本路线、交付节奏。目标是表达任务在时间轴上的开始、结束、阶段和进度。

## P0 硬规则

- 每个任务必须有 `label`。
- 每个任务优先写 `start` 和 `end`，格式 `YYYY-MM-DD`。
- 没有 `end` 时可写 `duration`，单位为天。
- 任务数优先 3-12 个；更多任务应按阶段拆图或合并。
- 不用甘特图表达因果流程、系统架构或数据流。

## 推荐参数

- `diagram_type`: `gantt`
- `direction`: 可省略；模板默认横向时间轴。
- `steps`: 任务列表，字段包含 `id`、`label`、`start`、`end`、`phase`、`owner`、`progress`。
- `edges`: 通常不需要；依赖关系只保留关键说明，不在主图画复杂网络。

## 示例

```json
{
  "diagram_type": "gantt",
  "steps": [
    {"id": "research", "label": "需求调研", "start": "2026-06-01", "end": "2026-06-05", "phase": "准备", "progress": 100},
    {"id": "design", "label": "方案设计", "start": "2026-06-06", "end": "2026-06-12", "phase": "设计", "progress": 60},
    {"id": "pilot", "label": "试点验证", "start": "2026-06-13", "end": "2026-06-20", "phase": "验证", "progress": 20}
  ]
}
```

## 视觉要求

- 使用传统 draw.io 风格：白色画布、左侧任务列、右侧时间轴和条形任务。
- 任务条按真实日期比例定位，进度用条内浅色填充表示。
- 阶段用低饱和颜色区分，不使用大面积高饱和色。
- 主图必须自解释，不渲染底部说明。

## 禁止事项

- 不要把每个任务依赖都画成连线网络。
- 不要在任务名里写长句或完整说明。
- 不要把没有时间范围的任务强行画成甘特图。
