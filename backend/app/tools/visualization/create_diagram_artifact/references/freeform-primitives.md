# Freeform Drawing Primitives

使用 `create_diagram_artifact` 且 `diagram_mode="freeform"` 时，读取 `freeform-index.md` 后必须读取本文件。本文定义所有 freeform 图共用的可调用绘图基础信息；具体图类型再读取对应设计文档。freeform 输入字段必须是 `canvas/shapes/connectors/groups`。

## 使用边界

- Schema 只定义字段结构；本文定义 Agent 可选择的绘图原语。
- 本文是通用基础层，不替代 `freeform-architecture.md` 等类型规范。
- 后处理不重写语义结构；节点类型、布局模式、连线端点和线型由 Agent 在 `diagram_plan` 或 `diagram_patch` 中明确给出。

## shape.type 原语

| 语义 | 推荐 shape.type | 适用场景 | 使用要点 |
|---|---|---|---|
| 普通模块 | `rectangle` | 通用能力块、表格单元、简单步骤 | 标签短，尺寸统一，避免全图都用同一矩形 |
| 服务/应用 | `rounded_rect` | API、微服务、业务应用、门户 | 适合主要业务节点，同层尺寸保持一致 |
| 数据库 | `database` 或 `cylinder` | 数据库、数据仓库、数据湖、对象存储 | 放在数据层或底部支撑区，标签使用实体名 |
| 队列/总线 | `queue` 或 `rounded_rect` | 消息队列、事件总线、数据总线 | 推荐横向长节点，作为异步关系中转 |
| 外部系统 | `cloud` | 第三方平台、外部服务、云端系统 | 放在主系统边界外或侧栏中 |
| 判断/规则 | `diamond` | 条件判断、路由规则、规则引擎 | 只用于确有分支语义的节点 |
| 引擎/计算 | `hexagon` | AI 引擎、模型服务、调度编排、计算核心 | 用少量强调边框，避免滥用 |
| 文档/报告 | `document` 或 `note` | 报告、工单、文件、说明注释 | 注释不应替代结构表达 |
| 容器节点 | `container` | 系统边界、域边界、分层背景 | 可作为 connector 端点，承载一组普通节点 |
| 泳道 | `swimlane` | 阶段、组织、职责分区、流程泳道 | 适合流程和责任边界清晰的图 |
| 用户/角色 | `actor`、`person` 或 `rounded_rect` | 用户、运维、监管、业务角色 | 放在入口侧或消费侧，不挤入主系统内部 |

如果渲染器暂不支持某个具体形态，使用最接近的 `shape.type` 并通过 `style` 或 label 保留语义，例如用 `rounded_rect` 表示消息总线时设置长条尺寸和虚线边框。

## connector.type 和 style 原语

| 关系语义 | 推荐 connector.type | 推荐 style 字段 | 端点规则 |
|---|---|---|---|
| 主数据流 | `arrow` | `endArrow=block;strokeWidth=2` | 连接主干层、域、总线或代表节点 |
| 同步/API 调用 | `arrow` | `endArrow=block;strokeWidth=1.5` | 连接调用方和服务/API 边界 |
| 异步事件 | `dashed` | `dashed=1;endArrow=block` | 必须经过队列、事件总线或消息主题 |
| 批处理/同步任务 | `dashed` | `dashed=1;dashPattern=8 4;endArrow=block` | 适合跨层低频同步，不与主链路同权重 |
| 控制/调度 | `dashed` | `dashed=1;strokeWidth=1.2;endArrow=open` | 连接调度器、规则、被编排能力 |
| 监控/日志/告警 | `dotted` 或 `dashed` | `dashed=1;strokeColor=#94A3B8;endArrow=open` | 指向监控域，视觉权重低于主数据流 |
| 依赖/部署 | `line` | `endArrow=none;strokeWidth=1` | 表达支撑关系，不抢业务主线 |
| 反馈闭环 | `arrow` | `curved=1;endArrow=block` | 每张图最多 1-2 条，避免绕线过多 |

通用连线约束：

- connector 的 `from` 和 `to` 必须引用已有 shape/group id。
- 能连接 group/container 时，优先连接边界或代表节点；不要默认连接所有普通节点。
- 线标签只用于消除歧义，保持 2-6 个汉字或短英文。
- 同一语义的线型和颜色应一致，不同语义要能区分。
- 连接线不应从节点中心穿过，布局时预留水平/垂直通道。

## 布局原语

| 布局原语 | 适用场景 | 结构建议 |
|---|---|---|
| 横向层带 | 分层架构、能力架构、平台架构 | 使用横向 group/container 表示层，自上而下或自下而上阅读 |
| 纵向域区 | 多业务域、多系统域、多组织边界 | 使用纵向 group/container 表示域，跨域线只保留主干 |
| 左右输入输出 | 外部输入、消费端、监管推送 | 左侧放用户/设备/第三方，右侧放应用/报告/API/告警 |
| 底部支撑带 | 基础设施、安全、监控、存储、运维 | 作为弱依赖或支撑域，不与主流程同权重 |
| 中心平台 | 一个核心平台承接多入口多出口 | 中心放平台/总线，左右或上下放输入输出边界 |
| 泳道 | 流程、职责、组织或阶段明确 | 每条泳道只放该职责内节点，跨泳道连线少而清晰 |
| 矩阵 | 能力地图、对比、分布 | 行列标签稳定，单元格少用连线 |
| 星型聚合 | 多源汇聚到总线/网关/中心能力 | 必须用聚合节点，避免多个普通节点直连同一目标 |

## groups 原语

- `groups` 表示语义边界、背景区域或层级，不是普通节点的复制品。
- group 可以有 `x/y/width/height` 和 `children`，用于可编辑结构和 QA 判断。
- 架构、拓扑、平台类图优先用 group/container 建立主结构，再放普通 shape。
- group 标题放左上角，颜色使用浅底和语义边框；不要让 group 背景压过节点。

## style 字段原语

常用字段：

- `fillColor`: 节点或容器填充色，建议浅色。
- `strokeColor`: 边框或连线颜色，建议与语义层/域一致。
- `strokeWidth`: 主要边框 1.5-2，弱依赖 1-1.2。
- `fontColor`: 文本颜色，确保和填充色有足够对比。
- `fontSize`: A4 页面交付默认按原屏幕字号约 1.5 倍设计；后处理会将基准字号及以下自动放大：普通节点 18 及以下乘 1.5，容器/层标题 21 及以下乘 1.5，连线标签 15 及以下乘 1.5。不要再使用 11-13 作为架构图/汇报图默认字号。
- `fontFamily`: 默认由工具补齐为固定模板同款中文字体；除非有明确品牌规范，不要手动改成 Arial。
- `rounded`: 圆角控制，服务类节点常用 `rounded=1`。
- `dashed`: 虚线控制，异步、弱依赖、外部边界常用 `dashed=1`。
- `endArrow`: 箭头控制，主数据流用 `block`，弱依赖可用 `open` 或 `none`。

## 标签文本和上下标

- 普通 label 可以直接写 `SO2`、`NO3-`、`PM2_5`、`CO₂`、`μg/m3`、`m³` 等常见污染物和单位，工具会在 Draw.io/SVG 中规范为上下标。
- 如需显式控制，也可以在 label 中使用安全的 `<sub>...</sub>` 和 `<sup>...</sup>`；不要写其它 HTML 标签。
- 不要为了上下标把同一个标签拆成多个 shape；保持一个语义节点一个 label。

风格原则：

- 一张图最多 3-5 个主语义色，不要全图只用一种蓝色或一种灰色。
- 容器使用浅色背景，普通节点使用白底或更浅底色。
- 强调节点控制在 10%-20%，不要每个节点都加粗高亮。
- 显式 style 优先；工具固定商务清爽默认风格只补默认值，不替代设计选择。

## 通用禁忌

- 不要让多个普通节点重叠或坐标相同。
- 不要用长句 label 替代结构拆分。
- 不要把每个普通节点都逐个连线，除非图类型本身就是关系图。
- 不要让连线数量超过读者能快速追踪的范围；高扇入先加总线、网关、汇聚点。
- 不要用 HTML 作为 freeform 图表交付物；交付应包含 `.drawio`、SVG 和 PNG。
