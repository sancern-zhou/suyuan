# Data Flow Diagram Template

适用于数据采集、处理、存储、分析、输出的流向图。目标是表达数据如何进入系统、如何变换、在哪里沉淀、被谁消费。

## P0 硬规则

- 数据流图只画数据，不画审批动作和组织职责。
- 每条边标签必须说明数据或处理动作。
- 数据源、处理、存储、应用消费必须视觉上可区分。
- 外部系统放在边界位置，不能混入内部处理链路。
- 实时流、批处理、人工导入如果同时存在，必须用不同主干或边标签区分。

## 结构模型

按下面顺序组织：

1. 数据源：站点、设备、第三方 API、文件、业务系统。
2. 接入采集：网关、采集任务、消息队列、ETL。
3. 处理计算：清洗、校验、聚合、模型、规则。
4. 存储沉淀：数据库、数据仓库、对象存储、缓存、指标库。
5. 应用消费：报表、告警、可视化、接口、AI 分析。

## 推荐布局

- 默认 `direction="LR"`，让数据从左向右流动。
- 数据源放左侧，消费端放右侧，存储放中下或中部稳定位置。
- 如果同时有实时和离线链路，使用两个 `group`：`实时链路`、`离线链路`。

## 推荐参数

- `diagram_type`: `data_flow`
- `layout_engine`: `graphviz`
- `direction`: `LR`
- `steps`: 所有节点带 `group`
- `edges`: 每条边带数据/动作标签

## 示例

```json
{
  "steps": [
    {"id": "sensor", "label": "监测站点", "group": "数据源"},
    {"id": "ingest", "label": "数据接入\n校验 | 去重", "group": "接入采集"},
    {"id": "mq", "label": "消息队列", "group": "接入采集"},
    {"id": "compute", "label": "指标计算", "group": "处理计算"},
    {"id": "warehouse", "label": "指标库", "group": "存储沉淀"},
    {"id": "dashboard", "label": "可视化看板", "group": "应用消费"}
  ],
  "edges": [
    {"from": "sensor", "to": "ingest", "label": "小时数据"},
    {"from": "ingest", "to": "mq", "label": "清洗后数据"},
    {"from": "mq", "to": "compute", "label": "实时订阅"},
    {"from": "compute", "to": "warehouse", "label": "指标结果"},
    {"from": "warehouse", "to": "dashboard", "label": "查询展示"}
  ]
}
```

## 视觉要求

- 数据源、处理、存储、消费四类节点使用一致的形状或颜色编码。
- 存储节点要稳定醒目，因为它是数据流的锚点。
- 边标签比节点说明更重要，必须短且具体。

## 禁止事项

- 不要把“用户提交审批”画成数据流，除非明确是数据对象流转。
- 不要让双向同步、批处理、实时流共用无标签箭头。
- 不要把数据库画成普通业务模块。
