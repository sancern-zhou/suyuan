## 一、总体结论

**项目整体成熟度中上：骨架优秀、边角失守。** 后端 default-deny 鉴权、统一路径能力层（path_config）、fail-closed Python 沙箱、事务性 Outbox + 可重建 Qdrant 架构、restart_server.sh + preflight + nginx 契约测试的部署主链路，均达到同类项目高水准；前端 auth 层工厂化、守卫测试与测试文化也超出平均。但四条评审线各发现了必须立即修复的 P0 级问题，集中在**权限/隔离的「最后一公里」失守**（admin 配置接口、知识库私有库、bash 沙箱断网、前端 XSS 与硬编码密钥、活体凭据落盘），以及**项目自定规范被自身代码破坏**（路径规范约 40 处违规、docs/ 整目录不入库、start.sh 违反启动规范）。

## 四、规范符合性结论

- **CLAUDE.md 知识库图谱铁律 9 条**：6 条符合（图谱归属、PG 事实源、检索审核状态、Agent 工具契约等实现质量高）；3 条存在问题——「Qdrant 只存可重建索引」部分违反（chunk 向量无重建入口）、「失败不恢复旧版本」被 replace_document 直接违反、「can_search/can_manage 约束一切」机制覆盖但实际失效。详见 02 报告核查表。
- **AGENTS.md 部署条款**：preflight、契约测试、restart_server.sh、前端产物三 grep 验证（CI 自动执行）均合规且有测试守护；但 start.sh、生产模板、templates-local、docs/ 四处不符合或游离于规范外。详见 04 报告核查表。
- **路径规范（禁 cwd/`__file__` 推根）**：`Path.cwd()/os.getcwd()` 合规良好（生产代码仅 startup.py 一处），但 `__file__` 推根仍有约 40 处生产代码违规；另有约 178 个测试/spec 文件混编在 backend/app 生产包内（占 13%）。

## 五、亮点（跨评审线归并）

1. **安全基座成体系**：default-deny ASGI 鉴权 + 信任网段 + 不可信头剥离 + 生产配置强校验；CI gitleaks 全历史扫描；secrets 全局 gitignore；上传链路 UUID 落盘 + SVG 消毒 + 属主校验。
2. **数据架构先进**：事务性 Outbox（幂等键、advisory lock、skip_locked 租约、is_latest 丢弃被取代事件）+ 读路径 PG 复核防孤儿向量 + chunk 稳定身份复用 + 抽取全程溯源。
3. **部署即代码**：restart_server.sh 进程组终止/cwd+cmdline 双校验/systemd 探测；nginx 模板与启动脚本均有 pytest 契约测试守护；postgres 密码强制注入。
4. **测试与守卫文化**：后端约 570 个测试文件、前端 96 单测 + 7 e2e；架构守卫测试防止旧接口复活、锁定启动脚本必须过 preflight。
5. **前端 auth 工厂化**：依赖注入、禁未声明外链、401 令牌比对防误杀、一次性 WS 票据、开放重定向防护。
