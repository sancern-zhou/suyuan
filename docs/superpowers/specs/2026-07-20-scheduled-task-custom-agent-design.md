# 定时任务 Custom Agent 执行模式设计

## 背景

现有定时任务通过 `execution_mode` 选择 `assistant`、`expert`、`query` 或 `social` 等既有 Agent 模式。每个模式同时绑定业务系统提示词和一整套工具白名单。这种方式存在两个问题：

1. 任务可能被配置到能力不匹配的模式。例如业务提示要求创建报告包，但实际模式没有报告包工具。
2. 模式会向模型暴露与当前任务无关的工具 schema，持续增加每轮上下文和 token 消耗。

本设计新增可选的 `custom` 执行模式。用户为单个定时任务选择最小工具集合；系统不加载其他 Agent 模式的业务提示词，只保留不可编辑的最小平台内核提示词。

## 目标

- 允许普通定时任务和事件触发任务选择 `custom` 执行模式。
- 允许用户自由选择任务级工具白名单，不推断或自动补充工具依赖。
- 一个任务运行期间只创建一个 Loop Agent。
- 所有步骤共享同一个 Agent、会话和冻结的工具集合。
- 模型上下文中只出现用户所选工具的 schema。
- 保持所有既有执行模式及历史任务行为不变。
- 对无效工具、循环调用和确定性模型错误快速失败，避免无意义迭代。

## 非目标

- 不建立可复用的 Agent 模板或模板版本管理。
- 不允许逐步骤配置不同工具。
- 不显示工具 schema token 估算或工具数量统计。
- 不自动分析工具依赖，不推荐或补充配套工具。
- 不允许在任务运行期间动态增删工具。
- 不替换现有 `assistant`、`expert`、`query`、`social` 模式。

## 已选方案

新增独立的 `custom` 执行模式，而不是覆盖既有模式的工具列表，也不在第一版引入 Agent 模板。

该方案使配置语义明确：选择 `custom` 即表示不继承任何既有模式的业务提示词和工具能力。与既有模式隔离也能避免改变历史任务行为。

## 数据模型

`ScheduledTask` 增加可选字段：

```json
{
  "execution_mode": "custom",
  "tool_names": [
    "read_file",
    "call_sub_agent",
    "create_report_package",
    "render_report_package",
    "validate_report_package"
  ]
}
```

字段规则：

- `tool_names` 是任务级有序工具名称列表。
- 只有 `execution_mode="custom"` 时允许设置 `tool_names`。
- custom 任务必须至少选择一个工具。
- 重复名称按首次出现位置去重，保留用户配置顺序。
- 非 custom 任务携带 `tool_names` 时保存失败，不静默忽略。
- 旧任务没有 `tool_names` 时保持向后兼容。

所有 `TaskStep` 继续只保存业务 `agent_prompt`；不增加步骤级工具字段。

## 提示词模型

custom 模式不加载任何既有 Agent 模式的业务系统提示词。系统只注入一段不可由任务用户编辑的最小平台内核提示词，负责：

- 工具调用协议；
- 通用安全边界；
- 明确的循环终止要求；
- 任务成功或失败的终态要求；
- 禁止返回“是否继续”等需要实时用户交互的中间状态。

领域知识、业务流程、产物格式和具体任务要求继续由各步骤的 `agent_prompt` 提供。

最小内核不描述未选择的工具，也不暗示 Agent 拥有其他模式能力。

## 工具选择与校验

### 保存时校验

创建或更新 custom 任务时，后端必须对每个工具执行以下校验：

1. 名称能在全局工具注册表中解析；
2. 工具当前处于启用状态；
3. 当前操作者有权使用该工具。

任何一项失败时，整个保存操作失败。响应必须列出具体工具名称和失败原因。系统不删除无效项、不替换工具，也不自动增加依赖。

### 运行前校验

任务启动时再次执行相同校验，以处理任务保存后工具被下线、禁用或撤权的情况。运行前校验失败时必须在第一次模型请求之前结束任务，并返回明确失败原因。

### 运行时冻结

校验通过后，从全局工具注册表按 `tool_names` 构造任务专属、只读的 ToolRegistry。该实例在整个任务运行期间冻结：

- 未选择工具不注册、不生成 schema，对模型不可见；
- 模型不能通过名称请求未选择工具；
- 管理员在运行途中禁用已选工具时，本次任务失败，不回退或替换；
- `call_sub_agent` 只有被明确选择时才可调用；子 Agent 按调用参数指定的目标模式独立运行。

## 执行生命周期

custom 任务使用以下生命周期：

```text
读取任务配置
  -> 校验 custom 工具列表
  -> 构造只读 ToolRegistry
  -> 使用最小内核创建一个 Loop Agent
  -> 按顺序追加并执行所有步骤的 agent_prompt
  -> 复用同一 session_id 和固定工具集
  -> 完成或明确失败
  -> 销毁任务专属 Agent
```

与当前逐步骤创建 Agent 的执行方式不同，custom 模式在任务步骤循环外创建一次 Agent。每个步骤只向同一运行实例追加新的业务指令。任务专属 Agent 不注册为全局模式实例，任务结束后释放。

现有模式继续沿用原有执行路径，避免扩大本功能的兼容风险。

## 前端配置

定时任务创建和编辑界面的执行模式列表增加“自定义模式”。

选择 custom 后：

- 显示全局已启用且当前用户有权使用的工具列表；
- 支持搜索和多选；
- 显示说明：“仅加载所选工具，不继承其他模式能力”；
- 工具选择区位于任务级配置区域，不出现在步骤编辑区域；
- 不默认选择工具；
- 不显示依赖建议、token 估算或其他额外统计。

切换离开 custom 模式时，前端清空 `tool_names`，避免提交无效组合。重新打开 custom 任务时，按照保存顺序恢复选择状态。

## API 行为

创建与更新接口接收 `tool_names`，读取接口原样返回规范化后的有序列表。

建议使用结构化校验错误，例如：

```json
{
  "detail": {
    "code": "invalid_custom_task_tools",
    "items": [
      {
        "tool_name": "render_report_package",
        "reason": "disabled"
      }
    ]
  }
}
```

前端直接展示具体工具及原因，不用通用“保存失败”掩盖问题。

## 异常与终止策略

custom 模式不回退到任何既有模式，也不在错误后扩大工具集。

### 工具循环

- Loop Guard 达到 block 级别时，将阻断结果写入上下文，要求 Agent立即换策略或明确失败。
- 如果下一轮再次请求相同工具和相同参数，运行时直接终止任务。
- 终止结果必须是机器可识别的失败终态，不能继续消耗剩余迭代次数。

### 模型请求错误

- 流式和非流式请求均出现同一确定性错误后，计为一次失败周期。
- HTTP 400、鉴权失败和请求格式错误等确定性错误达到小次数阈值后熔断。
- 熔断后返回明确失败原因，不继续运行到全局最大迭代次数。
- 可重试的网络瞬断仍可使用现有有限重试策略，但不得改变工具配置。

### 工具状态变化

已选工具在任务运行中被禁用、删除或撤权时，当前运行立即失败。后续运行需用户编辑任务或恢复工具状态。

## 持久化与兼容性

- `tool_names` 随 ScheduledTask 一起持久化。
- 历史任务缺少该字段时按空值读取，但不会触发 custom 校验。
- 既有模式的工具白名单、系统提示词和运行流程保持不变。
- custom 会话的展示模式记录为 `custom`，便于识别来源，但不会被前端当作可交互的全局 Agent 模式实例。
- 普通定时触发和事件触发共用同一 custom 执行逻辑。

## 测试设计

### 后端

- 合法 custom 工具列表可以创建和更新。
- 空列表、未知工具、禁用工具和无权限工具保存失败。
- 非 custom 模式携带 `tool_names` 保存失败。
- 重复工具规范化后保留首次出现顺序。
- 旧任务没有 `tool_names` 时可正常加载和运行。
- 实际模型请求只包含所选工具 schema。
- 未选择工具不能通过名称调用。
- 多步骤 custom 任务只创建一个 Agent，所有步骤共享 ToolRegistry 和 `session_id`。
- 任务启动前工具失效时，在第一次模型请求前失败。
- custom 模式不加载任何既有模式业务系统提示词。
- Loop Guard 二次相同调用会终止任务。
- 连续确定性 HTTP 错误在限定次数内熔断。
- 普通定时任务和事件任务都能运行 custom 模式。

### 前端

- 执行模式列表显示“自定义模式”。
- 仅 custom 模式显示工具搜索和多选区。
- 创建、编辑和重新打开任务时保持选择顺序与状态。
- 切换离开 custom 后清空 `tool_names`。
- 后端结构化工具校验错误能够准确展示。
- 多步骤界面只显示一处任务级工具配置。

### 核心验收

验收不能只检查界面选择结果。必须在运行时测试中确认：

1. 发给模型的工具 schema 只包含任务选择的工具；
2. 多步骤执行期间工具集保持固定；
3. 整个任务只创建一个 Loop Agent；
4. custom 模式未继承其他模式的业务提示词；
5. 无效配置和确定性运行错误会快速、明确失败。

## 实施边界

本功能涉及以下范围：

- ScheduledTask 数据模型和存储兼容；
- 定时任务创建、更新和读取 API；
- custom 工具校验及任务专属 ToolRegistry 构造；
- custom 模式最小内核提示词；
- custom 任务的单 Agent、多步骤执行生命周期；
- 定时任务创建和编辑界面；
- 后端与前端自动化测试。

不在本次实现中重构其他 Agent 模式，也不建设通用 Agent 模板管理系统。
