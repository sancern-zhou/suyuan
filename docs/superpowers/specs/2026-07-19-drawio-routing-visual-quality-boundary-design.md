# Draw.io 连线路由与视觉质量闭环职责边界

## 背景

AI 候选画板在创建阶段已经通过 XML 几何信息识别连线与节点的碰撞，并自动选择端口、调整通道和写入显式正交路径。若视觉质量闭环再次执行同一套 XML 路由检查，会形成重复判断：能够确定性识别的问题本应在生成阶段自动修复，而不应留给 Agent 根据质量报告再次修改。

## 设计原则

确定性、可机械修复的连线问题由自动路由模块闭环；依赖整体观感和语义判断的问题由视觉质量闭环处理。

XML 几何检查不作为截图后的独立质量环节。自动路由模块内部仍保留写回并重新解析后的后置断言，用于证明输出满足“连线不穿节点”的硬约束。这是路由算法的正确性保障，不是第二轮质量检查。

## 处理流程

```text
AI 生成候选 XML
  -> 自动检测并修复连线与节点碰撞
  -> 写入显式 segmentEdgeStyle、端口和航点
  -> 重新序列化、解析并执行内部零碰撞断言
  -> 保存不可变候选
  -> 生成截图
  -> Agent 复核视觉可读性
  -> 接受候选或生成修订候选
```

若自动路由找不到安全路径，创建阶段返回结构化 `unroutable_edge` 或对应路由错误，候选不得持久化。不得把确定性的穿节点问题降级为视觉警告。

## 自动路由模块职责

自动路由模块负责：

- 检测连线是否穿过节点或受保护区域；
- 自动选择入口和出口端口；
- 调整水平或垂直通道位置；
- 在候选 XML 中写入显式、可复现的正交路径；
- 在写回并重新解析后验证 `edge_vertex_intersection_count == 0`；
- 在无法满足硬约束时阻止候选持久化；
- 输出路由指标用于审计、监控和问题定位。

路由指标不是视觉闭环的修复任务。`edge_vertex_intersection_count` 在成功候选中必须为零；`routed_edge_count`、`rerouted_edge_count`、`max_route_offset` 和 `edge_edge_crossing_count` 仅用于说明处理结果及辅助观察。

## 视觉质量闭环职责

视觉质量闭环不重复执行 XML 连线碰撞检测，也不对已保存候选原地修改路径。它通过截图和上下文判断无法稳定机械量化的视觉问题，包括：

- 路径是否过于曲折或绕行过远；
- 多条连线交叉是否显著影响理解；
- 箭头方向和终点是否清晰；
- 连线、标签和节点在视觉上是否过密；
- 整体阅读顺序是否自然；
- 局部布局虽然无几何碰撞，但是否仍然难以阅读。

发现这类问题时，Agent 应基于当前候选生成新的修订候选，再经过自动路由和截图复核；不得直接改写已截图的不可变候选。

## 一致性保障

渲染和接受阶段应通过候选版本标识以及现有不可变引用保证使用同一份 XML。若未来允许候选在创建后被外部修改，则应增加 XML 内容哈希校验，而不是在视觉闭环重复路由检查。

截图阶段生成新的质量报告时，不应丢失创建阶段的路由审计指标。可以保留原报告中的 `metrics`，或将路由结果放入独立的 `routing_metrics` 字段；这些数据只用于审计，不参与截图阶段的重复阻断。

## 验收标准

- AI 候选创建成功时，内部后置断言证明不存在连线穿节点。
- 无法安全路由时，候选不会持久化。
- 截图视觉质量服务不重复运行 XML 路由碰撞检查。
- 截图完成后仍可查看创建阶段的路由审计指标。
- 视觉修订通过新候选完成，候选 XML、截图和质量结论保持一致。
- 非 AI 候选和人工草稿不引入新的自动路由行为。
