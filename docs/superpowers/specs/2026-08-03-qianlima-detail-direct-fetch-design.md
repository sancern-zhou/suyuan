# 千里马详情页直连抓取修复设计

## 背景

生产链路存在两种不同的详情页结果：

- HTTP 快速路径不使用当前 SOCKS5 代理，返回旧版脱敏正文，其中会员字段被替换为 `****`。
- Playwright 会员浏览器使用当前 SOCKS5 代理时，只得到“今日浏览已达到上限”的壳页。
- 同一会员账号使用 Playwright 直连时，可以取得完整详情和真实中标单位，证明会员账号权限有效。

## 目标

只修复详情页抓取路径，使会员浏览器可以绕开当前受限代理取得完整正文，并对 2026-08-02 的招投标数据执行回填测试。

## 非目标

- 不禁止包含 `****` 的正文入库。
- 不改变列表搜索、候选筛选、LLM 复核或数据库表结构。
- 不全量回填全部历史数据。
- 不更换或新增代理服务。

## 方案

### 详情抓取流程

1. 保留现有 HTTP 快速抓取。
2. HTTP 返回可用且没有明确会员受限提示的详情时，继续直接使用该结果。
3. HTTP 返回明确会员受限提示时，不将其作为最终抓取结果，继续尝试会员浏览器。
4. 详情页会员浏览器默认直连，不应用 `QIANLIMA_PROXY_*` 配置；列表搜索和其他请求的代理行为保持不变。
5. 浏览器返回正文后沿用现有详情判定和入库流程。本次不增加针对裸 `****` 的拒绝规则。

### 边界与失败处理

- 浏览器仍遇到验证码、空壳页、浏览上限或会员受限提示时，沿用现有错误和账号切换逻辑。
- 多账号继续复用各自的 storage state 和 `xAuthToken`。
- 详情直连行为应可通过配置恢复使用代理，以便将来替换为健康代理后重新启用。

## 测试设计

自动化回归测试覆盖：

1. HTTP 返回明确会员受限正文时，必须继续进入浏览器抓取，而不是提前返回。
2. 详情浏览器默认不携带 SOCKS5 代理启动参数。
3. 显式启用详情代理时，仍可沿用现有 Playwright 代理配置。
4. 不新增禁止 `****` 入库的断言，保持现有数据策略。

## 昨日数据回填验证

修复部署到当前运行环境后，针对 2026-08-02 执行回填测试：

1. 选择昨日已入库且正文包含脱敏标记的候选重新抓取详情。
2. 使用现有 LLM 抽取和保存流程覆盖详情及结构化字段。
3. 对比回填前后详情完整度、中标单位填充数量和 accepted-but-missing 数量。
4. 抽样核对至少两条中标公告，确认数据库中保存的中标单位与实时完整详情一致。

## 成功标准

- 自动化测试通过。
- 详情浏览器实测使用直连，并能取得此前代理路径无法取得的完整正文。
- 2026-08-02 回填样本中的中标单位可以从完整正文成功抽取并写回。
- 列表抓取和其他代理配置不受影响。
- 没有新增 `****` 正文入库禁令。
