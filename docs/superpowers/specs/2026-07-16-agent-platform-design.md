# 智能体平台模式选择页设计

## 背景

当前六种 Agent 模式（助手、专家、问数、报告、图表、运维）的切换入口位于对话输入框下方，入口不够明显，也无法在用户进入系统时清晰说明各模式的定位。

本次改造在现有左侧导航和对话工作区基础上新增“智能体平台”功能：首页集中展示各 Agent 模式及介绍，用户选择模式后进入对应的空白对话工作区。

## 目标

- 用户刷新系统或重新登录后，默认看到智能体平台首页。
- 左侧导航提供醒目的“智能体平台”入口，用户可随时从对话页返回首页。
- 首页清晰展示六种 Agent 模式的定位、适用任务和运行状态。
- 用户选择空闲模式后进入该模式的新建空白对话。
- 移除输入框下方的模式切换控件，模式选择统一从智能体平台完成。
- 复用现有模式状态、会话恢复、后台任务和右侧结果面板能力。

## 非目标

- 不改变 Agent 后端接口、分析流程或事件协议。
- 不重构现有会话持久化机制。
- 不新增或删除 Agent 模式。
- 不调整模型档位、附件上传和输入框内的其他能力。
- 不改变知识管理、工具管理等管理模块的业务功能。

## 方案选择

采用“同一工作区内切换平台首页与对话页”的方案。

相比新增 `/agents`、`/chat/:mode` 等独立路由，该方案可以直接复用现有 `ReactAnalysisView`、Pinia 模式状态和主布局，减少对会话恢复及复杂面板联动的影响。相比弹窗式模式选择，它能够提供正式、明确的产品入口和足够的模式介绍空间。

## 信息架构与导航

### 默认入口

- 访问 `/` 时显示智能体平台首页。
- 浏览器刷新或重新登录后仍显示智能体平台首页。
- 平台/对话工作区状态不写入 `localStorage`，因此不会恢复上次停留的对话视图。
- 直接访问 `/session/:id` 属于明确的历史会话恢复行为，恢复成功后直接显示对应模式的对话页。

### 左侧导航

- 在左侧导航顶部、“新对话”附近新增一级入口“智能体平台”。
- 平台首页显示时，该入口处于选中状态。
- 对话页中点击该入口返回平台首页，不停止任何正在执行的任务。
- 最近对话、案例库或会话历史被选中时，直接打开该会话所属模式的对话页。
- “新对话”继续作为对话工作区内的明确重置操作；当用户位于平台首页时，不制造隐式模式选择。

## 平台首页

### 页面结构

主区域顶部展示：

- 标题：`选择智能体，开始工作`
- 说明：简要提示用户根据任务类型选择合适的智能体。

下方采用响应式卡片网格。桌面端多列展示，窄屏逐步收敛为单列。卡片整体可点击并支持键盘操作，每张卡片包含图标、名称、能力标签、简介、运行状态和“开始使用”提示。

### Agent 模式内容

| 模式值 | 展示名称 | 定位 |
| --- | --- | --- |
| `assistant` | 智能助手 | 通用问答、任务处理与综合分析 |
| `expert` | 专家分析 | 多专家协同研判，适合复杂问题和专业决策 |
| `query` | 智能问数 | 自然语言查询数据，联动地图与数据大屏 |
| `report` | 报告生成 | 根据资料与分析结果生成结构化专业报告 |
| `chart` | 图表创作 | 生成数据图表、流程图及可视化内容 |
| `ops` | 运维智能体 | 处理运维工单、排查问题并辅助形成处置方案 |

Agent 名称、模式值、图标、介绍和标签由统一元数据配置驱动。平台卡片、对话页标题及相关状态提示消费同一配置，避免多处维护造成不一致。

### 运行状态

- 模式存在正在分析的默认状态或活跃会话时，卡片显示“运行中”。
- 选择空闲模式时，清理该模式当前激活会话，创建空白对话状态，然后切换到该模式并进入对话页。
- 选择正在运行的模式时，不重置或清空任务，直接进入该运行中的对话，避免误删进行中状态。
- 返回平台首页只改变主区域展示，不暂停任务。

## 对话工作区

- 继续复用现有 `MainLayout`、普通对话区、问数大屏和右侧结果面板。
- 对话页顶部明确展示当前 Agent 名称和简短定位。
- 完全移除输入框下方的 `AgentModeSelector`，用户需通过左侧“智能体平台”返回并选择其他模式。
- 后台任务提示仍可存在，但不再承担模式切换职责。
- 模型档位、知识库、附件、语音及其他输入能力保持不变。

## 组件与状态设计

### Agent 元数据

新增独立配置模块，导出：

- 六种模式的有序列表。
- 按模式值获取元数据的辅助方法。
- 合法模式判断所需的稳定模式值。

现有 store 的模式值仍作为业务事实来源；配置模块只承担展示信息和顺序，不复制运行状态。

### AgentPlatform 组件

新增纯展示型平台组件：

- 接收 Agent 配置列表和运行模式集合。
- 发出 `select` 事件并携带模式值。
- 不直接操作 store、不负责创建会话，便于独立测试。

### ReactAnalysisView 工作区协调

在页面容器增加仅存于当前页面生命周期的工作区状态：

- `platform`：显示智能体平台。
- `chat`：显示现有主布局。

页面容器负责：

1. 初始化默认工作区。
2. 接收平台卡片选择。
3. 判断目标模式是否运行。
4. 对空闲模式执行模式切换和会话重置。
5. 对运行模式直接激活对应会话。
6. 处理左侧返回平台以及历史会话直达对话。

### AssistantSidebar

新增“智能体平台”模块及对应图标、选中态和事件。平台入口是导航行为，不直接修改 Agent 模式。

## 数据流

### 选择空闲 Agent

1. 用户点击 Agent 卡片。
2. `AgentPlatform` 发出模式选择事件。
3. 页面容器确认模式合法且未运行。
4. 切换至目标模式并调用现有模式会话重置能力。
5. 工作区状态改为 `chat`。
6. 现有 `MainLayout` 根据 store 当前模式渲染空白对话。

### 选择运行中的 Agent

1. 页面容器检测默认模式状态或该模式会话中存在运行任务。
2. 激活目标模式及其运行会话，不执行重置。
3. 工作区状态改为 `chat`。

### 恢复历史会话

1. 用户从最近对话、案例库、会话历史或 `/session/:id` 触发恢复。
2. 现有恢复逻辑加载会话并确定所属模式。
3. 恢复成功后将工作区状态改为 `chat`。
4. 恢复失败时保留当前页面状态并展示现有错误反馈。

## 错误与边界处理

- 非法或缺失的模式值不会触发重置，用户保留在平台首页。
- 模式初始化失败时不进入半初始化的对话页，并显示清晰错误提示。
- 重复点击卡片需要防止并发创建多个空白会话。
- 正在运行的模式优先保护任务状态，不执行默认新建逻辑。
- 返回平台首页不修改 `currentMode`，从而避免影响后台事件路由。
- 折叠侧栏使用图标和 `title` 保持平台入口可识别。
- 卡片提供可见焦点态，支持 Enter/Space 激活。

## 测试策略

优先为可独立测试的配置和状态协调逻辑编写 Node 测试，组件行为通过 Vue 构建和必要的静态契约检查验证。

覆盖场景：

- `/` 初始化时显示平台首页而不是对话区。
- 六种 Agent 卡片使用统一配置且文案完整。
- 点击空闲模式会重置目标模式并进入空白对话。
- 点击运行中模式不会重置任务并进入对应对话。
- 点击左侧“智能体平台”返回首页且不停止任务。
- 最近对话、会话历史和 `/session/:id` 恢复后直接进入对话页。
- 输入区域不再渲染 `AgentModeSelector`。
- 对话页能展示当前 Agent 名称和定位。
- 生产构建成功，现有前端测试不回归。

## 验收标准

1. 刷新首页或重新登录后，默认显示智能体平台。
2. 左侧导航存在清晰可见的“智能体平台”入口。
3. 首页完整展示六种 Agent 模式及相应介绍。
4. 空闲模式被选择后进入该模式的空白对话。
5. 运行中模式被选择后保持原任务并进入对应对话。
6. 输入框下方不再显示模式切换按钮。
7. 用户能从任意对话通过左侧入口返回平台首页。
8. 历史会话恢复仍能正确打开对应 Agent 对话。
9. 后台运行、右侧结果面板和其他管理模块行为保持兼容。
