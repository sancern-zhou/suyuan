# 统一会话归属与微信身份绑定设计

## 背景

系统已接入公司统一认证平台，但当前会话管理仍存在以下缺口：

- Web ReAct 会话没有用户归属字段，所有登录用户都能按 `session_id` 访问会话。
- 知识库问答会话已有 `user_id`，但续聊、历史、归档和删除接口没有一致执行所有者校验。
- 社交模式使用独立的文件会话和微信用户映射，尚未与认证平台用户绑定。
- 认证平台实际返回 `admin: true` 和 `roleCodeList`，当前后端没有解析这两个字段，因此会把超级管理员识别为普通用户。

本次建设只区分管理员和普通用户。普通用户只能管理自己的会话；管理员可以查看和管理所有用户的可写会话。Web 端可以查看微信会话历史，但微信会话对包括管理员在内的所有 Web 用户都只读，不跨渠道继续同一上下文；微信绑定的解绑和清理由独立的微信账号管理流程承担。

## 已验证的认证平台用户结构

使用现有前端登录流程验证管理员账户后，认证平台返回的相关字段为：

- 平台用户 ID：`1`
- 用户名：`ScGuanLy`
- 显示名称：`超级管理员`
- 管理员标记：`admin: true`
- 角色编码：`roleCodeList: []`

系统以平台用户 ID 作为稳定的会话归属标识。用户名和显示名称只作为展示快照，不参与权限判断。

## 目标与非目标

### 目标

- 正确解析认证平台管理员标记。
- 为 Web、知识库问答和新社交会话建立统一归属目录。
- 普通用户只能列出、读取和修改自己的会话。
- 管理员可以查看和管理所有可写会话，并查看所有只读微信会话。
- 已登录 Web 用户可直接扫码绑定自己的微信身份，不再发送四位绑定码。
- 新微信会话能在 Web 会话历史中只读查看。
- 未绑定微信用户仍可使用独立的微信会话，但不进入 Web 会话目录。
- 所有没有归属的 Web 和知识库历史归属管理员用户 ID `1`。

### 非目标

- 不迁移旧微信用户、旧社交映射或旧社交文件会话。
- 不支持管理员代替从未登录 Web 的用户绑定微信。
- 不支持一个平台用户绑定多个微信身份。
- 不允许不同平台用户抢占同一个微信身份。
- 不实现 Web 与微信双向续聊同一个会话上下文。
- 不建设通用的多角色 RBAC 权限系统。

## 方案选择

采用中央会话目录方案。Web ReAct、知识库问答和社交模式继续使用现有消息存储；新增统一目录负责会话归属、来源、列表索引和访问控制。

没有采用以下方案：

- 各存储独立实现权限：会重复三套查询、分页和访问规则，容易遗漏入口。
- 把全部消息迁移到单一会话表：社交模式依赖文件运行状态，知识库问答也有独立轮次模型，一次性迁移风险过高。

## 总体架构

功能拆为两个顺序交付、可独立验收的子项目。

### 第一阶段：统一身份与会话权限

- 扩展认证平台用户解析。
- 建立中央会话目录。
- 接入 Web ReAct 和知识库问答会话。
- 回填存量数据。
- 对所有会话读写入口实施默认拒绝的所有者校验。

### 第二阶段：微信扫码绑定与社交历史接入

- 登录用户直接发起微信扫码。
- 将扫码返回的微信用户 ID 绑定到当前平台用户。
- 新社交会话登记中央目录。
- Web 端通过社交只读适配器展示历史。
- 未绑定微信消息继续使用微信侧隔离的 Agent 会话，不登记中央目录。

## 认证用户模型

`CurrentUser.from_company_payload` 增加以下兼容规则：

- 角色编码支持 `roleCodes`、`roles`、`roleList` 和 `roleCodeList`。
- 当响应中的 `admin` 是明确的布尔值 `true` 时，`is_admin` 为真。
- 配置的管理员角色码仍可将用户识别为管理员。
- 缺少 `admin`、类型异常或其他真值形式不会直接提权。

最终管理员判定为：明确的 `admin: true`，或角色编码与配置的管理员角色集合相交。

## 中央会话目录

新增 `conversation_catalog` 表：

| 字段 | 约束 | 用途 |
|---|---|---|
| `session_id` | 主键 | 全局会话 ID |
| `owner_user_id` | 非空 | 认证平台稳定用户 ID |
| `owner_username` | 非空 | 用户名展示快照 |
| `owner_display_name` | 非空 | 显示名称快照 |
| `source` | 非空枚举 | `web`、`knowledge_qa`、`social` |
| `mode` | 可空 | assistant、query、social 等模式 |
| `title` | 可空 | 会话标题或首个问题摘要 |
| `read_only_on_web` | 非空 | 社交会话为真 |
| `created_at` | 非空 | 创建时间 |
| `updated_at` | 非空 | 列表排序和分页时间 |

建立 `(owner_user_id, updated_at)` 和 `(source, updated_at)` 索引。目录是访问控制的权威来源；具体消息存储不能因为存在某个 `session_id` 而绕过目录校验。

会话创建与目录登记组成一个完整业务操作。数据库存储应使用同一事务；文件型社交存储必须先成功登记目录才允许对外暴露会话。登记失败时创建失败或回滚，不能留下可访问的孤儿会话。

## 统一访问策略

新增集中式会话访问服务，输入当前 `CurrentUser` 和 `session_id`，输出允许访问的目录记录或统一的未找到结果。

访问规则：

```text
current_user.is_admin
OR catalog.owner_user_id == current_user.id
```

普通用户列表强制使用当前用户 ID 过滤。管理员列表允许跨用户查询，并返回所有者用户名、显示名称和会话来源。

不存在的会话、目录未登记的会话和其他用户的会话都返回 `404`，避免通过状态码判断其他用户的会话是否存在。社交会话在 Web 端发生写操作时返回 `409`，明确说明该会话只读。

必须覆盖以下入口：

- 会话列表、统计和活跃会话。
- 会话详情、消息分页和恢复。
- 图表、Office 文档和 Draw.io 画板。
- 手动保存、自动保存、案例标记和删除。
- 继续对话、取消运行和 steering 输入。
- 导入、导出和过期清理。
- 知识库问答创建、续聊、历史、近期消息、归档和删除。

全局清理和跨用户导入属于管理员操作。导入的普通用户会话归属当前用户。

## 各会话来源接入

### Web ReAct

创建会话时从 `request.state.current_user` 登记目录，客户端不能提交所有者字段。客户端传入已有 `session_id` 时，必须在加载历史或建立运行锁之前完成访问校验。

### 知识库问答

新会话继续写入现有 `knowledge_conversation_sessions.user_id`，同时登记目录。客户端传入已有会话 ID 时，必须验证其 `user_id` 与目录归属一致。历史、归档和删除接口移除客户端可控的用户 ID，以当前认证用户为准。

### 社交会话

社交文件会话仍是运行真源。中央目录负责在 Web 中列出和定位它们；社交只读适配器负责将文件会话转换为 Web 恢复响应，不把 Web 输入写回社交会话。

统一列表按目录分页，再按来源批量补充摘要，避免先加载三套完整历史再合并分页。

## 微信扫码绑定

### 绑定数据

微信绑定记录保存：

- `platform_user_id`
- `platform_username`
- `platform_display_name`
- `ilink_user_id`
- `account_id`
- `status`
- `bound_at`

`platform_user_id` 和活动状态下的 `ilink_user_id` 都必须唯一。

### 扫码流程

1. 已登录用户点击“添加微信”。
2. 后端从 `CurrentUser` 读取平台用户 ID、用户名和显示名称。
3. 后端生成临时微信账号 ID 并记录扫码任务所有者。
4. 前端展示二维码并轮询当前用户自己的任务状态。
5. 微信确认接口返回 `ilink_bot_id`、`ilink_user_id` 和 Token。
6. 服务端用扫码任务中的平台身份与 `ilink_user_id` 完成绑定。
7. 同一平台用户的旧微信绑定失效，新绑定生效。
8. 前端展示认证平台用户名和绑定成功状态。

浏览器不再提交姓名、邮箱、平台用户 ID 或用户名；这些信息全部来自服务端认证上下文。现有姓名/邮箱资料页、四位绑定码、微信发送绑定码步骤及相关拦截逻辑退出新流程。

扫码任务只能由发起用户或管理员查询、刷新、完成和清理。临时账号 ID 由服务端生成，不能作为权限凭据。

### 重复绑定规则

- 同一平台用户再次扫码时，以最后一次成功确认为准，旧绑定原子失效。
- 如果新的 `ilink_user_id` 已属于另一个平台用户，拒绝绑定，不抢占对方身份。
- 多窗口同时扫码时，事务和唯一约束保证只有最终有效绑定处于活动状态。

### 微信消息路由

收到微信消息后，使用渠道、机器人账号和发送者 ID 定位有效绑定。找到平台用户绑定后，创建或加载已归属社交会话，并以平台用户 ID 登记中央目录。

未绑定微信用户使用现有 SessionMapper 创建或恢复独立微信会话并正常调用 Agent，但不写入中央目录，因此任何 Web 用户和管理员都看不到该历史。用户后续完成 Web 扫码后，旧会话因为没有目录归属而不被接管；下一条消息创建新的已归属社交会话并替换该微信身份的 SessionMapper 映射。旧会话数据保持不变，不自动归属或迁移。

## Web 展示行为

- 普通用户只看到自己的 Web、知识库和新微信会话。
- 管理员看到所有会话，并能按所有者和来源识别记录。
- 会话列表展示来源标识：Web、知识库、微信。
- 管理员列表展示所有者用户名和显示名称；普通用户不显示跨用户筛选。
- 微信历史恢复后显示只读提示，禁用输入框、保存、案例标记和其他写操作。
- 用户从只读微信历史页面发起新对话时，显式创建新的 Web 会话，不修改微信会话。

## 历史数据迁移

迁移顺序：

1. 部署管理员字段解析、目录表和新写入逻辑，但暂不强制目录访问。
2. 将 Web `sessions` 表的全部存量会话登记为管理员用户 ID `1` 所有。
3. 将知识库已有非空 `user_id` 原样登记到目录。
4. 将知识库空 `user_id` 会话设置并登记为管理员用户 ID `1` 所有。
5. 跳过旧微信用户、旧社交映射和旧社交文件会话。
6. 校验目录记录数量和来源分布后，启用强制访问控制。

迁移必须幂等，不覆盖已经存在的正确目录归属。强制模式启用后，目录缺失一律拒绝访问，不回退到旧的开放行为。

## 异常处理

- 认证响应缺少合法管理员字段时按普通用户处理。
- 扫码超时、取消或确认失败时不创建有效绑定，临时账号进入可清理状态。
- 微信身份冲突返回明确的绑定冲突错误。
- 目录写入失败时终止会话创建。
- 来源数据已删除但目录仍存在时返回 `404` 并记录一致性告警，不向普通用户暴露内部状态。
- 社交文件读取失败时返回来源不可用错误并记录日志，不把失败误报为无权限。
- 所有日志只记录用户 ID、会话 ID、来源和 Token 指纹，不记录密码、原始 Token 或微信 Token。

## 测试策略

### 认证测试

- `admin: true` 映射为管理员。
- `admin: false`、缺失值、字符串真值和异常类型不能提权。
- `roleCodeList` 被正确读取。
- 配置角色码仍可授予管理员权限。

### 会话权限矩阵

- 普通用户 A 能管理自己的会话。
- 普通用户 A 无法列出、读取、恢复、删除或续聊用户 B 的会话。
- 管理员能管理 A 和 B 的会话。
- 不存在、未登记和越权访问统一返回 `404`。
- 猜测会话 ID 无法访问消息、图表、文档、画板、取消或 steering 接口。
- 社交会话 Web 写操作返回 `409`。

### 知识库问答测试

- 新会话登记当前平台用户。
- 已有会话续聊校验原所有者。
- 历史、近期消息、归档和删除执行相同权限规则。
- 客户端不能通过查询参数伪造其他用户 ID。

### 迁移测试

- 存量 Web 会话归属管理员用户 ID `1`。
- 已有知识库用户归属保持不变。
- 空知识库用户归属管理员。
- 旧社交数据不迁移。
- 重复迁移不改变已有正确归属。

### 微信绑定测试

- 扫码任务绑定当前登录用户，忽略或拒绝客户端身份字段。
- 其他普通用户不能操作该扫码任务。
- 同一平台用户重复扫码替换旧绑定。
- 已绑定他人的微信身份不能被抢占。
- 未绑定微信消息创建或恢复隔离会话、调用 Agent，但不登记中央目录。
- 未绑定用户扫码后不接管旧会话，而是创建新的已归属会话。
- 新绑定微信消息创建归属正确的社交会话目录记录。
- 新社交历史能在 Web 中只读列出和恢复。

### 前端测试

- 添加微信流程不再出现姓名、邮箱或绑定码。
- 扫码成功显示认证平台用户信息。
- 普通用户列表只展示自己的记录。
- 管理员列表展示所有者和来源。
- 微信会话显示只读状态并禁用写操作。

## 验收标准

- 任意两个普通用户之间无法通过列表或猜测会话 ID 读取对方历史。
- 管理员账户 `ScGuanLy` 能查看和管理所有用户会话。
- 存量 Web 和无主知识库历史只对管理员可见。
- 已登录用户扫码后，无需发送绑定码即可完成微信身份绑定。
- 新微信历史出现在绑定用户的 Web 历史中，且只能只读查看。
- 未绑定微信用户可以继续微信对话，但其会话不会出现在 Web 历史中。
- 旧微信数据保持不变且不出现在统一 Web 历史中。
