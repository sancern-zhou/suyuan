# 运城市告警溯源时间线报告设计

## 目标

将运城市告警溯源报告从按资产类型组织的数据与图片汇编，改为面向业务人员的污染过程时间线。报告应清楚呈现污染如何变化、同期天气和周边区域出现了什么情况、当前应关注什么以及下一步何时采取什么行动。

本设计只调整分析组织方式和报告表达，不改变告警判定规则，不扩大对具体污染源的判断边界。

## 核心原则

1. 以运城市污染物小时监测数据作为主时间轴。
2. 时间阶段由本次实际数据动态形成，不预设必须存在的固定阶段。
3. 气象、周边城市、轨迹、火点、实况图片和预报资产按各自实际有效时次挂接到时间线。
4. 不强行对齐时间不同的资产，不根据文件名或抓取时间臆测有效时次。
5. 报告使用业务语言，不出现“证据强度”“置信度”“假设竞争”等技术化描述。
6. 不确认具体污染源，不把提示性线索写成责任归因。

## 时间轴生成

主 Agent 应先读取告警 JSON、目标城市小时数据和可用资产的时间元数据，再生成本次报告的时间阶段。候选阶段包括：

1. 告警前背景；
2. 污染开始变化；
3. 污染加速或持续阶段；
4. 告警触发时刻；
5. 告警后最新变化；
6. 未来数小时趋势。

候选阶段不是固定目录。实际数据不足以区分相邻阶段时应合并；没有告警后监测数据时不得生成“告警后变化”；没有可用预报时不得编造未来趋势。每个阶段标题必须包含实际时间点或时间范围。

## 资产时间挂接规则

### 监测数据

- 目标城市小时数据定义主时间轴及污染变化阶段。
- 周边城市小时数据按相同或最近的有效小时与目标城市对照。
- 如果目标城市与周边城市数据时次不同，正文必须直接说明时间差。

### 气象实况和图片

- 气象历史按记录时刻与污染小时值合并分析。
- 风场、雷达、能见度、降水等图片必须读取资产中可确认的有效时次。
- 图片挂接到最近的污染阶段时，应使用业务语言说明其实际时次，例如“该图反映告警前约2小时的风场情况”。
- 无法确认有效时次的图片不得用于推动时间线判断，可列入附件或“需要补充确认的信息”。

### 后向轨迹

- 必须读取轨迹受体时刻、轨迹时长和各路径时间点。
- 轨迹图放在受体时刻对应或最接近的时间阶段。
- 正文明确轨迹分析针对哪个时刻，不得把72小时路径表述为告警时刻的同步观测。

### 卫星火点

- 按卫星观测或过境时间挂接，不使用文件抓取时间代替观测时间。
- 火点只作为周边燃烧或热异常线索，并结合其时间、方向和距离进行业务提示。
- 无法确认观测时间的火点不进入时间线主判断。

### 预报资产

- 气象和空气质量预报统一放入“未来趋势”阶段。
- 必须说明起报时间、预报时效和对应的未来时间范围。
- 历史实况与未来预报不能混写在同一时间节点中。

## 时间节点写作模板

每个时间节点只回答三个业务问题：

1. 当时发生了什么：污染物、AQI及主要相关指标如何变化；
2. 同期情况如何：天气、周边城市及对应图片显示了什么；
3. 对业务意味着什么：下一时段应关注什么，是否需要扩大盯守或现场核查。

示例结构：

> **13:00—15:00：O3持续上升**  
> 运城市O3由130升至144 μg/m³，临汾、晋城和洛阳同期也呈上升趋势。14:00风场图显示运城以东南风为主，需关注东南方向周边区域变化。建议未来1—2小时继续关注O3升幅，并结合本地企业工况和走航结果判断是否扩大巡查范围。

报告可以区分观测事实与业务判断，但不得使用算法复盘、模型评分或置信度术语。

## 最终报告结构

1. **本次告警概览**：用3—5句话交代告警时间、污染物、当前状态和首要业务关注点。
2. **污染过程时间线**：报告核心章节，按实际时间阶段串联监测、气象、周边变化、轨迹和图片。
3. **当前情况与未来趋势**：总结最新监测状态，并按实际起报时间说明未来数小时变化。
4. **可能影响因素**：汇总时间线已经呈现的本地累积、区域影响、天气条件、光化学生成或燃烧线索，不重复堆放资产。
5. **现场行动安排**：行动必须与时间线变化对应，包含执行时段、关注方向、现场动作、补充数据和升级条件。
6. **需要补充确认的信息**：说明缺失或时间无法对应的数据会影响哪些业务判断。
7. **附件与数据来源**：列出实际使用的文件及其有效时间或时间范围。

原“关键变化看板”和“天气与传输影响”不再作为相互割裂的主体章节，其内容拆入对应时间节点。必要的趋势表格可以保留在时间线内。

## 图片编排

- 图片紧跟其对应的时间节点出现，不集中形成图片陈列章节。
- 只选取能解释该节点变化或支持下一步行动的图片，不要求为了覆盖资产而插入全部图片。
- 每张图片的图注说明三个要素：有效时次、图上主要情况、对现场关注的意义。
- 没有明确时间或与本次过程无直接关系的图片不进入正文。

## 专家草稿职责

### 常规分析专家

- 先建立目标城市污染物小时变化表和候选阶段。
- 将周边城市、火点和空气质量预报按实际时间并入候选阶段。
- 草稿按时间顺序输出，不再按资产类型分别罗列结论。
- 为每个阶段给出污染变化、周边情况和业务关注点。

### 气象分析专家

- 为所有使用的气象记录、图片和轨迹提取有效时次。
- 按常规分析专家所需的时间阶段提供同期气象情况；无法得到阶段信息时，按实际时次顺序输出，供主 Agent 挂接。
- 明确实况、轨迹受体时刻和预报时效，禁止混写。
- 图片建议必须包含有效时次和适合挂接的时间节点。

### 主 Agent

- 以目标城市监测数据确定最终时间线。
- 将两个专家草稿按时次合并，处理时间不一致、缺失和重复内容。
- 确保每个节点形成“变化—同期情况—业务意义”的连续叙事。
- 删除技术化证据评级和单纯资产罗列。

## 异常与缺失处理

- 缺少目标城市小时数据时，不能生成完整时间线，任务应返回失败并说明原因。
- 缺少部分气象、周边或图片资产时，时间线仍可生成，但在对应节点或“需要补充确认的信息”中说明影响。
- 资产时间晚于报告生成时间、时间字段无法解析或时间范围明显冲突时，不得静默采用，应排除出主判断并记录原因。
- 告警触发时间与城市小时数据末端不一致时，按各自真实时间呈现，并说明当前城市数据更新到何时。

## 验收标准

1. 时间线章节是报告篇幅最大的主体章节。
2. 每个时间节点包含明确的实际时间点或时间范围。
3. 每个节点至少说明污染变化和业务意义；存在同期资产时一并说明。
4. 正文使用的每张图片均标明有效时次并挂接到具体节点。
5. 实况、轨迹和预报的时间口径清楚，不强行同步。
6. 报告中不出现“证据强度”“置信度”“假设竞争”等技术术语。
7. “可能影响因素”来源于前述时间线，不新增没有时间依据的结论。
8. 现场行动具有明确执行时段，并能对应时间线中观察到的变化。
9. 缺失或无法确认时次的资产不会被用于主判断。
10. 保持“不确认具体污染源、不重新判断告警是否成立”的现有业务边界。

## 测试范围

- Skill 发布测试检查时间线主导结构、资产时次挂接规则和业务语言约束。
- 专家 Skill 测试检查草稿是否按时间顺序输出，并包含资产有效时次。
- 报告样例测试检查章节顺序、节点时间、图片时次和行动时段。
- 使用时间不一致、图片无时次、缺少告警后数据和缺少预报等样例验证降级行为。
