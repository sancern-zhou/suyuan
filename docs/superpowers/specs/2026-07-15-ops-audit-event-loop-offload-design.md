# 运维工单审核事件循环卸载设计

## 背景与根因

系统级 SSE 已通过 `EventSourceResponse` 每 15 秒发送透明注释心跳。实际运行中，`OpsAuditRunRulesTool.execute()` 虽然是异步函数，却直接调用同步的 `run_ops_audit_rules()`。视觉审核会在该调用中同步等待数百项任务完成，使当前 Uvicorn worker 的 asyncio 事件循环长时间无法调度。

因此同一事件循环上的 SSE 心跳和断连监听都无法运行。Nginx 在最后一个业务帧之后等待 600 秒，最终以 `upstream timed out while reading upstream` 关闭连接。其他 worker 仍可响应健康检查，不能证明承载审核请求的 worker 没有阻塞。

## 方案

仅修改 `OpsAuditRunRulesTool.execute()`：通过 `asyncio.to_thread()` 在线程中执行 `run_ops_audit_rules()`，异步等待其结果。数据保存、结果标准化和异常转换仍在原协程中执行，不修改 SSE 工厂、Agent 事件协议、前端解析逻辑或 Nginx 超时。

该修改修复的是阻塞型工具违反异步执行约定的问题，而不是向工单审核业务事件中加入心跳。心跳仍由系统级 SSE 传输层独立产生。

## 数据流

1. Agent 调用 `ops_audit_run_rules`。
2. 工具协程把同步规则引擎提交给 asyncio 默认线程池。
3. Uvicorn 事件循环保持可调度，SSE 心跳、断连监听及其他异步请求可以继续运行。
4. 规则引擎完成后，结果返回工具协程。
5. 工具按现有逻辑保存摘要数据并返回 Agent。

## 取消与错误语义

- 同步规则引擎抛出的异常会通过 `await asyncio.to_thread(...)` 回到工具现有异常处理逻辑，外部错误契约不变。
- 客户端断开会及时取消 Agent/SSE 协程，但 Python 线程中的同步审核不能被安全地强制终止，可能继续运行至当前审核完成。这是方案 1 的已知限制。
- 本次不引入任务队列、进程隔离或可中断规则引擎；这些属于后续架构增强。

## 测试与验收

- 新增回归测试，用阻塞替身模拟规则引擎，并断言工具运行期间 asyncio 事件循环仍能执行独立协程。
- 断言工具参数和返回结果保持不变。
- 运行工单审核工具测试、SSE 聚焦测试和 API 测试。
- 线上验收时，Nginx 日志不再出现该审核请求的 600 秒 upstream read timeout，浏览器连接中可持续收到透明心跳。

## 非目标

- 不修改 600 秒 Nginx 超时。
- 不把心跳写入 Agent 消息、会话历史或审核进度事件。
- 不统一改造其他工具的执行模型。
- 不承诺客户端断开后立即终止已进入线程的同步审核。
