# 多点曲线视觉审核设计

## 目标

为季度气态多点校准表增加附件视觉审核，只核对一个核心问题：多点曲线图片中呈现的浓度梯度是否与 RF 表单填写的多点校准浓度一致。

第一期不审核站点名称、站点编号、作业时间、平台持续时长、单点仪器照片、校准偏差是否合格，也不要求视觉模型精确提取每个平台的数值。

## 适用范围

适用于以下 RF 表：

- `RF_Q_GASEOUSMULTIPOINT_CO`
- `RF_Q_GASEOUSMULTIPOINT_NO2`
- `RF_Q_GASEOUSMULTIPOINT_O3`
- `RF_Q_GASEOUSMULTIPOINT_SO2`

每个 RF 表按工单编号和污染物独立审核。表单浓度来自有效的 `MCLBZ10`、`MCLBZ20`、`MCLBZ40`、`MCLBZ60`、`MCLBZ80` 字段；必要时将零点作为辅助上下文，但不因缺少零点单独判问题。

## 历史附件特征

历史工单中存在两种主要附件组织方式：

1. 单张“梯度图”“多点曲线”或类似名称的曲线截图。
2. 多张按浓度命名的仪器屏幕照片，另附曲线图或结果图。

本期只审核曲线图片。候选附件通过 RF `TYPECODE`、文件名关键词和图片格式共同筛选，不把单点仪器照片误当成曲线。

历史曲线既可能按浓度升序，也可能按浓度降序，因此升降方向本身不作为问题。审核关注平台数量、明显梯度以及平台相对量级与表单浓度是否一致。

## 审核方式

采用“表单事实 + 原始图片 + 受约束提示词”的多模态直接判断，不实现复杂的曲线像素分析、平台聚类或坐标换算。

发送给多模态模型的业务上下文包括：

- 污染物类型；
- 浓度单位；
- RF 表单有效浓度点序列；
- 曲线图片文件名；
- 曲线图片原图。

提示词要求模型：

1. 判断图片是否为目标污染物的有效多点校准曲线。
2. 判断图片是否存在多个清晰、持续的平台或梯度段。
3. 判断平台数量、顺序和相对量级是否能反映表单浓度序列。
4. 允许曲线升序或降序，允许轻微波动、拍摄倾斜、摩尔纹和坐标刻度不清。
5. 不强制输出精确平台浓度，不输出人为构造的置信度。
6. 证据不足时必须返回资料不足，不能猜测为无问题。

## 模型输出协议

模型必须返回结构化 JSON：

```json
{
  "result": "PASS | ISSUE_REVIEW | INSUFFICIENT_EVIDENCE",
  "reason_code": "NONE | GRADIENT_MISMATCH | POINT_COUNT_MISMATCH | NO_CLEAR_GRADIENT | POLLUTANT_MISMATCH | NOT_MULTIPOINT_CURVE | CURVE_INCOMPLETE | IMAGE_UNREADABLE",
  "reason": "简明、可供报告使用的中文原因",
  "observed_summary": "图片中实际看到的平台、梯度或资料不足情况"
}
```

状态含义：

- `PASS`：图片梯度与表单浓度一致，不进入报告。
- `ISSUE_REVIEW`：模型明确发现不一致，进入“疑似问题待人工复核”。
- `INSUFFICIENT_EVIDENCE`：图片无法支持判断，进入“资料不足待人工复核”。

不使用模型自报置信度作为分流条件。

## 多附件处理

同一工单、同一污染物可能存在多张候选曲线图片：

- 任一候选图片明确返回 `ISSUE_REVIEW`，生成疑似问题项，并保留该图片证据。
- 没有疑似问题，但所有候选图片均为 `INSUFFICIENT_EVIDENCE`，生成资料不足项。
- 至少一张候选图片返回 `PASS`，且没有图片明确返回 `ISSUE_REVIEW`，视为通过。
- 没有曲线候选图片，生成资料不足项，原因码为 `NOT_MULTIPOINT_CURVE`。

以上策略避免一张模糊的重复附件覆盖一张可正常确认的曲线，也避免明确不一致被另一张无关图片抵消。

## 问题与报告数据

新增视觉审核规则 `ATTACHMENT_MULTIPOINT_GRADIENT_REVIEW`。进入报告的每个问题项至少包含：

- 工单编号；
- 站点 ID 和站点名称（数据集可用时）；
- RF 表名；
- 污染物；
- 表单浓度序列及单位；
- 报告分类：`疑似问题待人工复核` 或 `资料不足待人工复核`；
- 原因码、原因说明和模型观察摘要；
- 附件文件名；
- 审核时使用的本地图片绝对路径；
- 原始附件路径和原始 URL；
- `needs_manual_review: true`。

远程附件在视觉审核前下载到本次审核输出目录下的证据子目录。最终问题清单必须引用该持久化本地文件，不能引用临时目录，以便报告生成器直接插图。

## 失败处理

- 附件下载失败、文件损坏、模型调用失败、JSON 无法解析：生成 `INSUFFICIENT_EVIDENCE`，不得静默通过。
- 表单没有足够有效浓度点：不调用视觉模型，生成资料不足项并说明表单浓度数据不足。
- 视觉审核关闭时不运行本规则，也不生成视觉资料不足问题。
- 模型原始响应保存为审核证据，结构化结果只接受协议内的枚举值。

## 测试要求

测试采用 TDD，至少覆盖：

1. 正常升序梯度返回通过。
2. 正常降序梯度返回通过。
3. 平台数量明显不符进入疑似问题待复核。
4. 无明显梯度进入疑似问题待复核。
5. 图片模糊进入资料不足待复核。
6. 没有曲线候选附件进入资料不足待复核。
7. 多附件中一张通过、一张资料不足时整体通过。
8. 多附件中存在明确问题时生成疑似问题。
9. 问题证据包含持久化本地图片路径、原始路径和 URL。
10. 关闭视觉审核时不产生本规则问题。

## 非目标

以下内容留待后续单独设计：

- 站点名称或编号识别与一致性；
- 曲线作业时间与 RF 时间一致性；
- 单点仪器屏幕读数与 `MCLXY*` 精确比较；
- 曲线平台持续时间和稳定性指标；
- 校准结果偏差或线性是否符合技术标准；
- “无需校准”与“校准后读数”的条件联动；
- O3 上级标准型号、设备号的一致性。
