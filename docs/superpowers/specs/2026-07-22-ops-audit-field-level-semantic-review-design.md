# 运维审核字段级语义复核修复设计

## 背景

工单 `CH2607081783471194919` 的 NOx 周检记录中，`PMTCHECKVALUE=0.001`，对应字段说明 `PMTCHECKROW=厂家备案参数0-4.096V`。现有通用配置使用 FPI 范围 `1.5-4.096V`，确定性审核产生范围异常候选；字段说明虽进入语义上下文，但自动清除逻辑未识别“厂家备案参数”，随后工单级语义任务将 NOx、SO2 等多个异常混合审核，最终形成误报。

## 目标

1. 将“厂家备案参数”等字段级厂家范围说明识别为范围配置差异证据。
2. 将通用备注语义审核从每工单一个结论改为每个具体异常项一个结论。
3. 通过稳定的 `review_item_id` 将语义结论精确映射回原始问题，避免同规则的多个 RF 表或字段互相污染。
4. 保持现有专用批处理（纸带、无设备、附件文件名、主表描述）行为不变。

## 非目标

- 本次不新增语义结果后置校验或模型输出矛盾拦截。
- 本次不直接修改 FPI 通用正常范围；型号专属范围需另行完成业务口径确认。
- 本次不扩大到附件 OCR 内容校验。

## 设计

### 1. 确定性字段说明识别

扩展字段级范围说明识别，使“厂家备案参数”“厂家备案范围”等表达与现有“厂家参数”“厂家实际参数”一致。命中后继续沿用现有确定性清除路径，不再调用通用备注模型。

该清除仅表示字段说明足以解释“通用配置范围与现场设备范围不同”的候选，不修改全局范围配置。

### 2. 通用语义任务拆分

`RF_ABNORMAL_VALUE_NO_REMARK` 等通用备注候选按原始问题拆分。每项至少携带：

- `review_item_id`
- `working_order_code`
- `rule_id`
- `rf_table`
- `field`
- `message`
- 解析后的 `evidence`
- 当前字段相关的 `remark_candidates`
- 精简后的工单与 RF 上下文

`review_item_id` 由工单号、规则、RF 表、字段及稳定序号组成，保证同一工单同一规则的多项问题可以分别返回结果。

### 3. 上下文组装

通用备注模型输入以当前问题为中心，不再把整张工单所有 RF 表文本作为主要证据。字段级说明（如 `PMTCHECKROW`）和表单总备注分别标注；必要的工单标题、流程备注作为辅助上下文。

提示词明确：对于范围异常，必须优先检查当前字段的 `remark_candidates`。厂家备案或厂家实际范围能够解释候选时，不套用故障闭环的原因、措施、结果三要素。

### 4. 结果与最终问题映射

批量模型按 `review_item_id` 返回逐项结论。语义结果保留具体原始问题引用；最终问题组装直接使用该引用，不再按 `rule_id` 从 `sample_issues` 中选择第一条问题。

同一工单可以同时存在已清除和已确认的语义项，互不覆盖。

## 错误处理

模型批次失败或缺少某个 `review_item_id` 时，该项沿用现有待人工确认降级语义，不借用同工单其他项的结果。

## 测试

1. “厂家备案参数0-4.096V”能够触发现有确定性清除路径。
2. 同一工单的 NOx 与 SO2 异常生成不同 `review_item_id`。
3. 一个异常清除、另一个异常确认时，最终问题只包含被确认的具体异常。
4. 最终问题保留正确的 RF 表、字段、原始消息和证据。
5. 现有纸带、无设备等专用语义审核测试继续通过。
