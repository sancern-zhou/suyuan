# Draw.io Agent 完成上下文优化设计

## 背景

图表模式中，`create_drawio_board` 已成功生成并交付画板后，Agent 仍可能继续调用该工具。日志显示下一次 ReAct iteration 会在已有 `tool_result` 后追加空的 `user` 消息，同时工具成功摘要只表达“已生成”，没有说明交付状态和条件式下一步。这使 LLM 更容易把任务理解为仍需继续编辑。

## 目标

在不增加系统级终止、不隐藏工具、不改变 XML 上下文注入策略、也不新增 `llm_resume` 字段的前提下，让 LLM 基于清晰的消息结构和工具摘要自主决定结束并回复用户。

## 设计

### 1. 工具续接不追加空用户消息

Planner 组装 Anthropic messages 时：

- `user_conversation` 非空时，保持现状，追加当前 `user` 消息。
- `user_conversation` 为空且历史已存在时，直接使用 `conversation_history`，不追加 `{"role": "user", "content": ""}`。
- 首次请求没有历史时，仍允许追加当前用户消息；正常情况下该内容非空。

这样工具链保持标准结尾：`assistant/tool_use -> user/tool_result`，LLM 服务能够正确识别同一次工具续接。

非流式与流式 Planner 使用相同规则，避免两条执行路径行为不一致。

### 2. 强化 Draw.io 工具摘要

不让工具判断整个用户任务是否完成，只陈述本次画板调用的局部事实，并给出条件式下一步：

- 创建成功：说明画板已生成并返回前端；若用户没有其他明确修改要求，应直接回复，不要重复调用。
- 编辑成功且有变化：说明修改已返回前端；若用户要求均已满足，应直接回复，不要继续调用。
- 编辑成功但无变化：说明目标已是期望值；应直接回复，不要再次提交相同或等价操作。
- 执行失败：保留具体错误和修正后重试语义，不增加结束提示。

摘要仍使用现有 `summary` 字段，不增加新的结果字段。

## 非目标

- 不设置 `state.task_completed`。
- 不在运行时隐藏或阻断 `create_drawio_board`。
- 不修改工具循环保护器。
- 不修改完整 XML 或 `board_context` 的注入行为。
- 不新增或依赖 `llm_resume`。
- 不阻止一个用户请求中确有必要的多次编辑。

## 测试

1. Planner 流式路径：历史以 `tool_result` 结束且 `user_conversation` 为空时，请求消息不包含额外空用户消息。
2. Planner 非流式路径：验证同样行为。
3. Planner 首次请求：没有历史且用户内容非空时仍正确追加用户消息。
4. Draw.io 创建成功摘要包含“已返回前端”和条件式直接回复提示。
5. Draw.io 编辑有变化摘要包含交付状态和条件式直接回复提示。
6. Draw.io 编辑无变化摘要明确禁止相同或等价重试。
7. Draw.io 失败摘要继续引导修正后重试。

## 成功标准

- 下一次工具续接请求最后一条消息是实际 `tool_result`，而不是空用户消息。
- Mimo/DeepSeek 的工具续接识别不再被空用户消息破坏。
- LLM 能从 `summary` 判断画板已经交付，并在没有未满足要求时主动回复用户。
- 现有失败重试和明确的连续编辑能力不受影响。
