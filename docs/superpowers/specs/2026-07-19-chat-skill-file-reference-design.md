# 对话输入框技能与文件引用设计

## 背景

当前主对话输入框把 `@` 用于选择“标准分析”和“知识问答”工作流。其中“标准分析”对应的后端工作流已经删除，而且把工作流、上下文和底层工具混在同一个入口中，不利于用户理解，也无法可靠地向后端表达选择结果。

本设计重新定义输入框中的两个快捷入口：

- `/` 选择本轮采用的技能；
- `@` 引用当前对话中的文件；
- 工具不直接暴露给用户，由 Agent 在当前模式的工具白名单内自动选择。

本次改造是协议级切换，不兼容旧输入协议或旧会话草稿。

## 目标

1. 让用户明确表达本轮采用的方法和需要引用的文件。
2. 将技能、上下文资源和底层工具分成独立概念。
3. 使用结构化字段向后端传递选择，不依赖 prompt 文本解析。
4. 同时支持用户上传文件和 Agent 生成文件。
5. 保持现有模式工具权限边界，技能不能绕过工具白名单。
6. 为中文输入法、键盘操作、重名文件和失效资源提供确定行为。

## 非目标

- 不允许用户从输入框指定或优先选择底层工具。
- 不在本次改造中自动切换 Agent 模式。
- 不支持同一轮选择多个技能。
- 不迁移旧草稿中的 `/技能` 或 `@文件名` 文本。
- 不解析或兼容旧的 `@标准分析`、`@知识问答`输入。
- 不提供跨会话文件搜索。

## 概念与语义

### 技能

技能描述“如何完成任务”，是一套可复用的方法、流程和约束。技能目录对所有用户模式通用，但技能能否在当前模式执行取决于其所需能力。

- 用户未选择技能时，Agent 按现有方式直接处理请求；不强制为简单请求自动加载技能。
- 用户选择技能时，本轮必须加载并遵循该技能。
- 每轮最多选择一个技能；新选择替换旧选择。
- 技能不能扩大用户权限，也不能绕过当前模式的工具白名单和风险确认。

技能元数据至少需要提供：

```json
{
  "id": "trend_analysis",
  "name": "趋势分析",
  "description": "比较时序数据并总结变化趋势",
  "aliases": ["趋势", "时序分析"],
  "required_tools": ["read_file"],
  "optional_tools": ["generate_chart"]
}
```

`required_tools` 用于发送前兼容性校验，`optional_tools` 只用于说明增强能力，缺失时不阻止发送。

### 对话文件

对话文件是当前用户在当前会话中可访问的文件资源，包括：

- 用户上传的文件和图片；
- Agent 生成的报告、表格、图片和图表文件；
- 画板导出的文件或快照；
- 工具运行产生且已登记到会话资源清单的文件。

文件必须已经登记为会话资源。临时路径、未经登记的工具输出和纯外部 URL 不进入候选列表。

### 工具

工具是 Agent 的内部执行能力，不在输入框中提供选择器。后端继续根据 Agent 模式生成工具白名单，Agent 根据自然语言、所选技能和文件上下文自行决定调用哪些工具。

## 输入框交互

### 选择结果展示

输入框在正文编辑区上方提供一个选择标签栏：

- 技能标签位于最前面，使用 `/技能名称`展示；
- 文件标签使用 `@文件名`展示；
- 每个标签都有移除按钮；
- 标签是不可拆分的结构化组件，不属于 `query` 文本。

采用独立标签栏而不是在 textarea 内模拟富文本标签，以避免光标、复制粘贴和中文输入法在 `contenteditable` 中产生不稳定行为。用户选中候选项后，触发字符和当前搜索片段从正文中删除，并在标签栏新增结构化选择。

### `/` 技能选择器

- `/` 仅在正文行首，或者前一个字符为空格、制表符或换行时触发。
- 候选项支持按技能名称、别名和说明搜索。
- 每项展示技能名称、简短用途和当前模式兼容状态。
- 当前模式缺少必需工具的技能仍然可见，但标记为不可用，不能完成选择。
- 选择技能后关闭候选框，并创建或替换技能标签。
- 删除技能标签不会删除或修改技能本身。

### `@` 文件选择器

- `@` 采用与 `/` 相同的触发位置规则。
- 候选范围仅限当前会话中有效且有权访问的文件。
- 文件支持按名称和扩展名搜索。
- 候选项按“最近使用”“用户上传”“Agent 生成”分组。
- 每项展示文件图标、名称、来源、来源消息轮次；出现重名时额外展示创建或上传时间。
- 支持选择多个文件；已经选择的文件显示勾选状态并且不能重复添加。
- 删除文件标签只解除本轮引用，不删除会话文件。

### 新文件上传

`+` 或现有上传按钮继续负责添加新文件。上传成功并完成会话资源登记后，文件自动成为本轮已选文件，同时进入后续 `@` 候选列表。

### 键盘和输入法

- `ArrowUp`、`ArrowDown`：移动候选高亮；
- `Enter`：候选框打开时选择高亮项，否则发送；
- `Escape`：关闭候选框；
- `Shift+Enter`：换行；
- 标签获得焦点时，`Backspace` 或 `Delete` 移除整个标签；
- `compositionstart` 到 `compositionend` 期间不触发选择、关闭或发送；
- 鼠标选择候选项时保持编辑区焦点。

## 请求协议

所有新请求必须显式提交 `skill_ids` 和 `context_refs`，没有选择时传空数组。客户端不再把展示标签拼入 `query`。

```json
{
  "query": "对比两个月的数据并生成趋势结论",
  "skill_ids": ["trend_analysis"],
  "context_refs": [
    {
      "type": "conversation_file",
      "resource_id": "file_123",
      "display_name": "六月监测数据.xlsx"
    },
    {
      "type": "conversation_file",
      "resource_id": "artifact_456",
      "display_name": "七月监测数据.xlsx"
    }
  ],
  "agent_mode": "query",
  "model_tier": "auto"
}
```

协议约束：

- `skill_ids` 必须是数组，长度为零或一；
- `context_refs` 必须是数组，允许多个引用；
- 第一版只接受 `type = conversation_file`；
- `resource_id` 是授权和解析依据；
- `display_name` 只用于展示和审计，不能用于定位文件；
- `query` 允许为空，只要 `skill_ids` 或 `context_refs` 至少有一项；
- `query`、`skill_ids`、`context_refs` 全部为空时禁止发送；
- 消息请求不再接受 `attachments`。上传接口必须先把新文件登记为会话资源，消息请求随后通过 `context_refs` 引用该资源。

这是破坏性协议升级。前后端必须同步发布，不保留旧字段缺失时的降级逻辑，也不从 `query` 中解析技能或文件引用。

## 数据流

1. 输入框加载全局已启用技能目录，以及当前会话资源清单。
2. 当前模式改变时，前端根据后端提供的模式能力重新计算技能兼容状态。
3. 用户通过 `/` 选择一个技能，通过 `@` 选择一个或多个会话文件。
4. 前端在发送前重新校验技能状态、上传状态和资源有效性。
5. 后端验证技能存在且启用，并验证 `skill_ids` 数量。
6. 后端验证每个 `resource_id` 属于当前用户和当前会话，解析为 Agent 会话资源引用。
7. 后端用当前模式工具白名单校验技能的 `required_tools`。
8. 校验通过后，运行时加载技能内容，将资源清单加入 Agent 上下文，并由 Agent 自动选择工具。
9. 发送成功后清空正文、本轮技能选择和文件选择；失败时全部保留。

## 模式与技能冲突

技能目录本身全模式通用，但执行能力受模式限制。

- 若当前模式包含全部 `required_tools`，技能可选并可发送；
- 若缺少任一必需工具，技能候选显示不可用状态；
- 若模式在选择后发生变化并导致技能不再兼容，保留标签但标红，阻止发送；
- 错误信息列出缺失能力和可执行该技能的模式；
- 系统不自动切换模式，避免改变会话工作空间和运行状态；
- `optional_tools` 缺失不阻止执行；Agent 使用当前模式内的可用替代方案。

## 文件状态与错误处理

### 上传或生成处理中

处理中资源显示进度状态，并暂时禁用发送。成功后转换为普通文件标签；失败后标记失败并允许用户移除或重试。

### 文件失效

文件被删除、过期、权限撤销或资源登记丢失时：

- 对应标签标红；
- 发送前阻止请求；
- 明确指出失效文件；
- 保留正文、技能和其他有效文件引用。

### 请求失败

网络错误、服务错误或发送前校验错误都不得清空输入框状态。只有服务端接受请求并返回已创建任务或已开始流式响应的确认后，客户端才清空本轮内容。

### 会话切换

选择项属于当前会话草稿。切换会话时保存当前会话的正文、技能 ID 和资源 ID；恢复时重新校验技能与文件。旧格式草稿不迁移，旧的 `/`、`@`纯文本保持普通文本。

## 安全与权限

- 后端不能信任客户端提交的技能兼容状态；必须重新校验技能启用状态和模式工具白名单。
- 后端不能根据文件名、客户端路径或 URL 读取文件；必须通过 `resource_id` 和会话资源清单解析。
- 每个资源必须同时满足用户所有权或共享权限、会话归属和未失效条件。
- 技能只能约束规划流程，不能授权工具、外部写操作或高风险动作。
- Agent 生成文件只有在成功登记到会话资源清单后才能再次引用。

## 测试策略

### 前端单元测试

- `/` 和 `@` 的触发边界、搜索片段和关闭行为；
- 技能单选替换、文件多选去重和标签移除；
- 上传文件与 Agent 生成文件的分组、排序和重名展示；
- 中文输入法组合期间不会误选或误发送；
- 候选框打开时 Enter 选择，关闭时 Enter 发送；
- 空正文但存在技能或文件时可发送；完全空请求不可发送；
- 失效、处理中或模式不兼容状态阻止发送；
- 请求失败保留草稿，请求被接受后清空草稿。

### 后端单元测试

- 请求模型要求显式提供两个数组，并限制技能数量；
- 技能不存在、未启用或依赖工具不足时拒绝请求；
- 文件跨用户、跨会话、已删除或已过期时拒绝请求；
- `display_name` 不能影响实际资源解析；
- 技能加载结果和资源引用正确进入 Agent 上下文；
- Agent 仍只能看到当前模式的工具白名单。

### 集成测试

- 上传文件后立即通过标签发送；
- 下一轮使用 `@` 再次引用已上传文件；
- 引用 Agent 生成的报告、表格、图片和画板导出文件；
- 切换模式后技能从可用变为不可用；
- 前端提交结构化选择，服务端持久化并在恢复草稿时重新校验；
- 前后端均不解析旧的 `@标准分析`和`@知识问答`文本。

## 发布与清理

前后端作为同一版本发布。上线时完成以下清理：

1. 删除 `InputBox.vue` 中旧工作流候选列表和 `@` 工作流插入逻辑；
2. 删除未被使用的旧工作流选择组件；
3. 更新请求模型、会话草稿模型和发送调用链，要求结构化字段；
4. 为技能目录补齐依赖工具元数据；
5. 确保所有上传和生成文件都登记到会话资源清单；
6. 更新前后端测试，明确旧协议不再接受。

发布不包含旧草稿迁移或双协议灰度期，因此必须避免前端和后端版本错配。
