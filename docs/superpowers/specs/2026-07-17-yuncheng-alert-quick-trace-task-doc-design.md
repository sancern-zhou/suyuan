# 运城告警快速溯源定时任务文档设计

## 1. 编写目标

为业务人员编写一份运城市小时告警快速溯源定时任务说明，使读者能够理解任务何时运行、如何判断告警、告警后准备哪些资料、如何完成专业研判、形成哪些报告，以及异常情况下系统如何处理。

## 2. 目标读者

- 驻场业务人员
- 业务管理人员
- 项目负责人
- 需要了解告警处置闭环的业主代表

文档使用业务语言，不展开代码类名、接口定义和数据库实现细节。必要的任务名称、状态名称和文件名称只用于帮助定位业务成果。

## 3. 文档范围

文档仅描述当前运城市驻场试用场景的正式链路：

1. 每小时整点检查运城市城市级空气质量数据。
2. 根据快速上升、AQI 污染水平和连续高值规则判断告警。
3. 无论是否告警均保存本轮判断证据。
4. 有告警时抓取监测、周边城市、气象、轨迹、火点和预报资料。
5. 由溯源分析 Skill 组织常规监测专家、气象专家和主助手完成研判。
6. 生成 Quarto 源报告、Word 报告和微信摘要。
7. 由事件任务服务完成微信正文及附件投递。

不扩展介绍济宁每日快速溯源 Fetcher，也不把早期“社交模式定时扫描最新证据目录”的旧链路作为现行流程。

## 4. 文档结构

正式文档保存为：

`backend/app/scenarios/yuncheng_trial/运城告警快速溯源定时任务说明.md`

正文包含以下部分：

1. 文档用途与业务目标。
2. 任务概览和 Mermaid 主流程图。
3. 每小时数据检查及告警判断规则。
4. 无告警与有告警的分支处理。
5. 告警后溯源资料抓取清单。
6. 溯源分析 Skill 的双专家协作和主助手审核流程。
7. 报告生成、验收和微信投递。
8. 证据目录及主要交付物。
9. 数据缺失、任务失败、重复事件等异常处理。
10. 业务结论边界和驻场使用建议。

## 5. 表达方式

- 开头先给出端到端流程图，让业务读者快速建立整体认识。
- 告警阈值使用表格集中呈现，并区分“可触发告警的主规则”和“仅用于研判的辅助线索”。
- 数据抓取按业务用途分类，说明每类资料要回答的问题。
- Skill 分析流程强调角色职责和审核关系，不描述底层 Agent 调用协议。
- 报告环节明确 `report.qmd`、`report.docx`、微信摘要和证据目录的关系。
- 异常处理采用“出现什么情况—系统如何处理—业务影响”的表格。
- 对轨迹、风场和火点等资料统一使用提示性表述，避免确定性归因。

## 7. 验收标准

- 业务人员不阅读代码即可说明完整处理闭环。
- 明确任务频率、12 小时默认回看窗口和告警阈值。
- 明确无告警静默、有告警才抓取上下文并触发分析。
- 覆盖监测、周边城市、气象、轨迹、火点和预报资料。
- 清楚说明常规监测专家、气象专家和主助手的分工。
- 明确报告源文件、Word 附件、微信摘要及证据留存位置。
- 明确数据缺失可降级继续、报告失败不推送、重复事件不重复执行等处理原则。
- 明确当前未接入站点小时数据及本地污染源数据，结论只能用于提示性研判。
- 文档中不存在未完成的占位内容、未解释缩写或相互矛盾的口径。
