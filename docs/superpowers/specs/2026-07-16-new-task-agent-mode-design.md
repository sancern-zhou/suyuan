# 新建任务智能体模式设计

## 目标

取消用户在未选择智能体时点击“新建任务”的阻断提示，并根据当前工作区决定新任务使用的智能体模式。

## 行为规则

### 智能体平台选择页

用户尚未进入某个智能体对话，或已从对话页返回智能体平台时，点击“新建任务”：

- 不显示“请先选择一个智能体”的提示。
- 明确切换到 `assistant` 模式，不使用本地持久化的历史模式。
- 重置通用助手当前会话，创建空白对话工作区。
- 关闭管理面板并重置右侧面板状态。

### 智能体对话页

用户已选择智能体并处于对话页时，点击“新建任务”：

- 保持 `store.currentMode` 不变。
- 重置该模式的当前会话并进入空白对话。
- 关闭管理面板并重置右侧面板状态。

### 返回智能体平台后

用户从专家、报告、图表、问数、运维或通用助手对话返回智能体平台后，平台页不再视为已选择智能体。此时点击“新建任务”统一进入通用助手模式。

## 实现方案

在 `ReactAnalysisView.vue` 的 `handleSidebarAction` 中，在修改 `workspace` 前记录点击动作发生时的工作区：

- 当 `actionId === 'restart-session'` 且原工作区为 `platform`，目标模式为 `assistant`。
- 当原工作区为 `chat`，目标模式为当前 `store.currentMode`。
- 删除原有平台页错误提示和提前返回逻辑。
- 在 `restart-session` 分支中，仅当目标模式不同于当前模式时调用现有 `store.switchMode`，随后调用 `store.restart()`。
- 沿用既有的 `hideManagementPanel()` 和 `resetPanelState()`，不修改 store 的重置语义。

## 不包含

- 不改变智能体卡片选择逻辑。
- 不改变历史会话恢复逻辑。
- 不改变“智能体平台”按钮返回选择页的行为。
- 不引入“最近选择智能体”或新的本地持久化字段。
- 不修改后台会话 API。

## 测试与验收

- 源码回归测试确认旧提示文字已删除。
- 测试确认平台页的新建任务路径显式使用 `assistant`。
- 测试确认对话页的新建任务路径沿用 `store.currentMode`。
- standalone 构建后实际验证：
  - 首次进入平台点击新建任务，显示通用助手欢迎内容。
  - 选择专家智能体后点击新建任务，仍显示专家智能体欢迎内容。
  - 专家对话返回平台后点击新建任务，显示通用助手欢迎内容。
