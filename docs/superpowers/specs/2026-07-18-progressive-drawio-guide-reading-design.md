# 画板设计文档渐进读取约束

## 背景

画板工作流文档已经维护了不同图形类型到专项设计文档的映射，但画板系统提示词没有把“先识别类型、再读取匹配文档、最后绘制”声明为工具调用前置条件。Agent 因此可能直接生成 XML，或者一次性读取全部设计文档，既降低设计质量，也浪费上下文。

## 目标

在画板系统提示词和 `create_drawio_board` 工具说明中建立一致的渐进读取协议：Agent 根据实际绘制需求只读取必要的 Markdown 设计规范，并在完成必要阅读后才生成或大幅重构画板。

## 渐进读取协议

### 第一阶段：基础规范

首次执行本轮实质性画板任务前，读取：

1. `app/agent/guides/drawio_board_workflow.md`
2. `app/agent/guides/drawio_xml_rules.md`
3. `app/agent/guides/drawio_edit_policy.md`

基础规范用于确认权威 XML、编辑策略、合法 XML 结构和专项文档路由。

### 第二阶段：按图形类型读取专项规范

Agent 先判断用户主诉对应的主要图形类型，再依据工作流路由读取最匹配的专项文档。单一类型只读取一份；确实同时包含两种主要表达结构时最多读取两份。禁止为了保险无差别读取整个 `drawio_patterns` 目录。

如果需求类型不明确，Agent 应先依据用户的主要信息关系选择最接近的类型；必要时可通过澄清用户意图解决，而不是读取所有文档。

### 第三阶段：绘制与质量闭环

完成必要阅读后，Agent 才能调用 `create_drawio_board` 新建、大幅重构或进行结构性编辑。生成候选后继续执行既有的校验、截图、视觉复核、最多两轮修正和显式接受流程。

## 局部编辑例外

仅修改文字、颜色、字号、尺寸或位置，并且不改变图形类型、信息层级、节点关系或连线语义时，可以跳过专项设计文档。此类操作仍需遵守基础工作流、XML 规则和编辑策略，并优先使用局部 edit operations。

只要编辑涉及新增结构、重排主要布局、改变层级或改变关系语义，就不属于局部编辑例外，必须读取匹配的专项设计文档。

## 落点

1. 在 `build_board_prompt` 生成的系统提示词中新增“绘制前渐进读取规范”章节，明确三个阶段、1–2 份上限、禁止全量读取及局部编辑例外。
2. 在 `CreateDrawioBoardTool` 的工具说明中压缩复述同一前置条件，防止 Agent 在工具选择阶段忽略系统约束。
3. 保留 `drawio_board_workflow.md` 作为专项文档路由的唯一权威来源，系统提示词不复制完整映射，避免两处路由漂移。

## 测试契约

自动化测试必须验证：

- 画板系统提示词要求先读取基础规范，再按需求读取专项规范，最后绘制。
- 系统提示词明确专项文档最多一至两份，并禁止一次性读取全部文档。
- 系统提示词明确局部文字、样式、尺寸和位置编辑可跳过专项文档。
- 工具说明包含同样的绘制前置要求，并继续引用三份基础规范。
- 原有质量闭环提示保持存在，渐进读取规则不能替代截图和显式接受流程。

## 非目标

- 本次不在运行时记录或强制验证 `read_file` 调用历史。
- 本次不新增专项设计文档或改变现有文档路由。
- 本次不改变 XML 校验、截图渲染、版本管理和候选接受状态机。
