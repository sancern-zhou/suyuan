# 右侧可视化全宽与纵向滚动设计

## 背景

右侧预览面板的可视化画廊在浏览器视口宽度达到 1800px 时，会被全局媒体查询强制切换为双列。右侧面板本身没有足够宽度时，单张图表因此只占一半面板。多个图表继续加入后，画廊还需要明确承担垂直滚动职责，避免内容被面板裁切。

## 目标

- 可视化 Tab 中的图表始终以单列展示。
- 每张图表铺满右侧面板的可用内容宽度。
- 多张图表按生成顺序上下排列。
- 图表列表超过右侧面板可用高度后，在画廊内容区显示纵向滚动条。
- 顶部资源 Tab 不随图表列表滚动。
- 画廊不产生横向滚动条。

## 非目标

- 不改变图表数据、渲染器或资源排序逻辑。
- 不改变文档、溯源、文件产物和画板 Tab 的布局。
- 不引入双列或由面板宽度驱动的响应式图表布局。
- 不调整右侧面板整体宽度或拖拽行为。

## 方案

采用固定单列布局：保留 `VisualizationGallery` 作为右侧面板内唯一的可视化滚动容器，删除所有会将 `.gallery-grid` 改为双列的容器查询和全局媒体查询。网格固定使用 `grid-template-columns: minmax(0, 1fr)`，卡片随这一列占满可用宽度。

本设计覆盖 `2026-08-02-right-panel-multi-visualization-ux-design.md` 中“宽度足够时可使用双列”的响应式约束；从本次变更起，右侧可视化在任何面板宽度下都只使用单列。

画廊保持 `height: 100%` 和 `min-height: 0`，显式使用 `overflow-y: auto` 与 `overflow-x: hidden`。`RightPanelContainer` 继续使用纵向 Flex 布局：Tab 区域不收缩，`.panel-content` 占用剩余高度并允许内部画廊滚动。画廊标题继续使用 `position: sticky`，因此滚动多个图表时仍可看到标题和新增提示。

## 组件边界与数据流

- `RightPanelContainer.vue`：继续负责固定 Tab 和分配剩余面板高度，不接管滚动。
- `VisualizationGallery.vue`：负责单列全宽布局、纵向滚动及横向溢出抑制。
- `VisualizationCard.vue` 与各渲染器：保持现有接口和尺寸行为，不修改资源输入或渲染流程。

资源列表、生成顺序、新增计数以及“查看最新”行为保持不变。`showLatest` 仍滚动画廊自身到底部。

## 异常与边界

- 没有图表时，空状态继续在画廊内容区居中显示。
- 单张图表高度不足以填满面板时不强制拉伸高度，只要求宽度铺满。
- 多张图表总高度超过面板时，纵向滚动条出现在画廊右侧。
- 窄面板中，卡片内部内容不得通过画廊产生横向滚动；具体图表继续由现有渲染器响应容器宽度。

## 测试与验收

先增加一个源码布局契约测试，并确认它在现有实现上因双列规则和通用 `overflow: auto` 而失败。测试至少验证：

- 画廊网格固定为单列。
- 不存在将画廊网格切换为 `repeat(2, ...)` 的规则。
- 画廊显式启用纵向滚动并禁用横向滚动。
- 右侧面板内容区域保留 `min-height: 0`，确保内部滚动容器能够收缩。
