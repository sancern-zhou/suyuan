# 消息附件统一资源预览设计

## 背景

统一资源目录已经负责会话内文件、产物、可视化、数据和来源资料的持久化与交付。当前用户输入附件虽然在上传时登记为 `role=attachment`，但消息展示仍存在两条未统一的预览路径：图片使用旧附件 URL 打开弹窗，非图片附件没有点击预览能力；消息附件本身也没有持久保存统一资源 `resource_id`。

本设计只完善用户输入附件的就地预览，不增加“输入附件”或“来源资料”视图。来源资料继续只供 Agent 检索和使用，不向用户展示，也不自动触发预览。

## 目标

1. 用户输入附件继续显示在对应的用户消息中。
2. 图片附件保留现有图片弹窗交互，但内容通过统一资源接口加载。
3. 文档附件点击后在现有右侧预览面板打开。
4. 消息恢复后，新机制保存的附件仍能通过 `resource_id` 打开。
5. 附件不进入“文件产物”列表，不改变 `output/report` 的自动预览逻辑。
6. `source`、`data` 和 `url` 等 Agent 内部资源不进入用户界面。

## 非目标

- 不新增“输入附件”或“来源资料”标签页。
- 不让 `read_file` 自动打开来源资料。
- 不把 `attachment` 重新发布为 `output`。
- 不兼容缺少 `resource_id` 的旧历史消息附件。
- 不恢复任何旧上传、Office、Visualization 或 HTML artifact 预览接口。
- 不提供来源资料的用户手动预览入口。

## 用户交互

### 图片附件

用户点击消息中的图片附件时：

1. 使用当前会话和附件 `resource_id` 定位统一资源；
2. 从资源目录取得授权后的 `content_url`；
3. 使用现有图片弹窗显示；
4. 弹窗下载入口使用资源的 `download_url`。

图片弹窗不改变右侧面板的当前选择。

### 文档附件

用户点击消息中的非图片附件时：

1. 确认消息属于当前激活会话；
2. 使用 `resource_id` 在当前会话资源 Store 中查找资源；
3. 目录尚未加载时先加载目录；
4. 将附件设为用户显式选择的资源；
5. 展开现有右侧面板；
6. 根据 `renderer` 打开对应预览。

PDF、HTML、Markdown、表格和演示文件进入文档预览。没有专用渲染器的文件进入通用文件详情，展示文件信息并提供下载，不显示空白预览。

## 消息附件协议

上传接口已经返回统一资源 `resource_ref`。前端构造用户消息附件时必须保存：

```json
{
  "resource_id": "resource-id",
  "name": "附件名称",
  "type": "image 或 file",
  "mime_type": "application/pdf"
}
```

`resource_id` 是预览身份的唯一依据。`file_id` 可以在现有上传兼容数据中继续存在，但不得用于新预览反查；旧 URL 也不得作为统一预览失败后的降级路径。

会话消息持久化和恢复必须原样保留 `resource_id`。恢复会话只恢复附件的可点击能力，不自动打开任何附件。

## 前端组件职责

### 消息列表

消息列表负责：

- 展示附件；
- 区分图片和非图片点击；
- 发出包含 `resource_id` 的附件预览意图。

消息列表不负责拼接资源内容 URL，不直接读取服务器路径，也不自行加载资源目录。

### 页面与面板管理

页面级逻辑负责：

- 校验当前 `session_id`；
- 加载或复用当前会话资源目录；
- 处理最后一次点击优先的并发选择；
- 控制图片弹窗或右侧面板；
- 切换右侧目标标签页。

### 资源 Store

资源 Store 继续按会话隔离资源状态，并增加“显式选择来源”的语义。用户点击附件形成显式选择后，普通目录刷新不得自动把选择切回最新工具产物。切换会话或清理会话状态时必须清除该选择。

### 统一预览宿主

预览宿主保留两个清晰入口：

- `product`：只从 `output/report` 顶层产物中选择，用于文件产物和自动预览；
- `explicit`：按已明确选择的 `resource_id` 渲染，允许 `role=attachment`。

显式入口只能渲染当前会话中已加载且允许预览的资源，不得因此放宽“文件产物”的筛选规则。

## 分类与可见性规则

| 资源角色/类别 | 用户界面行为 |
| --- | --- |
| `output/report + file/artifact/visual` | 保持文件产物与自动预览行为 |
| `attachment` | 只显示在用户消息中，点击后预览 |
| `source` | 不显示、不自动打开，只供 Agent 使用 |
| `data/url` | 不显示、不自动打开，只供 Agent 使用 |

来源资料即使已加载到前端资源 Store，也不得参与面板计数、标签页可见性、自动选择或恢复选择。

## 状态与并发

- 点击文档附件后，右侧面板立即展开并切换到匹配的预览标签页。
- 显式附件选择优先于目录刷新引发的自动产物选择。
- 连续点击多个附件时，仅最后一次点击可以更新预览；先发出的异步加载结果不得覆盖后续选择。
- 切换会话时清除显式选择和未完成的附件预览请求。
- 图片弹窗状态与右侧文档预览状态互不覆盖。
- 恢复会话时不自动打开附件；用户再次点击后才预览。

## 权限与安全

- 目录加载继续要求用户拥有会话读取权限。
- 内容通过统一 `/sessions/{session_id}/resources/{resource_id}/content` 边界交付。
- `session_id` 与 `resource_id` 必须同时匹配。
- 前端不得接收或构造服务器文件路径。
- 资源必须具备 `preview` 能力才能内嵌预览；仅具备 `download` 能力时进入通用详情。
- 下载继续使用资源 `download_url` 和会话认证。
- 不允许用附件入口打开 `source`、`data` 或 `url` 资源。

## 错误处理

- 资源目录未加载：加载成功后继续打开。
- 资源不存在、失效或不属于当前会话：在附件位置或统一提示区显示“附件资源不可用”。
- 无会话权限：显示无权限错误，不降级访问旧 URL。
- 内嵌预览不受支持：打开通用文件详情并提供下载。
- 网络失败：保留最后一次显式选择并允许重试。
- 会话已切换：静默丢弃旧会话预览请求的完成结果。

## 测试与验收

### 协议与恢复

- 新上传附件的消息对象包含 `resource_id`。
- 消息持久化和恢复保留 `resource_id`。
- 缺少 `resource_id` 的附件不会访问旧预览接口。

### 图片

- 图片点击继续打开现有图片弹窗。
- 图片内容来自统一资源 `content_url`。
- 图片下载使用统一资源 `download_url`。

### 文档

- PDF、HTML、Markdown、表格和演示附件在右侧打开。
- 普通文件进入通用详情和下载。
- 点击文档附件会展开右侧面板并选择正确资源。
- 快速点击多个附件时最终显示最后点击的附件。

### 隔离与可见性

- `attachment` 不出现在“文件产物”列表。
- `source`、`data` 和 `url` 不显示、不自动打开。
- 切换会话不会显示上一个会话的附件。
- 资源目录刷新不会覆盖用户显式选择。

### 回归

- `output/report` 自动预览保持不变。
- 新会话和会话恢复的资源目录加载保持正常。
- 正式前端产物继续只包含统一资源接口，不重新引入旧 Office、Visualization、Report、HTML artifact 或旧文件预览接口。
