# Suyuan 公司验证码登录设计

## 目标

修复自研 Vue 3 登录页在提交前因加密模块未配置而中断的问题，并兼容公司认证服务 `@suncereltd/suncere-sys@2.1.4` 的图片验证码协议。用户应能在独立登录页输入账号、密码和四位验证码，经过公司认证网关完成登录。

## 已确认现状

- 页面引用 `/suyuan-runtime-config.js`，但部署目录只有示例文件，当前请求得到 SPA HTML。
- 未注入 SM4 客户端协议密钥时，登录在浏览器内报错，不会产生认证请求。
- 临时注入公司标准运行参数后，`/api/auth/token/authentication` 能正常到达认证服务。
- 认证服务要求图片验证码；验证码接口 `/api/auth/token/captcha` 已验证返回 GIF。

## 方案比较

### 方案 A：扩展现有 Vue 3 登录页并使用公司 SM2/SM4 模块（采用）

保留当前页面和鉴权适配器，使用用户提供的 `/tmp/SM2.js`、`/tmp/SM4.js` 所定义的公司标准算法和参数，并增加验证码状态、图片和请求字段。改动小，能够同时支持独立登录和平台会话复用。

### 方案 B：移植公司包完整登录组件

公司组件基于 Vue 2、Ant Design Vue 和公司 Store，迁移会引入大量无关依赖及双因素登录逻辑，不适合当前 Vue 3 应用。

### 方案 C：由 Suyuan 后端代理账号密码登录

会让 Suyuan 后端接触用户密码，扩大安全边界，也偏离公司统一认证协议，因此不采用。

## 前端组件与数据流

1. 登录页进入时生成 UUID `captchaKey`。
2. 图片地址为 `/api/auth/token/captcha`，参数包括 `oldKey`、新 `key`、随机支持的验证码 `type` 和防缓存时间戳。
3. 用户输入四位 `verifyCode` 后提交。
4. `authApi.login` 在既有加密字段之外提交：
   - `verifyCode`
   - `captchaKey`
   - `isLog: "1"`
   - `logType: "5"`
5. 登录失败时清空密码和验证码，并生成新 key 刷新图片。
6. 登录成功后沿用现有逻辑取得 Access Token，再查询当前用户并进入原目标页面。

## SM2/SM4 模块

- 将用户提供的 SM2、SM4 实现纳入前端鉴权模块，协议参数与公司 `2.1.4` 标准包保持一致。
- SM2 固定使用 cipher mode 1（C1C3C2）。
- SM4 固定使用 CBC、客户端标准 key 同时作为 IV、Base64 输出。
- 为适配 Vue 3 + Vite，将文件中的 CommonJS `require` 改为 ES Module `import`；算法、参数和导出行为不变。
- `companyCrypto` 复用模块导出的 `encryptSM2`、`encryptSM4`，签名仍使用现有 SM3、时间戳、Token 和 UUID 布局。
- 移除页面对 `/suyuan-runtime-config.js` 的依赖，不再因部署漏放该文件而中断登录。

## 错误处理

- 验证码图片可点击刷新。
- 图片请求失败时保留刷新入口，不发送无验证码的登录请求。
- 认证失败显示认证服务的业务消息，并自动换一张验证码。
- 加密模块初始化或执行失败时显示明确错误，不回退到明文密码。

## 测试与验收

- 单元测试验证登录请求包含验证码和审计字段。
- 单元测试验证验证码 URL 包含新旧 key、类型及时间戳。
- 现有 SM2/SM3/SM4协议测试继续通过。
- 前端生产构建通过。
- 浏览器实测应观察到验证码请求和登录请求；最终响应中不打印密码、加密请求体或 Access Token。

## 范围边界

本次不实现短信、邮箱、UKey、双因素认证或忘记密码流程，也不调整公司网关和 Suyuan 业务路由。SM2/SM4 参数后续如需按环境轮换，需要另行恢复运行时注入机制。
