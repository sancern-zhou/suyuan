# 当前轮用户附件上下文设计

## 背景

Web 对话已经使用结构化 `context_refs` 表达用户在当前轮输入或选择的附件，
并使用统一会话资源目录保存文件、产物和预览。当前实现能够校验并持久化
`context_refs`，但非图片资源没有进入当前轮 Planner 消息。模型只看到用户的
原始短文本，例如“阅读”，同时只能从完整会话资源目录中猜测目标文件。

当前轮输入语义和会话资源发现是两个独立职责：

- 当前轮上下文表达用户这一次提交了什么；
- 会话资源目录表达整个会话有哪些可发现资源。

两者必须同时保留，不能由会话资源目录替代当前轮附件语义。

## 目标

1. Planner 首轮同时看到用户原始文本和本轮结构化附件信息。
2. 本轮附件信息包含资源 ID、文件名、媒体类型和 Agent 可读取路径。
3. 完整会话资源目录继续独立注入，不因本轮选择而过滤。
4. 非图片附件正文不自动进入上下文，由 Agent 使用文件工具按需读取。
5. 图片保持现有原生多模态输入能力。
6. 附件路径只能从服务端已授权的统一资源实体生成。

## 非目标

- 不在首次 Planner 请求前自动解析 PDF、Office、HTML 或其他附件正文。
- 不恢复废弃的 Web `attachments` 请求字段。
- 不把前端提供的路径或 URL 当作 Agent 文件定位依据。
- 不在当前轮附件段落中加入“必须读取”“应优先处理”等固定行为指令。
- 不改变统一资源目录的生命周期、版本和展示协议。

## 上下文结构

Planner 第一轮用户消息由两个事实段落组成：

```text
## 当前进行的任务
阅读

## 本轮用户附件
1. index (1).html
   资源 ID: 05019032325be4af1c4da8ef6a8e215d
   类型: text/html
   路径: backend_data_registry/uploads/4922e1d8-3186-4ce4-8cf7-d7d7e72d86b1.html
```

`本轮用户附件` 只陈述资源归属与可用定位信息，不附加操作指令。完整会话资源
目录继续位于稳定的系统上下文层，用于跨轮发现和按需查询。

## 数据流

1. Composer 上传文件并取得统一资源 `resource_id`。
2. Composer 在发送快照中提交原始 `query` 和 `context_refs`。
3. 路由从当前会话的统一资源目录解析并授权 `context_refs`。
4. 路由把解析后的 `StoredResource` 列表作为 `selected_resource_refs` 传给 Agent。
5. Agent 将这些引用转换成当前轮附件事实，并交给上下文构建器。
6. 上下文构建器在第一轮把原始 query 和本轮附件事实组装进同一条用户消息。
7. 完整会话资源目录通过现有 `session_resource_context` 独立注入。
8. Agent 根据当前任务自行决定是否以及如何读取附件。

## 字段规则

每个当前轮附件包含：

- `resource_id`：统一资源的稳定身份；
- `label`：用户可识别的文件名；
- `media_type`：读取 `StoredResource.media_type`；
- `path`：从 `StoredResource.locator.path` 解析，并转换为 Agent 文件工具可消费的
  规范路径。

不得使用 `context_refs.display_name` 定位文件。不得使用客户端路径。路径不存在、
资源非 active 或不属于当前会话时，沿用现有请求边界校验并拒绝请求。

## 图片处理

本轮图片同时具有两种表示：

- 当前轮附件事实，保留文件名、资源 ID、媒体类型和路径；
- 支持原生多模态的模式中，转换为模型图片内容块。

图片类型判断使用 `StoredResource.media_type`。为兼容已有测试构造数据，可在必要时
回退读取 `metadata.mime_type`，但正式资源字段具有更高优先级。

## 消息持久化

用户消息继续持久化原始文本、`context_refs` 和轻量附件元数据。轻量附件协议补充
统一资源 `resource_id`，但不保存附件正文、base64 或未经规范化的绝对路径。

运行时当前轮路径只用于 Planner 上下文，不改变前端消息展示协议。

## 测试

后端回归测试覆盖：

1. “阅读”加 HTML 附件时，第一轮用户上下文保留“阅读”。
2. 同一上下文包含 HTML 的文件名、资源 ID、媒体类型和可读路径。
3. 本轮没有附件时，不生成空附件段落。
4. 多个附件保持请求中的选择顺序。
5. 非图片附件不生成原生 image block。
6. 图片使用 `StoredResource.media_type` 正确生成运行时附件。
7. 消息轻量附件包含统一资源 `resource_id`。
8. 完整会话资源目录仍然存在，且不被本轮附件集合过滤。

集成回归应捕获 Planner 的首次请求，验证通用短指令不会再只剩裸文本，也不会把
会话中的旧报告错误表示为本轮附件。

## 验收标准

- 当前轮 Planner 用户消息同时包含用户原始文本和本轮附件事实。
- 附件事实不包含固定操作指令。
- Agent 可以直接使用所给规范路径调用文件读取工具。
- 会话资源目录继续完整、独立地进入系统上下文。
- 附件正文不会因本次修改无界注入 prompt。
- 现有图片多模态、消息恢复和统一资源测试保持通过。
