# 右侧资源面板多可视化与预览体验设计

## 目标

在现有统一 Session Resource 资源体系上改进右侧面板体验，不引入旧资源接口或第二套资源状态：

- “可视化”自动展示当前会话内全部有效图表和可视化图片。
- 旧图在前，新图追加到底部；新增资源不替换旧图、不抢焦点、不强制滚动。
- 文档预览提供明确的文件身份、同类资源切换和稳定选择。
- Excel 编辑在任何可能丢弃修改的操作前提供保护。
- 空标签、附件路由、文件产物文案和面板自动展开行为符合用户预期。

## 非目标

- 不改变后端资源声明、资源 catalog 或内容授权协议。
- 不恢复 `/office-documents`、`/visualizations` 等旧接口。
- 不实现跨会话画廊、图表搜索、收藏或复杂布局编辑。
- 不改变画板编辑器自身的版本和保存协议。

## 总体架构

### 可视化画廊

新增独立的 `VisualizationGallery`，由 `RightPanelContainer` 在 `activeTab === 'visualization'` 时加载。文档和画板继续使用单资源 `ResourcePreviewHost`。

画廊直接消费当前会话的 resource catalog：

1. 使用现有 `buildResourceGroups` 构造资源组。
2. 仅保留有效顶层产物和 `targetTab(group) === 'visualization'` 的资源组。
3. 每组通过 `preferredPreview(group)` 选择一个有效展示资源。
4. Chart 与生成的 PNG/JPG 等图片统一进入画廊。
5. 每个 `group_id` 只对应一张卡片。同组版本更新时原位更新，不产生重复卡片。

组件边界如下：

- `VisualizationGallery`：排序、累计展示、新增提示和滚动行为。
- `VisualizationCard`：标题、格式、版本、下载和单卡错误边界。
- 现有 Chart/Image renderer：实际内容渲染，不感知画廊状态。
- resource store：继续负责 catalog、版本刷新和会话隔离，不保存画廊 DOM 状态。

### 排序与更新

画廊按资源组首次产出时间升序排列，保证旧图在前、新图在后。首次产出时间优先取组内最早的 `created_at`，缺失时回退到最早 `updated_at`，最后以 `group_id` 提供确定性排序。

资源刷新时：

- 新 `group_id` 追加为新卡片。
- 已存在 `group_id` 的新版本保持原位置并更新内容。
- 已失效资源组从画廊移除。
- 不依赖当前 `selectedResourceId`，因此新图不会替换旧图。

## 用户交互

### 可视化标签

- 进入标签后无需选择，所有有效可视化自动呈现。
- 每张卡片显示标题、格式、版本和下载操作。
- 单卡内容加载失败时只显示该卡片的错误与重试，不影响其他卡片。
- 新图到达时保持用户当前滚动位置，不自动滚动。
- 画廊显示轻量提示“新增 N 个可视化”，用户点击“查看最新”后滚动到底部并清除提示。
- 同组版本更新显示短暂“已更新”状态，但不计入新增数量。

### 文档预览

文档仍采用单文件预览，但增加固定标题栏：

- 显示文件名、格式、版本及是否为最新版本。
- 提供同类文档选择器，用户无需回到“文件产物”标签切换文档。
- 下载原始文件、报告导出和已有派生文件下载统一放入标题栏操作区。
- 用户主动选择文档后，catalog 新增资源不得改写当前选择。
- 仅在没有有效选择时自动选择最新文档；当前资源失效时选择同类最新文档，没有同类资源时回到文件产物。

### 标签与面板

- 文档、可视化、溯源、画板数量为零时禁用对应标签。
- 文件产物标签在存在会话时始终可用。
- 第一个资源产物出现时可以自动展开右侧面板。
- 用户手动关闭后记录关闭意图；后续新资源只提示，不再次强制展开。
- 用户手动设置的右侧宽度和当前有效标签在会话期间保持稳定。

### 附件路由

消息附件解析为统一资源后，按资源组实际 `targetTab` 打开：

- 文档、表格、PDF、演示文稿进入文档。
- Chart 和可视化图片进入可视化。
- Draw.io 进入画板。
- 不支持预览的普通文件进入文件产物详情。

图片可以继续使用现有快速弹窗，同时提供统一资源下载；不再把所有非图片附件无条件送入文档标签。

### 文件产物文案

面向用户隐藏内部 relation 名称：

- `preview + pdf` 显示为“PDF 预览”。
- `rendition + html` 显示为“HTML 导出版”。
- `rendition + docx` 显示为“Word 导出版”。
- 版本只显示“共 N 个版本”，详细版本列表按需展开。

## Excel 未保存保护

Spreadsheet renderer 维护本地 `dirty` 状态：

- 单元格修改后进入未保存状态，工具栏显示“未保存”。
- 保存成功并刷新到新版本后清除未保存状态，显示“已保存为 vN”。
- 保存失败保留 workbook 和用户编辑内容。
- 点击重新加载、切换文档、切换右侧标签、关闭右侧面板或切换会话前，若存在未保存修改则请求确认。
- 用户取消时必须保持当前标签、当前文件和编辑内容不变。

为避免父组件读取渲染器内部实现，预览层通过明确的离开守卫接口上报是否允许离开。浏览器刷新/关闭页面使用 `beforeunload` 作为最后保护。

## 选择状态模型

资源选择需要区分来源：

- `auto`：首次恢复或当前选择失效后的自动选择。
- `product`：用户从文件产物打开。
- `document-picker`：用户从文档选择器打开。
- `explicit`：用户点击消息附件。

除 `auto` 外都视为用户意图。catalog 版本更新不得覆盖仍有效的用户选择。

`selectedGroupId` 与 `selectedResourceId` 必须保持一致；预览宿主不得一边写入 group、一边只读取 resource。实现阶段选择一个单一事实来源，并删除或真正使用冗余字段。

面板关闭意图与“当前是否存在资源”分离，避免资源 watcher 每次刷新都重新打开面板。

## 异常与并发

- catalog 请求失败时保留现有资源和当前预览，仅展示非阻断错误与重试入口。
- 重复或乱序 `resources_changed` 继续由 resource version 与 request token 去重。
- 新图计数以画廊已经见过的 `group_id` 集合为准，重复事件不重复提示。
- 会话切换后到达的旧请求结果不得更新当前画廊、选择或未保存确认状态。
- 单卡异步 renderer 失败由卡片错误边界处理，不卸载整个画廊。
- 文档 iframe 无法加载时提供可理解的失败状态和重新加载入口，而不是仅依赖浏览器空白页。

## 响应式与可访问性

- 右侧较窄时画廊使用单列；宽度足够时可使用双列，但必须保持资源顺序。
- 图表卡片提供合理最小高度，内容不得横向撑破面板。
- 标签栏使用 tablist/tab/aria-selected/aria-disabled 语义。
- 文件选择器、下载菜单、新增提示和确认操作支持键盘操作。
- 状态变化使用非打断式 live region；错误信息与对应卡片关联。

## 验收标准

1. 初始 catalog 有多张 Chart 和图片时，可视化标签自动展示全部资源。
2. 新资源组到达后旧卡片仍存在，新卡片追加到底部，滚动位置不跳。
3. 同一组的新版本原位更新，不产生重复卡片。
4. Chart 与 PNG/JPG 可混合排序和展示。
5. 单卡失败不影响其他卡片，重试只重新加载该卡。
6. 用户查看旧文档时，新文档到达不抢占预览。
7. 文档标题栏可识别当前文件并直接切换同类文档。
8. 空的文档、可视化、溯源和画板标签不可激活。
9. 用户手动关闭右侧面板后，新资源不会强制展开它。
10. Excel 未保存时，重新加载、切换资源、切换标签、关闭面板和切换会话均受到保护。
11. 附件按真实资源类型打开。
12. 文件产物不再展示 `preview`、`rendition` 等内部术语。
13. 统一资源接口检查继续通过，生产源码和构建产物不包含旧资源接口。

## 测试策略

### 单元测试

- 画廊资源筛选、首次产出时间排序、Chart/Image 混排和同组去重。
- 新增组与同组版本更新的差异识别。
- 自动选择仅在无有效选择时发生，用户选择在 catalog 刷新后保留。
- 空标签可用性、附件目标标签和文件产物用户化文案。
- Spreadsheet dirty 状态、保存清理和离开守卫。

### 组件与 E2E

- 初始多图自动展示。
- 新图追加且旧图保留、滚动位置稳定、查看最新按钮有效。
- 文档选择器、标题栏和下载菜单。
- 新文档不抢占用户选择。
- Excel 在所有离开路径上的确认与取消行为。
- 手动关闭面板后资源更新不重开。
- 不同类型消息附件进入正确目标。
- 窄面板下标签与卡片不溢出。
