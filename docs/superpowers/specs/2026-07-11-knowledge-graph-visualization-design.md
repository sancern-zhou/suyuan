# 知识库图谱可视化设计

## 背景与历史结论

项目曾拥有完整的认知地图可视化模块 `CognitiveMapPanel.vue`，其中包含节点—边画布、类型筛选、关系筛选、层级查看、详情和管理操作。该组件在提交 `5159530`（“将知识图谱并入知识库工作台”）中由约 2400 行缩减为只读迁移入口，随后在提交 `db7b88e`（“下线独立认知地图运行机制”）中删除。

当前仍保留知识库级图谱 API、实体关系状态、审核与合并、关系文本列表和 Graph Agent 对话，但交互式节点—边画布已经删除。恢复旧组件会同时恢复独立地图列表、文件上传和独立构建等旧机制，与“每个知识库拥有自己的图谱”冲突，因此不采用旧组件恢复方案。

参考项目 Yuxi 将图谱渲染抽为独立 `GraphCanvas`，采用 AntV G6，业务页面负责数据、工具栏、详情面板和构建管理。该边界适合当前项目。

## 目标

- 在“知识库 → 图谱”页内重建独立 AntV G6 可视化组件。
- 图谱始终由当前 `kb_id` 隔离，不恢复独立认知地图入口。
- 默认加载并渲染当前知识库全部有效实体和关系，不抽样、不截断、不以子图替代。
- 支持搜索、筛选、拖拽、缩放、平移、邻居高亮、重新布局和全屏。
- 节点和关系详情展示属性、审核状态、Mention、来源文档、原文证据和置信度。
- 在详情面板直接完成确认、拒绝、编辑、合并和删除。
- 图谱构建、事实审核和可视化共用现有知识库图谱机制。

## 非目标

- 不恢复独立认知地图入口、地图列表或地图绑定机制。
- 不恢复旧认知地图的独立上传和独立构建流程。
- 不改变每个知识库独立拥有图谱的数据模型。
- 不以默认 200 条限制、抽样或按需子图代替全量渲染。

## 总体架构

```text
KnowledgeGraphTab
├── KnowledgeGraphStatus
├── KnowledgeGraphToolbar
├── KnowledgeGraphCanvas（AntV G6）
├── KnowledgeGraphDetailPanel
└── CognitiveMapGraphChat
```

### KnowledgeGraphTab

负责当前知识库上下文、全量快照加载、构建完成后的刷新、工具栏状态和详情选择。知识库切换时取消旧请求、清空选择并销毁旧图实例，旧响应不得覆盖新知识库状态。

### KnowledgeGraphCanvas

是无知识库 API 依赖的独立渲染组件，只接收标准化的 `nodes` 和 `edges`，向上发出节点、关系和空白画布事件。组件负责：

- AntV G6 实例生命周期。
- Canvas 力导向布局。
- 节点拖拽、画布缩放和平移。
- 点击选择与一跳邻居高亮。
- 节点大小按关联度变化。
- 节点颜色按实体类型稳定映射。
- 关系颜色按关系类型稳定映射。
- 自环、重复关系和孤立节点渲染。
- 适应画布、重新布局和全屏。

画布缩放较小时可隐藏普通节点文字和关系标签，放大时恢复。该策略只降低标签绘制量，所有节点和关系始终存在。

### KnowledgeGraphToolbar

提供：

- 实体名称搜索与定位。
- 实体类型多选筛选。
- 关系类型多选筛选。
- 关系标签开关。
- “显示历史数据”开关。
- 适应画布、重新布局、全屏和刷新。
- 已加载实体、关系和加载进度。

类型筛选只控制可见性，不重新请求或删除图数据。搜索只定位、居中和高亮，不改变数据集合。

### KnowledgeGraphDetailPanel

节点详情展示名称、类型、别名、描述、自定义属性、Mention 数量、审核状态、创建来源和合并状态。关系详情展示起终点、关系类型、描述、属性、Mention 数量和审核状态。

证据部分按需请求，不放入全量快照：

- 来源文档和文档版本。
- 分块 ID 与原文片段。
- evidence text。
- 抽取置信度。
- 跳转到知识库文档分块。

跳转前校验文档内容版本；证据属于旧版本时显示“证据已失效”，不得跳转到新版本的错误位置。

详情面板直接提供确认、拒绝、编辑、合并和删除操作。拒绝、删除和合并需要二次确认。

## 数据范围

默认全量渲染以下有效状态：

- `candidate`
- `confirmed`
- `published`

开启“显示历史数据”后追加：

- `rejected`
- `archived`
- `merged`

默认与历史模式都不设置实体或关系数量上限。

## 后端接口设计

### 图谱快照

新增知识库级快照接口，严格校验读取权限和 `kb_id`：

```http
GET /api/knowledge-base/{kb_id}/graph/snapshot
    ?review_statuses=candidate&review_statuses=confirmed&review_statuses=published
    &cursor=<opaque_cursor>
    &page_size=1000
```

响应：

```json
{
  "knowledge_base_id": "kb-id",
  "snapshot_version": "version",
  "entities": [],
  "relations": [],
  "next_cursor": null,
  "entity_total": 0,
  "relation_total": 0
}
```

游标只用于传输分批，前端必须自动获取全部批次。为知识库增加单调递增的 `graph_revision`：图谱抽取持久化、贡献删除、人工编辑、审核、合并和删除事实时，在同一事实事务中原子递增该值。快照接口使用 `graph_revision` 作为 `snapshot_version`，后续分页请求必须携带第一页版本；版本不匹配时返回 `409 graph_snapshot_changed`。前端丢弃本轮数据并从第一页重试，避免渲染实体与关系不一致的残缺快照。

现有 `/entities` 和 `/relations` 管理接口保留原分页限制，列表管理与可视化快照职责分离。

### 证据详情

新增实体和关系证据接口：

```http
GET /api/knowledge-base/{kb_id}/graph/entities/{entity_id}/mentions
GET /api/knowledge-base/{kb_id}/graph/relations/{relation_id}/mentions
```

响应包含文档、内容版本、分块、证据文本和置信度。接口必须验证实体或关系属于路径中的知识库。

### 编辑操作

复用现有创建、更新、删除和合并 API。删除维持当前归档语义，并通过 Outbox 更新图谱索引。操作成功后前端局部更新画布，并后台刷新快照统计。

## 交互流程

### 首次加载

1. 进入当前知识库图谱页。
2. 拉取图谱状态和第一页快照。
3. 根据 `next_cursor` 自动获取全部批次。
4. 校验所有批次的 `snapshot_version` 一致。
5. 全部获取成功后生成 G6 数据并开始布局。
6. 任一批失败时不渲染残缺图，显示重试入口。

### 审核与编辑

1. 点击节点或关系打开详情。
2. 按需加载证据。
3. 执行确认、拒绝、编辑或删除。
4. 成功后更新当前节点或关系及统计；失败时保留原状态并显示错误。

### 合并

1. 在源实体详情中选择“合并”。
2. 画布进入目标选择模式。
3. 点击目标实体。
4. 显示源、目标和影响关系数量，二次确认。
5. 调用现有合并 API。
6. 删除源节点，刷新目标节点和受影响关系，然后校验快照。

### 构建完成

构建任务从 `queued/running` 进入终态后，图谱页重新加载全量快照，使新抽取事实进入画布。刷新不创建另一套构建或缓存机制。

## 性能策略

- 所有有效节点和关系必须渲染，不设置硬上限。
- 分批传输、全量完成后一次建图。
- 使用 Canvas 渲染和 G6 力导向布局。
- 缩放等级控制标签可见性。
- 保存稳定节点坐标，单事实编辑时避免全图重新布局。
- 数据转换使用纯函数，允许后续移入 Web Worker；首期不引入额外 Worker 协议。
- 显示加载和布局阶段，避免用户误认为页面卡死。

## 错误与并发处理

- 知识库切换或组件卸载时使用 `AbortController` 中止旧快照和证据请求。
- 每轮加载使用请求序号，晚到响应不得覆盖新状态。
- 快照版本变化时整轮重试，不拼接不同版本。
- G6 初始化或布局异常只影响画布，不能阻断图谱状态、审核列表或 Graph Agent。
- 编辑请求采用提交中状态，禁止重复提交；失败时不做乐观数据永久写入。
- 已被其他请求删除或合并的事实返回 404/409，并触发快照刷新。

## 测试与验收

### 后端

- 快照严格按 `kb_id` 隔离。
- 游标分页最终覆盖全部实体关系，不受 200 条限制。
- 默认状态和历史状态过滤正确。
- 所有图谱事实变更事务均原子递增 `graph_revision`。
- 分页期间版本变化可被前端识别。
- Mention 接口验证知识库归属并返回文档版本、分块、证据和置信度。
- 归档、审核、编辑和合并后快照与 Outbox 一致。

### 前端

- G6 数据转换支持孤立节点、自环和重复关系。
- 全量分页完成后才初始化画布。
- 快照批次失败不显示残缺图。
- 知识库切换、响应乱序和卸载清理正确。
- 类型筛选、标签开关、搜索定位和邻居高亮正确。
- 详情证据和文档版本失效提示正确。
- 确认、拒绝、编辑、删除和合并流程正确。
- 构建任务完成后刷新当前知识库快照。
- 前端生产构建通过。

## 依赖选择

新增 AntV G6 作为图谱渲染依赖。实现参考 Yuxi 的独立 `GraphCanvas` 生命周期与交互边界，但使用本项目的实体、关系、Mention、审核和构建 API，不复制 Yuxi 的 Milvus 限制或独立索引配置机制。
