# 例行工单审核规则说明（常规站 / 组分站）

> 更新日期：2026-11-16。本文档描述当前代码实际生效的例行（运维）工单自动审核规则，覆盖常规站与组分站两条审核路径。
> 规则清单以 `backend/app/services/ops_audit/configs/rule_catalog.yaml`（生效规则目录）与引擎调度代码为准；各规则的判定阈值/字段档案在 `configs/` 下各 YAML 中维护。
>
> 2026-11-16 降噪修订：① PM 周检流量(Main Flow)空值/占位不再作为 RF_ABNORMAL_VALUE_NO_REMARK 触发源（业务确认剔除，全窗口 55% 表单该字段为空，属表单填报习惯）；② XH 品牌为 API 贴牌机（多站备注佐证 + 全队实测值分布核验），CO 周检 5 字段与 NOx 反应室压力档案对齐 API 口径（见 `rf_range_profiles.yaml` 注释）；③ 语义复核确认的站点维护照片缺失现在会晋升进入最终问题清单（此前 confirmed_issue 结论被静默丢弃）。

## 1. 总体架构

例行工单审核（运维工单审核）对已创建的 Check / SupCheck 类工单做自动化质量审核：取数 → 确定性规则 → 视觉（多模态）规则 → 语义复核 → 最终问题清单 → 报告产物。

核心代码位置：

| 模块 | 路径 | 职责 |
|---|---|---|
| 审核引擎 | `backend/app/services/ops_work_order_audit_engine.py` | 取数（源库口径）、规则调度、视觉任务调度、作废剔除 |
| 本地取数 | `backend/app/services/ops_work_order_audit_local.py` | 本地 guangdong_mart（PG）取数，含组分站路径 |
| 配置加载 | `backend/app/services/ops_audit/config.py` | 加载 `configs/` 下全部 YAML 档案（整体覆盖内置默认值） |
| 规则实现 | `backend/app/services/ops_audit/rules/` | 全部规则检查函数（rf_* 常规站、sup_* 组分站、附件类共用） |
| 语义复核 | `backend/app/services/ops_audit/semantic/` | 备注/文件名/照片水印等 LLM 语义与多模态复核 |
| 问题定性 | `backend/app/services/ops_audit/scoring.py` | 硬错误/待确认/技术诊断三分类 |
| 最终清单 | `backend/app/services/ops_audit/final_issue_list.py` | 汇总、豁免、语义结果回填 |
| 服务入口 | `backend/app/services/ops_work_order_audit.py` | 一站式 API：取数→审核→语义候选→产物落盘 |
| Agent 工具 | `backend/app/tools/analysis/ops_work_order_audit/tool.py` | ops_audit_fetch_dataset / ops_audit_run_rules / ops_audit_inspect |

## 2. 审核对象与站点分流

| 维度 | 常规站 | 组分站 |
|---|---|---|
| 工单类型（DDWORKINGORDERTYPE） | `Check` | `SupCheck`、`SupSECCheck` |
| 表单存储 | 主网 RF 分表（`RF_W_*` 每周、`RF_TW_*` 两周、`RF_M_*` 月度、`RF_Q_*` 季度、`RF_Y_*` 年度、`RF_HY_*` 半年） | `sup_rf_common` 通用宽表（按 `RULEITEMTAG` 区分 173 类表单）+ 少量专用分表（`sup_rf_pm1monitorinspection`、`sup_rf_deviceflowcheck`、`sup_rf_monitorinspection`、`sup_rf_ambienttemperature`） |
| 表单规则 | rf_* 系列（约 70 条） | SUP_* 档案驱动规则（10 条）+ 档案（`sup_form_profiles.yaml`，已建档 68 类表单） |
| 取数路径判定 | 请求的 order_types 未全部落在组分站集合 | `is_sup_station_request()`：请求类型全部属于 `{SupCheck, SupSECCheck}` 时走组分站取数 |

分流细节：

- 常规站请求中 `SupCheck` 始终被排除（`EXCLUDED_AUDIT_ORDER_TYPES`），不会混入主网取数。
- 组分站取数只读 `sup_rf_common` 宽表与上表 5 张本地分表；仅读宽表会把整单误判为"无表单数据"（2026-10-26 复盘：周窗口 21 单中 17 单表单只在分表），因此分表必读。
- 维护周期（MAINTENANCETYPE）：常规站覆盖 Week / TwoWeek / Month / Quarter / HalfYear / Year。
- 工单流程步骤期望：Check 为 `CreateOrder`+`CheckOrder`(+`Review`)；SupCheck 为 `SupCheck_Check`；SupSECCheck 为 `SECCheckCnemc`/`OperationCheckCnemc`/`SupCheck_Check`。

## 3. 运行口径（审核窗口）

配置：`configs/audit_window.yaml`，实现在 `ops_audit/audit_window.py`。

- 每周一运行，审核**上上周完整自然周内创建**的工单：创建窗口 = `[本周一 − 14 天, 本周一 − 7 天)`（例如 2026-10-26 运行 → 审核 10-12 ~ 10-18 创建的工单）。
- **不限完成状态**：Finish / Doing / Wait 均审核，不约束完成时间；滞后完成的工单由后续运行按创建窗口自然补齐。
- 排除作废单：状态为 Invalid，或工单标题/内容、全部表单备注为"工单作废"类文本的整单剔除（含其历史库对照数据）。
- 时区 Asia/Shanghai。

## 4. 审核链路与问题定性

### 4.1 单工单执行顺序（audit_dataset）

1. 非视觉块：表单在位性护栏（FORM_DATA_MISSING）→ 流程（FLOW_*）→ 生命周期（LIFECYCLE_*）→ rf_required / time / unit / range / formula / humidity / multipoint / pm_pressure / position / enum / visibility / abnormal_remark / calibration_date → **组分站档案规则（sup_form、sup_attachment）** → 引擎遗留 rf 规则（站点一致性等）→ 跨工单设备身份（默认关闭）→ 附件要求 → O3 量值传递 XLS 比对 → O3 传递结果（当前停用）。
2. 视觉块（构建任务后统一执行，受 `semantic_review.yaml` 的 `flow_visual_enabled_rule_ids` 开关）：流量/校准照片读数与水印比对、两周清洗照片、半年站点维护照片、多点校准曲线图、**组分站水印抽检**。

### 4.2 问题定性（不再打数值分）

每条问题按三个维度归档：

| 维度 | 取值 | 说明 |
|---|---|---|
| 问题性质（7 类） | 完整性 / 规范性 / 时间合理性 / 数值逻辑 / 一致性 / 异常说明 / 附件质量问题 | 由 `rule_taxonomy.py` 归一 |
| 严重程度 | 高 / 中 / 低 | 目录默认值，个别规则运行时按条件升降级 |
| 定性（assessment） | 确定性问题 deterministic_issue / 待确认 candidate_issue / 技术诊断 technical_diagnostic | 见下 |

- **硬错误（确定性）**：`business_calibration.yaml` 的 `hard_error_rules`（47 条，其中 39 条为致命级 critical），如各时长不足、站点不一致、校准日期异常、多点线性指标超限、照片读数不一致等。
- **待确认**：不在硬错误清单的问题，以及证据带 `needs_semantic_review: true` 的问题（如超范围但有备注、字段的语义判断类），需结合语义复核/人工判断。
- **技术诊断**：环境依赖问题（视觉调用失败、XLS 读取环境缺失、单位不可换算），单独归档，**不计入业务问题**。
- 工单级不再输出分数，只有"有问题 / 空"标识（audit_level）。

### 4.3 复核阶段（rule_review_stages.yaml）

| 阶段 | 处理方式 | 代表规则 |
|---|---|---|
| semantic_remark | 备注语义复核（LLM 判断备注是否有效说明当前问题） | REMARK_SEMANTIC_INCOMPLETE、RF_ABNORMAL_VALUE_NO_REMARK、RF_TW_REMARK_LOW_VALUE、RF_NO_DEVICE_WITHOUT_REMARK、RF_PM_TAPE_USAGE_INVALID 等 12 条 |
| flow_visual | 照片多模态视觉比对（自动判定） | 8 条照片读数/水印时间规则 |
| manual_visual_review | 视觉识别 → 人工复核 | 多点曲线梯度、多点水印、O3 六点复核、组分站水印 |
| manual_evidence_review | 证据缺失 → 人工复核 | O3 缺 XLS 附件、O3 上级标准历史冲突 |
| technical_diagnostic | 技术诊断，不入业务清单 | 视觉失败、XLS 读取失败、单位不可换算、组分站水印读取失败 |
| future_ocr | 预留未来 OCR 能力 | 证书封面、报告目录、水印缺日期等 |
| excluded | 命中后不在最终清单展示 | 见 §7 |

### 4.4 语义复核口径（semantic_review.yaml + semantic/prompts.py）

- 阈值：备注完整度 0.75、附件完整度 0.8、照片水印 0.75、数值一致性 0.8；数值比对容差 5%；视觉判定置信度 ≥0.85 才出问题。
- 备注有效性口径：**相关且不矛盾即有效**，不强制"原因/措施/结果"三要素；对超范围类问题接受"厂家备案范围/表格范围有误"等字段级解释。
- 备注关键词参考：原因类（故障/异常/停机…）、措施类（已更换/修复/清洗…）、结果类（恢复正常/合格…）。
- 批量复核：备注、工单标题、无设备说明、纸带耗材、照片文件名等均有批量 LLM 复核器（每批 ≤8 项，超时 240s，LLM 不可用时回退确定性判定）。

## 5. 常规站审核规则清单

生效规则目录 `configs/rule_catalog.yaml` 共 81 条，常规站占绝对多数；下表按问题性质分组（严重程度为目录默认值）。标注【豁免】的规则虽在目录中，但按 `rule_taxonomy` 不进入最终问题清单；标注【停用】的规则当前引擎不执行。

### 5.1 流程与生命周期（工单级，均【豁免】不展示）

| rule_id | 名称 | 严重度 |
|---|---|---|
| FLOW_MISSING | 工单流程缺失 | 高 |

## 6. 组分站审核规则清单

组分站表单统一落在 `sup_rf_common` 通用宽表（string1..150 / bool_1..50 / time1..4 / remark* 列），规则完全由 **档案驱动**：`configs/sup_form_profiles.yaml` 按 `RULEITEMTAG` 对 68 类表单建档（阈值/公式/日期档位/附件要求/填写时限），未建档表单不做数值判定。

### 6.1 表单规则（sup_form_rules.py）

| rule_id | 名称 | 判定逻辑 | 严重度 |
|---|---|---|---|
| SUP_FORMULA_RECALC | 公式列复算不一致 | 档案 formula_columns 表达式复算 vs 填写值（AST 白名单求值，容差默认 0.5） | 高 |
| SUP_RANGE_OUT_OF_SPEC | 数值超出档案标准范围 | range_columns 区间判定；**无备注→高（判失败），有备注→降级为中并转人工复核** | 高/中 |
| SUP_REQUIRED_VALUE_EMPTY | 必填数值列为空 | 空值→高；填"/""-"且无说明备注→中 | 高/中 |
| SUP_DATE_REASONABLENESS | 日期异常 | 区间倒置、间隔不在档案档位（30/31/90/180/365 天等）、有效期未覆盖检查日期 | 高 |
| SUP_ABNORMAL_NO_REMARK | 档案声明异常取值（异常/不合格）命中且无备注 | — | 中 |
| SUP_CYCLE_TIMELINESS | 周期表单填写不及时 | 优先质控计划口径（表单创建晚于 `sup_mtc_taskitem.planfinishtime` 超 5 天宽限）；无任务项回退表单口径（检查日期滞后超档案 max_fill_lag_days 7~60 天）；质控数据文件过期另判 | 高 |

### 6.2 附件规则（sup_attachment_rules.py）

| rule_id | 名称 | 判定逻辑 | 严重度 |
|---|---|---|---|
| SUP_ATTACHMENT_REQUIRED_MISSING | 必需附件缺失 | 按档案 required_attachments（报告类/数据文件类，按扩展名+文件名关键词）；仅过程照片不满足；备注含豁免关键词（无需送检/无需检定/不适用/无此项/未配置/停运）跳过 | 高 |
| SUP_ATTACHMENT_ITEM_MATCH | 附件与表单监测项目不一致 | 附件 typecode（=ruleitemtag 或 ruleitemtag_监测项目）与表单 pollutanttype 全部不符时判不一致 | 高 |

### 6.3 水印抽检试点（sup_watermark_rules.py，阶段 2.3）

| rule_id | 名称 | 判定逻辑 | 严重度 |
|---|---|---|---|
| SUP_ATTACHMENT_WATERMARK_STATION | 附件照片水印与站点不一致待核验 | 视觉识别水印地点/坐标/时间，与台账比对：站点名无重合、坐标距离 >5 km、时间不在检查日窗口。任一不符→人工核验（不直接判失败） | 中 |
| SUP_ATTACHMENT_WATERMARK_READ_FAILED | 水印识别调用失败 | 技术诊断，不入业务清单 | 低 |

抽检策略：工单已被其他规则命中则照片全检；否则按工单号 SHA1 稳定哈希抽样（默认 30%，可用 `OPS_AUDIT_SUP_WATERMARK_SAMPLE_RATE` 调整）；每单照片上限 2 张，每次运行任务硬顶 20 个；仅处理档案 `watermark_check.enabled` 的表单（当前试点：Sup_RF_Week_NMHCQC）。

### 6.4 组分站建档表单概览（sup_form_profiles.yaml）

当前建档 68 个 `RULEITEMTAG`（66 份独立档案；`Sup_RF_DeviceFlowCheck_PTRMS`、`Sup_RF_NH3CalibrationCX` 为品牌变体，经 YAML anchor 复用锚档案）。按档案 `category` 元数据分布（数量与示例以解析 YAML 实测为准，2026-11-14）：

| category | 数量 | 覆盖内容（示例） |
|---|---|---|
| week_check（周巡检/周检查） | 27 | 站房周安全检查、谱育 VOCs 周检（thybWeekCheck）、激光雷达周检（Week_THLiDAR/Week_FKXLiDAR）、GAC/URG 周维护、PM1 周巡检（状态勾选位）、温室气体周检查、OCEC(JG) 周检等 |

## 7. 两类站点共用规则与排除口径

**共用规则**

- `FORM_DATA_MISSING`：表单在位性护栏，两类工单通用。
- `RF_VISIBILITY_NO_DEVICE_FIELD_CONFLICT`：能见度"无设备"说明与设备字段冲突，同时覆盖常规站 RF_HY_VISIBILITYCALI 与组分站 Sup_RF_NepheloMeterCalibration / Sup_RF_MonthNepheloMeterCheck（填 49i/48i 等非能见度型号升为高）。
- 附件要求配置（§8）的 order_types 同时含 Check 与 SupCheck，对两类工单生效。
- 组分站水印试点的触发前缀含 SUP_/RF_/FLOW_/LIFECYCLE_，两类工单命中问题都会触发照片全检。

**排除口径（不进入最终问题清单）**

- 前缀排除：`FLOW_*`、`LIFECYCLE_*`（流程/生命周期类仅备查）。
- 单列排除：RF_AUDITOR_EMPTY、RF_REVIEW_EMPTY（复核人/审批人缺失不作为审核点）、RF_VALUE_FORMULA_MISMATCH（公式复算类暂不展示）。
- 技术诊断类（视觉失败、XLS 环境缺失、单位不可换算、组分站水印读取失败）单独归档不计业务问题。

## 9. 触发入口与产物

- **Agent 工具**（对话内触发）：`ops_audit_fetch_dataset`（取数）、`ops_audit_run_rules`（跑规则）、`ops_audit_inspect`（查目录/规则说明）。
- **服务 API**：`ops_work_order_audit.run_ops_work_order_deterministic_audit` —— 取数 → 规则 → 语义候选 → 产物落盘。
- **取数数据源**：环境变量 `OPS_AUDIT_DATA_SOURCE`，`local`（默认，本地 guangdong_mart PostgreSQL）或 `source`（源库 pyodbc）；组分站请求（order_types 全为 SupCheck/SupSECCheck）自动走 sup_rf_common 路径。
- **产物**（输出到 agent memory 的 `ops/audit/` 目录）：数据集 JSON、审计结果 JSON、语义复核候选/任务 JSON、最终问题清单、报告输入 `ops_audit_report_input.v3`（含可上报项/待语义复核项/语义豁免项三个分区，一项一行按异常归组）及 Markdown 报告。
